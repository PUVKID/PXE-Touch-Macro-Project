# PXE 28차 사용 안내

16차의 기본 매크로·탐지 설정을 유지하며 메인 화면과 작은 진행 위젯, 일시정지·글자 변경 후 재시작을 정리한 차수입니다. 한글 OCR은 앱에 내장되어 오프라인으로 글자를 읽습니다. 시범 학습·행동 AI·모델 가져오기 기능은 포함하지 않습니다.

28차는 이번 변경 범위의 검사와 독립 검토를 마친 수정본입니다. 기존 최종 26차와 준비본 27차를 보존합니다. 파일명은 `PXE_28차_v2.8_공용.apk`이며 32,718,940바이트입니다. 빌드·단위 102개·린트 오류0/경고0·Android12 설치는 확인했고 UI·제어·OCR 기기 검사 11개 방법은 통과했습니다. 독립 내용·명세 검토와 로컬 소스 묶음 대조를 마쳤습니다. 원격 반영은 GitHub의 해당 커밋과 별도 확인 기록으로 구분합니다. 최종 SHA-256은 검증 결과에 기록합니다. 설치 전 [검증 결과](검증_결과.md)의 확인 범위를 읽어 주세요.

| 접근성·표시 권한 | 앱의 권한 안내에 따라 허용 | 보안상 캡처가 금지된 화면이나 앱이 제공하지 않는 정보는 강제로 읽지 않습니다. |
| 매크로·설정 | 기존 저장본·탐지 설정·테마 확인 | 업데이트 보존의 실제 확인 결과는 별도 검증 결과에 기록합니다. |

## 글자·영역·매크로 정하기

| 순서 | 설정 | 확인할 내용 |
| --- | --- | --- |
| 1 | 찾을 글자 입력 | 정확한 문구는 일치, 일부 문구는 포함을 선택합니다. |
| 2 | 인식 방식 선택 | 이미지로 그려진 게임 글자는 **한글 OCR**을 사용합니다. 화면 정보는 대상 앱이 제공한 글자를 읽습니다. |
| 3 | 탐지 영역 그리기 | 원하는 글자와 여백을 포함하고 다른 버튼·비슷한 문구를 줄입니다. |
| 4 | 녹화 또는 동작 편집 | 터치·제스처·글자 조건·대기·뒤로가기를 순서대로 구성합니다. |
| 5 | 이름으로 저장 | 목록 탐지는 현재 편집본과 별개인 이름 있는 매크로를 선택할 수 있습니다. |
| 6 | 탐지 시작 | 반복 횟수·우선 영역·복귀·새로고침 시간을 확인합니다. |

안내 화면의 글자 입력 → 영역 지정 → 녹화 → 시간 설정 → 실행 준비 순서를 따라갈 수 있습니다. 시간은 화면의 초·분 단위를 확인해 입력하세요.

## 반복·복귀·중복 방지

| 설정 | 동작 | 구분할 점 |
| --- | --- | --- |
| 탐지 반복 15회 | 선택한 저장 매크로를 첫 동작부터 15회 실행 | 한 동작의 개별 반복과 다릅니다. |
| 개별 반복 1~1000회 | 해당 동작 하나를 지정 횟수 반복 | 탐지 반복과 함께 적용되는지 확인하세요. |
| 최대 6개 우선 영역 | 매번 1번부터 확인하고 처음 일치한 영역 사용 | 동시에 6개 앱을 제어한다는 뜻은 아닙니다. |
| 완료 후 복귀·대기 | 뒤로가기·복귀 대기 뒤 쉬는 시간과 새로고침 간격 적용 | 목적에 맞게 시간을 직접 정합니다. |
| 같은 글자 중복 방지 | 완료한 글자가 안정적으로 사라진 뒤 재등장하면 다시 실행 | 끄면 새로고침 뒤 같은 문구도 다시 실행할 수 있습니다. |

**편집한 매크로는 사용하는 이름으로 다시 저장하세요.** 현재 편집본만 바꾸면 탐지에서 선택한 별도 저장본에 자동 반영되는 것은 아닙니다.

## 다음 글자를 기다리거나 조건으로 이동하기

| 옵션 | 사용할 때 | 동작·주의 |
| --- | --- | --- |
| 글자가 나타날 때까지 계속 기다리기 | 다음 화면의 버튼을 기다릴 때 | 글자 부재만으로 재시도 횟수를 소모하거나 뒤로가지 않습니다. 기다리는 동안 정지할 수 있습니다. |
| 인식 후 추가 대기 없이 다음 동작 | 화면 변화가 적고 추가 대기를 줄일 때 | 완료 후 대기와 터치 전 재확인을 생략하므로 정확도가 우선이면 끕니다. |
| 다음 글자에 맞춰 진행 | 호환되는 연속 글자 조건 | 다음 글자가 사전에 없다가 나타난 조건에서 대기를 줄입니다. |
| 글자가 없으면 | 유한 검색의 실패 동작을 정할 때 | 뒤로가기·재확인·스크롤 후 재검색·다음 동작·정지를 선택합니다. |
| 글자 조건 분기 | 화면 상태에 따라 순서를 바꿀 때 | 있음·없음 각각 이동 번호를 정합니다. 0은 다음 동작입니다. |

예를 들어 목표 화면의 문구가 없을 때 뒤로가기 동작으로 이동한 뒤 처음 찾기로 이어지게 구성할 수 있습니다. 유한 재시도 횟수를 다 쓴 뒤에도 없으면 중단하는 정책은 유지합니다.

유한 글자 동작은 창 조회 하나의 실제 대기를 최소 1.5초 또는 설정한 글자 제한 중 긴 시간까지 허용합니다. 정상 OCR 계산 전체에 이 제한을 강제로 씌우지는 않습니다. 무한 글자 대기와 목록 탐지는 늦은 창 응답을 중복 요청 없이 기다리며 정지할 수 있습니다.

**화면 읽기 오류와 글자 없음은 다릅니다.** 대상 앱이 불명확하면 그 상태로 터치하지 않고 다시 확인합니다. 이번 차수에 새로운 자동 복구 절차를 추가한 것은 아닙니다.

## Adobe만 찾기

| 항목 | 설정·동작 |
| --- | --- |
| 인식 방식 | 화면에 보이는 영문만 고르려면 **한글 OCR**을 선택합니다. |
| 찾을 글자 | `Adobe`를 그대로 입력합니다. 한글 `어도비`와는 다른 글자입니다. |
| 비교 방식 | 일치는 같은 문구만, 포함은 더 긴 문구 속의 `Adobe`도 허용합니다. |
| 대소문자 | `ADOBE`도 허용하려면 대소문자 무시를 켜고, `Adobe`만 허용하려면 끕니다. |
| 탐지 영역 | 영문 버튼을 감싸고 옆의 한글·다른 버튼은 제외합니다. |
| 저장과 적용 | 목록 탐지와 매크로 안의 글자 동작을 각각 확인하고 같은 이름으로 다시 저장합니다. |

화면 정보·자동 방식은 앱이 공개한 접근성 이름을 읽을 수 있습니다. 아이콘 이름이 실제 화면 글자와 다른 경우가 있으므로 표시된 영문을 기준으로 고르려면 OCR을 명시합니다. 번역·발음·동의어로 두 문구를 같은 것으로 처리하지 않습니다.

## 실행 제어와 화면

| 기능 | 조작·표시 |
| --- | --- |
| 일시정지·재개 | 메인 네 탭의 일시정지·계속 실행, 단축창과 펼친 진행 위젯의 제어 |
| 완전 정지 | 정지 버튼 또는 접힌 PXE 아이콘 길게 누르기 |
| 접기·펼치기·이동 | PXE 아이콘을 누르거나 끌어서 이동 |
| 크기·투명도·테마 | 앱 설정에서 조정하고 기기 설정·라이트·다크 선택 |
| 진행 상태 | 작은 위젯의 현재 반복/전체 반복, 펼친 상세의 동작·시간 확인 |
| 하단 위젯 불투명도 | 설정 → 화면 위 컨트롤에서 40~100%, 기본 95%, 컨트롤 불투명도와 별도 |
| 기록 | 설정의 실행 기록·오류 기록으로 원인 확인 |

28차는 기존 검정·흰색과 차분한 파란 포인트, 나눔고딕 Bold700을 유지합니다. 라이트·다크·기기 설정 선택은 저장되며 2dp 포커스 테두리와 누름·선택·비활성·마우스 올림 표시를 추가했습니다. 실제 UI·제어 표본 검사와 두 테마·1.3배 글꼴 검사는 통과했습니다. 제품 모든 화면의 hover/focus 등 전체 상태를 새로 전수 검사했다는 뜻은 아닙니다.

## 실행을 이어가거나 새 글자로 바꾸기

| 상황 | 조작 | 동작·주의 |
|---|---|---|
| 앱으로 돌아옴 | 일시정지 중 표시 확인 | 편집 중 자동 입력을 잠시 멈추는 기존 동작 |
| 원래 작업 계속 | 계속 실행 | 같은 실행을 이어감 |
| 메인 글자 변경 | 입력 뒤 글자 찾기 시작 | 유효한 새 글자로 새 실행, 별도 정지 선행 불필요 |
| 탐지 설정 변경 | 설정 저장 뒤 탐지 시작 | 새 설정과 선택 매크로 검증 뒤 새 탐지 시작 |
| 단축창 글자 변경 | 글자 창에서 입력 후 시작 | 임시 일시정지 뒤 새 입력 검증·실행 교체 |
| 단축창 글자 편집 취소 | 취소 또는 적용 없이 닫기 | 같은 실행이 남고 원래 실행 중이었으면 원래 상태로 이어감 |
| 완전 종료 | 정지 | 현재 실행 종료 |

빈 글자·잘못된 정규식·설정 오류·녹화 중에는 새 실행을 적용하지 않습니다. 단축창의 잘못된 글자는 검증 전에 기존 설정을 덮어쓰지 않습니다. 이미 일시정지했던 실행을 취소만으로 재개하지 않습니다. 실행 도중 동작 목록에 추가하기·좌표 선택·녹화 등 구조 편집은 여전히 정지 또는 녹화 종료가 필요하므로 해당 안내를 따르세요.

## 작은 진행 위젯

| 요소 | 조작·표시 | 의미 |
|---|---|---|
| 반복 숫자 | 1/15 같은 현재 반복/전체 반복 | 완료 수와 별개이며 무한 반복 분모는 ∞ |
| 숫자 부분 | 끌어서 이동 | 저장 위치를 화면 안으로 제한 |
| 화살표 | 상세 펼치기·접기 | 접힌 크기 104×44dp, 펼친 너비 280dp 기준 |
| 펼친 상세 | 진행·시간·일시정지·정지 | 노란 선의 해 아이콘은 Orbit 참고 상태 장식 |
| 불투명도 | 하단 위젯 불투명도 40~100% | 기본 95%, 기존 단축창 설정과 별도 |

화면 크기가 바뀌면 위젯을 다시 화면 안으로 맞춥니다. 실행 중 화면 회전 시 정지하는 기존 정책은 그대로입니다. 자동 터치 경로가 위젯과 겹치면 제어 버튼을 누르지 않도록 위젯을 숨기는 처리를 포함합니다. 실제 위젯 위치의 자동 터치 통과와 회전 뒤 위치·정지 조건의 기기 검사 방법은 통과했습니다. 기본 화면의 3D 장식 제거는 AI 제거와 별개이며 학습형 행동 AI·모델 가져오기는 포함하지 않습니다.

## 이번 화면 변경의 범위

| 변경 | 유지한 조건 |
|---|---|
| 버튼·입력·탭·동작 목록의 조작 표시 | 기존 메뉴와 실행 콜백 유지 |
| 4단위 간격·유동 높이·한글 줄바꿈 | 일반 메인 조작부 최소 48dp, 좁은 화면에서 작업 버튼 세로 배치 |
| 작은 반복 위젯 | 접힘 104×44dp, 숫자 부분 드래그·화살표 펼침, 상세 너비 280dp |
| Rust로 라이트·다크 색상 XML 생성 | 기존 팔레트와 정확히 같은 값 사용 |

Rust는 PC 빌드 단계에서 사용하므로 기기 사용자가 별도 설치할 필요는 없습니다. MLKit 한글 OCR과 네 기준 파일 WatchConfig·Step·Macro·CapturePacer는 유지했습니다. 서비스에는 검증 후 재시작 API와 진행 수 공급을 추가했고 단축창·HUD도 변경했습니다. 새 속도 개선 수치는 측정하지 않았으며 27차의 중단된 60분 검사를 28차의 성공 결과로 사용하지 않습니다.

## 개발용 폴더 위치

빌드 도구는 차수 소스와 실제 빌드 사본의 상위 프로젝트 폴더를 기준으로 경로를 계산합니다. 프로젝트의 차수·코드·실행환경 구조를 유지하며 기존 빌드 안내의 서명 키·SDK·JDK·Gradle 위치를 확인하세요. 이 개발용 경로 처리는 APK를 사용하는 기기의 설정과는 별개입니다.
