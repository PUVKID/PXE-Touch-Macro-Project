# PXE 28차 검증 결과 · 2.8.2

이번 수정은 원문 완전 일치 강제와 접근성 설명/낱말 부분 일치 배제입니다. 이전 2.8.1 검사 결과를 이번 제품의 실행 결과로 그대로 세지 않았습니다.

| 검사 | 실제 결과 | 범위 |
|---|---|---|

| 단위 | 107개·실패0·오류0·제외0 | 새 원문 일치·기호/구형옵션 경계3개 포함 |
| 린트 | 오류0·경고0 | 최종 제품 소스 |
| 화면 정보 회귀 | 통과 | 어도비+설명Adobe, Adobe Pro는 터치0 / Adobe만1회 / 구형REGEX의 [ 기호도 리터럴로1회 |

현재 기기 통과는 StrictRecognition28Test의 고유 2개 방법입니다. 이후 추가 검사의 장치 소실 원인은 확정하지 않았고 제품 충돌이나 성공으로 바꾸어 기록하지 않았습니다. 전용 Android12/API31 AVD와 ADB5047을 사용했고 사용자 블루스택·게임·기본 ADB5037은 사용하지 않았습니다. 한글/부분문구의 부재 대기 후 정확한 영문으로 바꿔 실제 한 번 터치하는 과정을 확인했습니다.

## 실패 원문과 수정

| 관측 | 조치 | 해석 |
|---|---|---|
| 구형REGEX 검증이 리터럴 [를 거부 | Step의 정규식 컴파일 검증 제거·구형 저장옵션 호환 유지 | 원문 비교만 사용하는 현재 정책에 맞춤 |
| 첫 OCR 회귀에서 단독 [를 읽지 못함 | 해당 실패 원문 보존, 기호 판독은 별도 정확도 범위로 분리 | OCR [ 판독을 성공으로 바꾸어 기록하지 않음. 기호 저장/실행은 단위와 ACCESS에서 확인 |

검사 APK의 기호 범위를 정정할 때 제품 APK 코드는 바꾸지 않았습니다. OCR의 Adobe 음성/번역 일치 기능을 추가하지 않았고, OCR 모델이 화면을 잘못 읽는 모든 경우를 없앴다는 의미도 아닙니다.

기존 매크로·단축키·작은 하단 창·느린 스크롤은 유지합니다. 화면정보의 text가 없는 이미지/아이콘은 OCR로 확인해야 합니다. 입력 문구와 대소문자·공백·문자 형태가 다르면 실행하지 않으므로 이전의 느슨한 비교보다 더 기다릴 수 있습니다. OCR 모델의 오독·실제 대상 앱 접근성 정보의 정확성·장기 무중단·모든 기능 전수·실기기 업데이트는 이번 검증의 범위가 아닙니다. 이전 제품과 실패 원문은 별도 보존했습니다.
