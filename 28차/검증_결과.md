19개는 8+6+3+1+1의 고유 검사 방법 수이며 실패 뒤 같은 방법을 재실행한 횟수를 추가 검사 수로 세지 않았습니다. 속도 수치는 자체 검사 화면의 총 경과로, 사용자 게임의 완료 시간·다른 차수 대비 속도 개선율이 아닙니다.

## 중간 실패와 수리

| 관측 | 원인·조치 | 최종 확인 |
|---|---|---|
| 새 글자 탐지 재시작 중 화면 정보 조회 중단 | 이전 세대 QueryLane 작업이 남아 있을 때 취소 가능한 대기 후 새 조회 | 새 글자 탐지·기존 설정 유지 기기 검사 통과 |
| 단일 모드 이름 충돌 | 이름으로 추정하던 경계를 명시적 restartWord로 분리 | 같은 이름 일반매크로 세대·저장본 유지 검사 통과 |
| 첫 스크롤 검사 입력 오류 | 시험 입력 retryDelay0을 유효범위300ms로 정정 | 실제 DOWN/UP 시간·화면22.5% 이동 검사 통과 |
| 중간 도구 실행 종료 | 종료 결과 없는 OCR 시도는 미완료로 보존 | 해당 시도 시간과 최종 시간을 합산하지 않음 |
| OCR 5바퀴 첫 최종 시도 중 잠금 정지 | Android SystemUI의 SIGSEGV 원문과 제품 잠금 정지 로그 확인 | 제품 수정 없이 전용 시험 기기의 잠금 해제 후 해당 검사만 재실행,5바퀴 통과 |

오류가 아예 발생하지 않는다고 판정하지 않습니다. SystemUI 충돌을 PXE 제품 충돌로 바꾸어 기록하거나 원문을 지우지 않았습니다. 잠금 화면에서 멈추는 안전 경계는 유지합니다.

## 자료와 한계

전용 Android12/API31 x86_64 AVD와 ADB5047을 사용했습니다. 사용자 블루스택·게임·기본 ADB5037은 조작하지 않았습니다. 실제 장기 무중단·수년 운용·모든 기능 전수·노트10+ 실기기·기존 전체 데이터 업데이트는 이번 검사의 범위가 아닙니다. 학습 AI는 없고 내장 MLKit 한글 OCR을 유지합니다. Rust는 PC 빌드의 색상 생성에 사용합니다.

이전 차수 결과는 이전 폴더와 Git 이력에 보존합니다. 이번 문서는 현재 28차2.8.1의 결과만 설명합니다.
