기기 검사는 고유5개 방법이며 약30초의 계측 실행입니다. 전용 Android12/API31 x86_64 AVD와 ADB5047만 사용했고 사용자 블루스택·게임·기본 ADB5037은 조작하지 않았습니다. 이번 수집 시점의 crash 버퍼는 비어 있었습니다. 설치·계측 원문과 시각은 비공개 작업 기록에 보존했습니다. 화면22장 중 두 테마·인식 팝업·큰 글꼴·접힘/펼침 HUD를 직접 열어 글자 잘림과 대비를 확인했습니다. [현재 실제 화면](화면_확인/2.8.3/README.md)

MacroService·TextRules·Step·WatchConfig·ScrollMotion은 직전2.8.2와 바이트 동일함을 비교합니다. 완전 일치·느린 자동 하강·등록 글자·새 글자로 시작·매크로 저장/실행 방식은 유지합니다. `Adobe`와 `어도비`·`ADOBE`·`Adobe Pro`·공백 차이는 서로 다릅니다. 이번 OCR 회귀는 해당 자체 화면과 글자에 한정되며 모든 글꼴·기호의 인식률이나 오독 부재를 뜻하지 않습니다.

## 한계와 보존

실제 앱의 모든 메뉴 전수·폰 실기기·사용자 블루스택·장기 무중단·게임15회 시간·미래 무오류는 검사하지 않았습니다. 이전2.8.2의 추가 검사 중 AVD 소실 기록과 기호OCR 실패 원문은 별도로 보존했습니다. 이를 이번 디자인 APK의 실패나 현재 성공 수로 합산하지 않습니다. 추가 수집 명령 하나는 기존 경로와 충돌해 실패했지만 정규 검사 스크립트의 화면22장 수집은 성공했고 파일을 직접 확인했습니다. 24시간 검사를 재개하지 않았습니다.

Graphify는 현재 로컬 AST 관계만 조사했습니다. Java 중심1595노드·5407관계이고 XML/바이너리/Gradle 미지원·일부 구문 미해석이 있어 실제 소스의 Ui.styleDialog와 MainActivity/FloatingController/TargetWords 호출을 직접 대조했습니다. 그래프 수는 앱 속도나 안정성의 근거가 아닙니다.
