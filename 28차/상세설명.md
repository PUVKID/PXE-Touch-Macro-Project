# PXE 28차 상세 설명

16차의 매크로·탐지 기본 설정을 유지하고 실행 제어·글자 변경 후 재시작·작은 진행 위젯과 네이티브 화면을 정리했습니다. Rust는 빌드 시 색상 생성에 연결합니다.

## LEVEL 1 · 처음 사용하는 분을 위한 설명

| 하는 일 | 이번 화면 변경 | 확인할 점 |
|---|---|---|
| 글자 찾기 | 입력창과 버튼의 간격·테두리 정돈 | 찾을 문구와 인식 방식을 먼저 확인 |
| 매크로 편집 | 동작 목록·더보기·설정의 조작 표시 통일 | 현재 편집본을 이름으로 다시 저장 |
| 화면 모드 | 라이트·다크·기기 설정 선택 유지 | 테마 선택 저장과 화면 가독성은 기기 검사 필요 |
| 키보드 조작 | 선택 가능한 항목의 포커스 테두리 추가 | 포커스는 현재 키보드로 조작할 항목을 뜻함 |

PXE는 사용자가 만든 터치·기다리기·뒤로가기 순서를 실행하는 앱입니다. 매크로는 이런 동작을 순서대로 저장한 목록이고, OCR은 화면을 그림처럼 읽어 글자를 찾는 처리입니다. 한글 OCR 모델은 앱 안에 있으며 인터넷으로 화면을 보내 읽는 방식이 아닙니다. 화면 정보 방식은 대상 앱이 제공하는 글자 정보를 읽습니다.

예를 들어 화면의 `Adobe`를 찾으려면 찾을 글자에 그대로 입력하고, 그림처럼 표시된 글자는 한글 OCR을 선택합니다. 필요한 버튼 주위에 탐지 영역을 지정하고 실행할 매크로와 반복 횟수를 확인합니다. 한글 `어도비`와 영문 `Adobe`를 같은 글자로 바꾸어 찾지는 않습니다. 입력·영역·녹화·시간 설정·실행 준비 순서를 안내 화면에서 따라갈 수 있습니다.

| 단계 | 사용자가 하는 일 | 앱에서 확인할 내용 |
|---|---|---|
| 준비 | 중요한 매크로 내보내기 | 기존 앱을 삭제하지 않고 업데이트할 조건 확인 |
| 설정 | 글자·최대 6개 우선 영역·매크로 지정 | 우선순위와 현재 저장본 일치 |
| 실행 | 탐지 시작 | 진행·반복·대기 상태 표시 |
| 제어 | 일시정지·재개·정지 또는 단축창 이동 | 정지와 일시정지는 다른 동작 |

일반 메인 버튼과 입력창은 최소 48dp를 기준으로 하며, 긴 글자가 있으면 높이가 늘어납니다. dp는 기기마다 화면 크기가 달라도 조작 크기를 비슷하게 맞추는 Android 단위입니다. 모서리·색·선택 표시를 정리했지만 앱이 누르는 위치나 OCR 모델을 바꾼 것은 아닙니다. Rust는 앱을 만드는 PC에서 색상 목록을 생성하는 데 사용합니다. 사용자가 별도로 Rust를 설치해 앱을 조작할 필요는 없습니다.

이번 차수의 빌드·단위 102개·린트와 실제 UI·제어·OCR 검사 11개 방법은 통과했습니다. 독립 내용·명세 검토와 로컬 묶음 대조를 마쳤습니다. 원격 반영은 게시 커밋과 별도 확인 기록을 따릅니다. 예전 27차의 54.5분 관측은 호스트 재부팅으로 60분 최종 판정이 끝나지 않은 기록이며 28차 성공 결과가 아닙니다. 26차 최종본은 유지합니다. 보안 화면이나 흐린 글자는 인식이 제한될 수 있으므로 실제 대상 앱에서 미리보기로 확인해야 합니다.

### LEVEL 1 · 멈추지 않고 설정을 바꾸는 순서

| 상황 | 사용할 조작 | 의미 |
|---|---|---|
| 앱으로 돌아와 편집 | 일시정지 중 표시 확인 | 편집 중에는 자동 입력을 잠시 멈춤 |
| 같은 작업 이어가기 | 계속 실행 | 기존 실행의 남은 순서를 이어감 |
| 새 글자로 바꾸기 | 글자 변경 뒤 시작 | 새 입력을 검사하고 새 작업으로 시작 |
| 완전히 끝내기 | 정지 | 현재 작업 종료 |
| 글자 편집을 취소 | 단축창 편집에서 취소 | 원래 실행이 계속되는 조건이면 다시 이어감 |

앱의 탐지·동작·글자·설정 네 탭에서 실행 제어를 볼 수 있습니다. 메인 앱에 들어올 때 자동 일시정지되는 동작을 없애지 않고, 지금 멈춘 상태와 계속 실행 버튼을 함께 표시했습니다. 단축창의 글자 창은 실행 중 열면 잠시 멈추고, 적용 없이 닫았으며 같은 실행이 그대로 남아 있으면 원래 실행을 이어갑니다. 이미 일시정지했던 실행을 임의로 재개하지는 않습니다. 동작 목록 구조 편집·좌표·녹화는 여전히 별도의 정지 조건이 있습니다.

작은 하단 위젯의 `1/15`는 현재 반복/전체 반복을 뜻하며 모든 작업 완료 개수는 아닙니다. 숫자 부분을 끌어 위치를 바꾸고 화살표로 상세를 펼칩니다. 펼친 화면에서 진행·시간·일시정지·정지를 확인합니다. 설정의 하단 위젯 불투명도는 40~100%이며 기본 95%입니다. 노란 선의 해 아이콘은 Orbit 참고 분위기를 반영한 상태 장식이고 AI가 아닙니다. 이번에 뺀 3D 장식도 학습 기능과 별개입니다.

실제 기기에서는 75번의 OCR 터치와 화면 진입·뒤로가기 각5회를 같은 앱 프로세스·서비스로 수행했습니다. 마지막 정지 뒤 전체 관측은65.9초이며 60분 장기 검사가 아닙니다.

## LEVEL 2 · 화면·색상·실행 기능의 연결

| 부분 | 역할 | 이번 연결 |
|---|---|---|
| Rust 테마 생성기 | 지정한 색상값을 Android XML로 출력 | PC 빌드 시 실제 호출 |
| Python 생성 도구 | 라이트·다크 출력과 원색 대조 | 6색씩 12개 리소스 생성 |
| Ui 공통 함수 | 화면 색·버튼·입력·폰트 제공 | 생성한 12색을 6개 색상 함수로 소비 |
| MainActivity | 탐지·동작·글자·설정 화면 구성 | 간격·목록·탭·입력 라벨 정돈 |
| 매크로 서비스 | 실제 탐지·터치·대기 실행 | 새 설정을 검증한 뒤 이전 실행을 교체하는 재시작 API 추가 |

테마는 단순 배경색 하나가 아닙니다. 배경·표면·본문·보조 글자·강조·테두리의 여섯 역할을 라이트와 다크로 나눕니다. 이번 생성값은 기존 PXE 팔레트와 같습니다. 색상값이 달라져 더 빠르게 보이는 효과를 목표로 삼지 않았으며, 빌드 과정에서 같은 값을 일관되게 전달하는 데 Rust를 연결했습니다.

| 조작 상태 | 표현 | 의미 |
|---|---|---|
| 기본 | 기존 색과 테두리 | 사용할 수 있는 조작 |
| 눌림 | ripple과 강조 테두리 | 누르는 동안의 응답 |
| 선택 | 선택 배경·테두리·탐색 표시 | 현재 탭 또는 항목 |
| 키보드 포커스 | 2dp 강조색 테두리 | 키보드 입력이 향하는 항목 |
| 비활성 | 배경 투명도·보조 글자 | 현재 사용할 수 없는 조작 |
| 포인터 올림 | 배경·테두리 변화 | 마우스를 올린 항목 |

이 상태는 서로 다른 개념입니다. 현재 탭이 선택되어 있어도 키보드 포커스가 다른 버튼에 갈 수 있습니다. 색만 믿지 않도록 기존 탭 라벨·연결 문구·동작 사용 여부를 보존했습니다. 입력 라벨은 실제 입력창·선택창 ID에 연결했습니다.

탐지는 1순위부터 최대 6개 영역을 확인해 처음 일치한 영역을 사용하고, 지정한 매크로 반복·복귀·완료 후 대기·새로고침 순서로 이어집니다. 같은 글자 중복 방지, 유한 재시도와 계속 기다리기, 글자 있음·없음 분기, 정지와 일시정지는 기존 처리입니다. 이번 차수는 그 흐름을 새로 설계하지 않았습니다.

빌드 검사는 코드와 리소스 연결을 확인하고 실제 기기 검사는 글자 잘림·포커스·테마·단축창 조작을 확인합니다. 둘을 같은 검사로 취급하지 않습니다. 서비스의 재시작 API와 화면 조작이 함께 바뀌었으므로 실제 연동 검사가 필요합니다. 확인한 결과와 미확인 범위는 검증 결과에 구분합니다.

### LEVEL 2 · 기존 실행과 새 실행을 구분하기

| 입력·상태 | 처리 | 결과 |
|---|---|---|
| 계속 실행 | paused 상태 전환 | 같은 실행을 이어감 |
| 유효한 새 글자·탐지 설정 | 스냅샷 복사·검증 뒤 이전 세대 무효화 | 새 매크로 또는 새 탐지 실행 |
| 빈 글자·잘못된 설정·녹화 중 | 검증 오류 | 기존 실행을 새 설정으로 교체하지 않음 |
| 단축창 편집 취소 | 시작 당시 실행 세대·원래 일시정지 상태 확인 | 조건이 같을 때만 원상 복원 |
| 자동 터치 경로와 위젯 겹침 | 실제 위젯 창 경계를 포함해 충돌 판단 | 자동 입력이 제어 버튼에 가는 일을 방지하도록 숨김 |

재시작은 일시정지 해제와 다릅니다. 재시작은 새 설정으로 처음부터 수행하며 기존 입력의 늦은 결과가 섞이지 않도록 실행 세대를 바꿉니다. 16차의 WatchConfig·Step·Macro·CapturePacer는 26차와 현재 28차에서도 같은 바이트이며, 기존 지연·반복·인식 조건을 성능 추측으로 조정하지 않았습니다.

작은 반복 위젯은 접힌 너비 104dp·높이 44dp이고 펼친 너비는 280dp를 기준으로 합니다. 작은 화면에서는 실제 화면 폭에 맞게 제한합니다. 숫자 부분 드래그와 화살표 펼침, 불투명도 저장은 서로 다른 조작입니다. 회전이나 화면 크기 변경 후 위치를 다시 화면 안으로 제한하지만 실행 중 회전 시 정지하는 기존 정책은 유지합니다.

실제 검사 11개 방법은 UI1·메인3·위젯/재시작6·OCR5바퀴1로 나뉩니다. OCR은 5회 진입에서15회씩, 총75회 터치와5회 뒤로가기를 확인했습니다. 같은PID·서비스에서 정지 뒤 전체 65.9초를 관측했으며 이전27차 장기 기록과 합산하지 않습니다.

## LEVEL 3 · 설정·실행·산출물 확인

| 준비물 | 조건 | 확인 방법 |
|---|---|---|
| Android 기기 | Android 11 이상, 지원 ABI | 실제 APK 메타데이터·검증 결과 대조 |
| 업데이트 | 기존 앱 ID·서명과 호환되는 설치 | 중요한 매크로를 먼저 내보내 보관 |
| 접근성·표시 권한 | 앱 안내에 따라 허용 | 연결 상태와 단축창 표시 확인 |
| 설정·저장본 | 글자·영역·반복·대기·테마 | 업데이트 전후 실제 값 비교 필요 |

28차의 제품 버전은 2.8.0, 버전 코드는 28이며 공용 빌드 설정은 ARM64와 x86_64입니다. APK 파일명은 `PXE_28차_v2.8_공용.apk`입니다. 실제 APK는 32,718,940바이트이며 SHA-256은 검증 결과에 기록했습니다. 전용 Android12 설치와 UI·제어·OCR 11개 검사 방법은 통과했습니다.

| 순서 | 입력·조작 | 확인할 출력 |
|---|---|---|
| 1 | 글자와 일치·포함 방식 선택 | 미리보기의 실제 인식 위치 |
| 2 | 우선 영역 최대 6개 지정 | 화면의 순위와 저장된 영역 |
| 3 | 터치·제스처·대기·분기 녹화 또는 편집 | 동작 목록과 개별 반복 |
| 4 | 이름으로 저장하고 탐지 매크로 선택 | 현재 편집본과 선택 저장본 일치 |
| 5 | 전체 반복·완료 후 대기·새로고침 설정 | 초·분 단위와 무한 옵션 구분 |
| 6 | 탐지 실행 후 일시정지·재개·정지 | 진행 문구와 실제 동작의 일치 |

탐지 반복 15회는 매크로 전체를 15회 실행하는 설정이며 한 동작의 1~1000회 개별 반복과 다릅니다. 같은 글자를 다시 실행할 조건은 중복 방지 설정과 재등장 상태에 달려 있습니다. 화면 읽기 오류를 글자 없음으로 취급하지 않는 기존 정책도 유지합니다.

| 화면 확인 | 필요한 상태 | 현재 근거 |
|---|---|---|
| 버튼·탭·동작 목록 | 네 탭 제어·메인 버튼 배치·포커스와 fixture 상태 표본 | 해당 검사 통과, 모든 상태 전수 검사는 아님 |
| 입력·팝업·선택 목록 | 라이트·다크·긴 한글·1.3배 글꼴 | 해당 기기 표본 검사 통과 |
| 단축창 | 접기·펼치기·끌기·투명도 | 진행 위젯·글자 편집·새 실행 6개 검사 방법 통과 |
| 저장과 업데이트 | 테마·매크로·탐지 설정 보존 | 실제 업데이트 검사 대기 |

개발자는 `source/빌드방법.txt`를 따라 실제 Python·JDK·SDK·Gradle·서명 위치를 지정합니다. 빌드는 Rust 색상 생성 → 빌드 사본 동기화 → 제품 빌드·단위 검사·린트 순서입니다. Windows 테마 실행 파일이 동작하더라도 Android 기기 검사가 완료된 것은 아닙니다.

실행 기록과 오류 기록은 설정 화면에서 확인합니다. 취소·중단·미인식·늦은 응답은 정상 실행과 구분해야 합니다. 27차의 속도 측정과 중단된 장기 검사는 이전 기록이며 이번 결과에 합산하지 않습니다.

### LEVEL 3 · 바뀐 글자 적용과 작은 위젯 사용

| 목적 | 절차 | 확인 |
|---|---|---|
| 메인 글자 변경 | 글자 탭에서 입력 후 글자 찾기 시작 | 새 입력을 새 실행으로 교체, 별도 정지 버튼 선행 불필요 |

아직 녹화 중이거나 동작 목록을 구조적으로 편집하는 경우에는 정지·녹화 종료 안내를 따릅니다. 새 글자만 바꾸는 실행 경로를 넓힌 것이며 모든 편집의 정지 조건을 제거한 것은 아닙니다. 메인 앱의 자동 일시정지 뒤에는 계속 실행을 직접 누릅니다. 단축창 글자 편집을 적용 없이 닫으면 같은 실행이 유지되고 원래 실행 중이었던 조건에서만 자동으로 이어집니다.

긴 한글은 버튼의 높이가 늘어나 표시하고 좁은 폭·큰 글꼴에서는 반폭 작업 버튼을 세로로 배치합니다. 기본 3D 장식을 제거하고 찾을 글자와 주요 설정, 시작 동작을 먼저 보여 줍니다. 일반 메인 버튼 최소 48dp와 작은 위젯의 44dp 높이는 다른 영역의 규격입니다. 새 1.3배 글꼴·두 테마의 실제 기기 검사는 통과했습니다. 이는 해당 메서드와 화면 표본의 근거이며 모든 지원 화면의 전체 상태를 새로 확인한 것은 아닙니다.

기기 검사 11개 방법이 통과했습니다. OCR5바퀴의 누적 경과는13,517·26,043·38,401·51,245·64,089ms, 정지 후 전체 65,890ms(65.9초)입니다. 이 값은 이번 유한 실행의 관측이며 속도 향상률이나60분 안정성을 뜻하지 않습니다. 진단 화면을 제외한 캡처 25장을 정리했고 작은/펼친 HUD는 잔상 없이 다시 확보했습니다. 직접 시각 검토는 작은/펼친 HUD·라이트 1.3배 탐지·다크 1.3배 글자, 네 종류의 화면 범위이며 전체 25장 검토로 확대하지 않습니다.

## LEVEL 4 · 구현 경계와 변경 영향

| 경계 | 구현 | 영향·절충 |
|---|---|---|

| 리소스 소비 | Ui의 bg/card/ink/muted/accent/line | 생성된 6역할×2모드 연결 |
| 상태 배경 | controlStates·ripple·focusRing | 기존 함수 중심으로 pressed/selected/focused/disabled/hovered 처리 |

| 팝업 | styles.xml·nex_dialog_light/dark.xml | 표면색·16dp 반경·목록 높이 일관화 |

메인 화면은 `Ui.java`, `MainActivity.java`, 테마·팝업 리소스와 제어 벡터 아이콘에서 정돈합니다. 일반 메인 버튼은 최소 48dp와 내용에 맞는 높이를 사용하고, 폭이 400dp 미만이거나 fontScale이 1.15를 넘으면 반폭 작업 버튼을 세로로 배치합니다. 공통 버튼의 하드 2줄 제한을 해제했고 한글 폰트 패딩·fallback 줄간격을 적용했습니다. 기존 컨트롤의 접기·이동을 유지하면서 RunHud는 104×44dp의 작은 반복 표시로 새로 구성했습니다.

| 실패 지점 | 처리·확인 | 남는 한계 |
|---|---|---|
| Rust 출력 불일치 | Python에서 지정 팔레트와 정확히 대조 후 실패 | 실행 환경·경로는 재현 시 별도 확인 |
| 잘못된 CLI·색상 | Rust의 인자·색상 거부 단위 검사 포함 | 실제6개 통과, Android 기능 검증과 구분 |
| 빌드·검사 실패 | 하위 프로세스 check=True로 전파 | 성공 로그·종료 코드 결합 필요 |
| 화면 상태 누락 | 기기에서 포커스·눌림·선택 확인 | 정적 코드만으로 전체 표시 보장 불가 |

기존 `nex_soft`와 Android 상태를 사용해 추가 상태를 표현하며 생성기에 없는 색상 이름을 가정하지 않았습니다. 나눔고딕 Bold700과 저장된 테마 선택을 유지합니다. React 컴포넌트나 별도 행동 AI를 Android 앱에 설치하지 않았습니다. MLKit 한글 OCR·전체 화면 입력·캡처 동시 작업 제한·오래된 결과 폐기 정책은 유지합니다. MacroService는 재시작 API와 반복 수 공급을 위해 변경했으며 서비스 전체가 불변이라는 초기 범위의 설명은 현재 소스에 적용하지 않습니다.

Graphify의 초기 28차 로컬 code-only 질의 근거는 보존하며, 새 실행 제어·진행 위젯과 장식 삭제 후 최종 갱신은 707노드·2264연결·31커뮤니티입니다. 캐시29개 재사용·1개 갱신·1개 삭제를 반영했습니다. 그래프는 변경 위치를 조사하는 자료이며 연결 전부가 런타임 실행을 의미하지 않습니다. 실제 소스 대조와 별도 검사 결과를 함께 해석합니다. 그래프와 내부 조사 기록은 공개 산출물에 섞지 않습니다.

현재 MacroService는 27차와 다릅니다. 검증 후 새 세대로 재시작하는 API와 반복 수·실행 세대 공급을 추가했습니다. 반면 WatchConfig·Step·Macro·CapturePacer 네 파일은 16차·26차·현재 28차의 SHA-256이 모두 같습니다. 이 네 파일의 동일성을 서비스 전체나 성능 동일성으로 확대하지 않습니다. 이전 최종 26차·준비본 27차를 보존하고 28차 검증 완료 전 최종본 교체를 선언하지 않습니다.

16차·26차·현재 28차의 네 기준 파일 동일성은 직접 SHA-256으로 확인했습니다. 기본 설정 유지와 새 실행 제어 수리는 구분합니다. 학습형 행동 AI·ONNX 경로는 추가하지 않으며 MLKit OCR은 유지합니다. 3D PxeModelView 장식과 관련 사용 경로를 제거했지만 이를 AI 학습 제거로 설명하지 않습니다.

Control 최초6개 중2개 실패는 fixture의 word_match=REGEX가 다음 검사에 남은 점과 다이얼로그가 나타난 직후 창을 조회한 검사 타이밍에서 발생했습니다. 테스트 시작 때EXACT를 명시하고 입력창이 나타날 때까지 최대 4초 조건 대기로 수정했습니다. 진단 화면에서 실제 대상 존재를 확인했으며 추정으로 제품 코드를 바꾸지 않았습니다. 제품 APK는 같은 지문이고 검사 APK만 재빌드한 뒤 6개 모두 통과했습니다.

| 공개 반영 | 문서·전체 비교·동일 수준 링크・원격 화면 | 준비 중, 게시 미확인 |

빌드 단계는 Rust 색상 생성 뒤 실제 빌드 사본을 동기화하고 Gradle의 `:app:assembleRelease :app:testDebugUnitTest :app:lintDebug -PNEX_PC`를 실행합니다. 도구 경로·JDK·SDK·서명은 빌드 안내의 환경 변수로 지정합니다. 생성 도구의 프로세스 성공만으로 Android 설치 성공을 단정하지 않으며 단위 검사 수·skipped·오류·경고도 실제 보고서에서 확정해야 합니다.

Graphify의 이전 그래프 수치를 최신 동결 소스의 규모로 쓰지 않습니다. 재시작·HUD·prepareGesture·Main 질의와 실제 소스 대조 및 최종 장식 삭제 뒤 갱신은 완료했고 그래프 수를 검사 개수·성능·기능 완전성으로 환산하지 않습니다. 네 기준 파일의 동일성은 재사용할 수 있으나 새 재시작·진행 위젯·UI의 기기 검사를 대체하지 않습니다. 블루스택과 기본 ADB 서버는 조작 대상에서 제외하고 전용 Android 12 장치를 사용하도록 준비했습니다.

28차 APK는 32,718,940바이트이며 SHA-256과 빌드 결과는 검증 결과에 확정했습니다. 전용 Android12 설치와 UI·제어·OCR 기기 11개 방법은 통과했고 독립 내용·명세 검토와 로컬 패키지 대조를 마쳤습니다. 원격 반영은 게시 커밋과 별도 확인 기록을 따릅니다. 27차 장기 검사의 중단을 PASS로 바꾸거나 새 실행과 합산하지 않습니다. 모든 기기와 미래 입력의 무결함·무중단을 보장하지 않습니다. 결과와 한계는 [검증 결과](검증_결과.md), 파일별 변경은 [변경 기록](변경기록.md)에서 대조합니다.

### LEVEL 5 · 최신 요구에 따른 구현·평가 범위

| 항목 | 직접 대조한 구현·정의 | 결과 해석 |
|---|---|---|
| 16차 기준 4파일 | WatchConfig·Step·Macro·CapturePacer의 16/26/현재28 SHA-256 동일 | 기본 정의 보존, 실행 속도 실측과 별개 |
| 재시작 | 연결·녹화·설정 검사 → 스냅샷 → 이전 세대 무효화 → 새 실행 | 기존 start/startWatch guard와 새 API를 구분 |
| 메인 제어 | 모든 탭에 paused/running 문구·벡터 제어 | onResume 자동 일시정지 보존 |
| HUD | compact 104×44dp, expanded 너비 280dp·높이 wrap-content | 화면 폭과 실제 측정 높이로 clamp |
| 설정 저장 | hud_x/y·hud_expanded·hud_opacity | 불투명도 40~100%, 기본 95% |
| 표시 문자 | 반복 현재/전체·무한이면 ∞ | 완료한 바퀴 수와 혼동하지 않음 |
| Rust | cargo test 6 passed, release 빌드 로그, 2팔레트 출력 대조 | Windows 빌드 기능, Android 런타임 아님 |

Rust 단위 6개는 대비·혼합·입력 보존·잘못된 인자·두 모드/출력 형식·잘못된 색상 거부를 포함하며 실패·무시·filtered out은 0개입니다. release 컴파일 로그의 38.23초는 해당 Rust 빌드 시간이며 Android 실행 속도나 성능 개선률이 아닙니다. 공개 소스에서 실행 파일은 제외하므로 theme-engine의 빌드 스크립트로 먼저 컴파일하고 target/release/astryx-theme.exe를 theme-engine/astryx-theme.exe로 복사합니다.

초기 범위 Android 단위 106개 통과와 초기 린트 오류 0·경고 12는 이전 입력의 근거입니다. 생성 리소스 전환으로 남은 미사용 기존 색상 12개를 정리했으며, 새 제어·진행 위젯·재시작·장식 제거를 반영한 제품 빌드·최종 린트는 통과했고 UI·제어·OCR 기기 11개 방법은 통과했습니다. 독립 내용·명세 검토와 로컬 소스 묶음 대조를 마쳤습니다. 원격 반영은 GitHub의 해당 커밋과 별도 확인 기록으로 구분합니다. 제거한 장식 OBJ를 읽던 전용 테스트 1개 실패 원문을 보존했고, 제품 참조가 없는 장식 소스·전용 검사 원본을 보존 후 제거했습니다. 장식 전용 4개 검사를 제외한 남은 단위 102개 통과를 확인했으며 매크로 수락 기준을 바꾼 것은 아닙니다. 최신 린트 오류1·경고2의 원인은 줄바꿈 상수·drawable 로딩·미사용 아이콘이었으며 원문을 보존하고 수정 후 오류0·경고0을 확인했습니다. MainControls28Test 3개·Control28Test 6개·Ui28Test 1개·Sustained26Test의 5바퀴 검사1개, 총11개 방법이 실제 통과했습니다. fixture에서 일부 상태를 만든 검사는 모든 제품 화면의 hover/focus/선택/비활성 검증을 뜻하지 않습니다.

최신 Graphify는 707노드·2264연결·31커뮤니티이며 APK 지문은 검증 결과에 확정했습니다. 새 장기 실행은 수행 결과가 없으며 27차의 54.5분 중단 기록은 그대로 보존합니다. 현재 28차는 변경 영향 검증판·준비본이고 기존 26차 최종본을 유지합니다.

각 실행 원문은 INSTRUMENTATION_STATUS_CODE 0과 최종OK(1/3/6/1), INSTRUMENTATION_CODE -1이며 호스트명령 종료코드0과 연결했습니다. JUnit 시간과 앱 내부 경과는 다릅니다. 5바퀴의 누적경과는13,517/26,043/38,401/51,245/64,089ms이고 마지막정지후 전체 65,890ms(65.9초)입니다. 새60분 장기 결과가 아니며 전체 기존 기능의 전수 재실행을 뜻하지 않습니다.

Control 최초2실패 원문은 보존했습니다. 원인은 fixture 설정REGEX 누출과 입력창 표시 전 조회였고 EXACT 초기화·4초 조건 대기 후 검사 APK만 재빌드했습니다. 제품 APK SHA-256은 바뀌지 않아102개 단위와 린트0 근거를 재사용합니다. crash buffer는 조회 당시 비어 있었으며 모든 미래 crash 부재를 보장하지 않습니다. 캡처는 대상폴더 생성 누락으로 첫 ADB pull이 실패한 뒤 폴더를 만들고 26파일 수집에 성공했습니다. 진단 1장을 비공개로 보존·제외한 25장을 정리했고, 잔상 없는 작은/펼친 HUD를 다시 확보해 직접 시각 검토했습니다. 캡처 전용으로 검사 1개를 추가 실행했으며 고유 통과 방법 수 11개에 중복 합산하지 않았습니다. 실제 4장 시각검토와 전체 이미지·모든 상태 검토는 구분합니다. 독립 내용·명세 검토와 로컬 패키지 대조를 마쳤습니다. 공개 상태는 게시 커밋과 별도 확인 기록으로 구분합니다.
