# PXE 27차 · 캡처 대기와 상태 표시 정리

**기존 인식 품질과 매크로 기능을 유지하면서 겹칠 수 있는 대기를 정리했습니다.** 16차 기반의 일반 매크로·오프라인 한글 OCR을 이어가고, 화면 배치를 크게 바꾸지 않은 범위에서 상태 표시와 색상을 다듬었습니다.

27차는 검증 범위를 명시한 준비본입니다. 기존 최종 26차는 유지하고 차수 폴더에 제공합니다. APK 빌드와 단위 106개·린트 오류 0·경고 0, 실제 UI와 캡처 복구 검사는 확인되었습니다. **60분 연속 검사는 호스트 재부팅으로 중단되어 최종 판정 미완료입니다.** 남은 호스트 마지막 표본의 장치 누적은 54.5분·247바퀴·OCR 3,705회이며 종료 JUnit·호스트 연속성을 입증하지 않습니다. 별도 15회×5구간 비교의 전체 평균 시간 변화는 11.2% 감소입니다. 사용자 게임 전체 15회 완료 시간이 아닙니다. 아래의 구현 설명과 실제 실행 검증을 구분하고, 확정 결과는 검증 결과 문서에서 확인합니다.

## LEVEL 1 - Beginner

### LEVEL 1 · 기존 순서를 유지하며 기다림 다듬기

PXE는 화면 글자를 찾아 사용자가 정한 순서대로 터치·제스처·뒤로가기를 실행합니다. OCR은 화면 사진에서 글자를 읽는 기능입니다. 앱 안에 한글 OCR이 들어 있어 인터넷 연결 없이 사용할 수 있습니다. 이번에는 다음 행동을 새로 학습하는 AI를 추가하지 않았습니다.

| 사용자가 정할 것 | 앱의 동작 | 확인할 점 |
| --- | --- | --- |
| 글자와 탐지 영역 | 지정한 문구를 찾아 위치 확인 | 비슷한 글자·다른 버튼을 영역에서 줄입니다. |
| 녹화 또는 동작 목록 | 저장한 순서대로 실행 | 이름 있는 저장본과 현재 편집본을 구분합니다. |
| 반복과 복귀 시간 | 정한 횟수 뒤 목록으로 돌아가 다시 찾기 | 동작 하나의 반복과 매크로 전체 반복은 다릅니다. |
| 기다리기·분기 | 문구가 나타나길 기다리거나 다른 동작으로 이동 | 유한 재시도와 계속 기다리기를 구분합니다. |
| 최대 6개 우선 영역·중복 방지 | 영역 순서대로 찾고 같은 글자 재실행 제한 | 완료 글자가 사라져야 다시 실행되는 조건을 확인합니다. |

### LEVEL 1 · 이번 화면과 대기 변경

| 부분 | 27차에서 다듬은 점 |
| --- | --- |
| 캡처 준비 | 컨트롤을 숨긴 뒤 화면이 안정되길 기다리는 시간과 다음 캡처까지의 간격을 함께 기다립니다. |
| 글자 읽기 | 기존 전체 화면과 해상도를 유지합니다. 글자 그림을 작게 줄여서 속도를 내지 않습니다. |
| 화면 색상 | 검정·흰색과 차분한 파란 포인트로 화면·팝업·컨트롤 색상을 맞췄습니다. |
| 상태 표시 | 같은 문구를 계속 다시 넣지 않고 실제 문구가 바뀔 때 갱신합니다. |
| 가독성 | 연결 상태와 선택한 탐색 항목, 카드와 상태창의 간격을 정리했습니다. |

화면 위 컨트롤이 캡처에 섞이지 않게 잠시 숨기는 시간과, 캡처를 너무 자주 요청하지 않게 두는 간격이 있습니다. 두 기다림을 차례로 더하던 부분을 겹치게 했지만, **각각 필요한 시간은 모두 유지합니다.** 실제로 얼마나 빨라지는지는 27차 측정 결과로 확인해야 합니다.

### LEVEL 1 · 준비와 제어

| 순서·상황 | 할 일 |
| --- | --- |
| 설치 | 기존 앱을 삭제하지 않고 업데이트하고 권한 안내를 따릅니다. 중요한 매크로는 내보내 보관합니다. |
| 설정 | 글자 → 영역 → 녹화 → 시간·반복 → 실행 준비 순서로 진행합니다. 이미지 글자는 한글 OCR을 선택합니다. |
| 저장 | 수정한 매크로는 사용하는 이름으로 다시 저장하고 탐지에서 선택합니다. |
| 실행 중 | Ⅱ / ▶로 일시정지·재개하고 정지 버튼으로 멈춥니다. |
| 예상과 다른 화면 | 문구·영역·조건 분기를 확인합니다. 대상 앱이 불명확하면 바로 터치하지 않는 정책입니다. |
| 결과 확인 | [검증 결과](검증_결과.md)에서 실제 확인 범위를 읽습니다. 중단된 연속 검사의 복구 관측과 별도 속도 비교를 구분합니다. 60분 통과로 표시하지 않습니다. |

## LEVEL 2 - Explorer

### LEVEL 2 · 입력에서 재탐지까지

이번 차수도 글자 조건과 저장한 동작을 연결합니다. 화면 정보 방식은 앱이 제공하는 글자를 읽고, OCR은 캡처 이미지에서 글자를 읽습니다. 자동 방식은 화면 정보와 OCR을 연결하는 기존 정책을 유지합니다. 검색 영역은 결과를 고르는 조건이며, 이번 개선을 위해 캡처를 영역 크기로 잘라 인식하는 방식으로 바꾸지 않았습니다.

| 단계 | 입력·처리 | 다음 상태 |
| --- | --- | --- |
| 대상 확인 | 현재 앱과 검색할 문구·영역 확인 | 조회 또는 정지 가능한 대기 |
| 캡처 준비 | 컨트롤 숨김 안정화와 캡처 간격 모두 충족 | 전체 화면 캡처 |
| 글자 선택 | 포함·일치·정규식과 영역·순번 조건 적용 | 일치 위치 또는 글자 대기 |
| 항목 실행 | 최대 6개 우선 영역 중 첫 일치로 진입 | 선택한 매크로 반복 |
| 완료·복귀 | 뒤로가기·대기·새로고침 적용 | 중복 방지 조건 확인 후 재탐지 |

### LEVEL 2 · 두 대기가 겹치는 원리

| 기다림 | 목적 | 27차 처리 |
| --- | --- | --- |
| 컨트롤 숨김 뒤 150ms | 캡처 전 화면 안정화 | 컨트롤을 숨긴 뒤 해당 시간이 지나야 캡처합니다. |
| 캡처 간 최소 간격 | 연속 캡처 요청 사이 간격 유지 | 앞 캡처에 따른 다음 허용 시점을 지킵니다. |
| 실제 OCR·앱 응답 | 화면에서 글자를 읽고 대상 앱 반응 대기 | 이 처리 시간을 없앴다고 주장하지 않습니다. |

기존에는 캡처 간격을 기다린 다음 컨트롤을 숨기고 다시 150ms를 기다렸습니다. 이번에는 숨김을 먼저 시작해 두 조건이 함께 충족되기를 기다립니다. 따라서 두 대기를 단순히 더할 필요가 줄어듭니다. 어느 쪽 대기가 더 오래 남아 있든 **나중에 충족되는 조건까지 기다리는 것**이 핵심입니다.

### LEVEL 2 · 그대로 유지하는 안전 조건

| 조건 | 동작 |
| --- | --- |
| 대상 앱이 불명확함 | 터치하지 않고 다시 확인합니다. 새 자동 복구 절차를 추가한 것은 아닙니다. |
| 정지·일시정지 뒤 늦은 응답 | 이전 응답으로 입력하지 않는 수명 관리 정책을 유지합니다. |
| 창 조회가 지연됨 | 같은 조회를 중복으로 계속 보내지 않습니다. |
| 오류와 글자 부재 | 화면 읽기 오류를 단순한 글자 없음으로 바꾸지 않습니다. |
| 전체 품질과 구성 | 해상도 축소·새 행동 AI·새 의존성 없이 기존 OCR과 매크로를 유지합니다. |

UI는 상태 확인 주기를 유지하고 같은 문구의 재설정만 줄였습니다. 이 변경만으로 OCR 처리나 대상 앱의 반응 시간이 빨라졌다고 해석하지 않습니다. 실제 속도와 연속 운용은 [검증 결과](검증_결과.md)에서 별도로 확인합니다.

## LEVEL 3 - Practitioner

### LEVEL 3 · 적용 순서와 설정 범위

기존 매크로·목록 탐지·테마 저장 구조를 유지합니다. Android 11 이상에서 기존 앱을 삭제하지 않고 같은 앱 ID와 서명의 APK로 업데이트하는 조건입니다. 실제 APK와 업데이트 보존 검사 결과는 [검증 결과](검증_결과.md)를 기준으로 확인합니다.

| 준비·설정 | 적용 범위 | 확인 방법 |
| --- | --- | --- |
| 한글 OCR / 화면 정보 / 자동 | 목록 탐지와 개별 글자 동작 각각 | 이미지에 그려진 글자는 OCR으로 미리보기 |
| 포함·일치·정규식·공백·대소문자 | 현재 검색 조건 | 원하는 문구·유사 문구가 다르게 처리되는지 확인 |
| 계속 기다리기 / 유한 재시도 | 글자 동작 | 부재 시 대기·뒤로·스크롤·정지 정책 확인 |
| 개별 반복 / 탐지 반복 | 한 동작 / 저장 매크로 전체 | 낮은 횟수로 확인한 뒤 목표 반복 적용 |
| 우선 영역·중복·복귀·새로고침 | 목록 탐지 | 같은 글자 재실행 조건과 초·분 단위 확인 |
| 저장본 선택 | 이름 있는 매크로 | 편집 뒤 같은 이름으로 재저장 |

`Adobe`만 찾으려면 OCR·일치·적절한 영역을 선택합니다. `어도비`와 번역·발음으로 연결하지 않습니다. 대소문자 무시 여부도 별도로 확인합니다. 화면 정보는 앱이 제공한 접근성 이름을 읽으므로 보이는 영문과 다를 수 있습니다.

| 글꼴 | 나눔고딕 Bold 유지 | 기존 한글 가독성 기준 유지 |

### LEVEL 3 · 결과를 읽는 순서

| 결과 항목 | 현재 상태 | 확정 시 필요한 근거 |
| --- | --- | --- |
| 제품 빌드·정적 검사 | APK 빌드·단위 106개 통과·린트 오류 0·경고 0 | 최종 APK와 검사 결과 대조 |
| OCR 반복·속도 | 75회 성공 · 5구간 평균 9.1초 | 같은 조건의 26차 평균 10.2초와 별도 비교 |
| 60분 연속 운용 | 중단 · 최종 판정 미완료 | 호스트 마지막 표본 247바퀴·OCR 3,705회. 종료 JUnit·호스트 종료 관측 없음 |
| 실제 UI | 검사 메서드 1개 통과·화면 6개 확인 | 같은 값 40회 갱신 시 콜백 1회, 실제 변경 뒤 2회 |
| 캡처 복구 | 검사 메서드 3개 통과 | 해당 검사 조건의 복구 동작 |
| 업데이트 보존 | 26→27 업데이트 설치 성공, 앱 ID·서명·저장 구조 유지 | 16→26 실제 설정 보존 근거 재사용. 모든 사용자 파일 제공자를 새로 재시험한 결과는 아님 |

연속 운용에서 중간에 앱이나 서비스를 재시작하면 단일 연속 실행과 구분해야 합니다. 전용 검사 장치를 사용하며 사용자의 블루스택을 검사 대상으로 조작하지 않습니다. 60분 결과가 확보되더라도 수년간 모든 환경에서 멈추지 않는다는 보장은 아닙니다.

## LEVEL 4 - Advanced

### LEVEL 4 · 캡처 대기의 변경 경계

27차는 16차 기반 실행 구조와 직전 제품의 인식·취소 정책을 이어갑니다. 캡처 간격을 줄이거나 OCR 입력을 축소하는 대신, 캡처 전 두 대기를 함께 진행하도록 순서를 바꿉니다. 화면 품질·검색 조건·저장 모델 변경과 분리된 수정입니다.

| 부분 | 27차 변경 | 유지한 조건 |
| --- | --- | --- |
| 캡처 준비 순서 | 컨트롤 숨김 안정화와 pacer 대기를 겹침 | 각각의 마감 시점까지 대기 |
| Android API 30 이하 | 간격 값 변경 없음 | **1100ms** |
| Android API 31 이상 | 간격 값 변경 없음 | **500ms** |
| 숨김 안정화 | pacer와 함께 기다림 | **150ms** |
| OCR 입력 | 전체 화면 유지 | 영역 자르기·다운샘플링 없음 |
| 인식·검색 구성 | 기존 모델·조건 재사용 | 새로운 AI·의존성 없음 |

두 대기 조건을 함께 충족하는 시점이 캡처 가능 시점입니다. pacer 대기가 남아 있으면 그동안 숨김 안정화도 진행됩니다. pacer 대기가 거의 없더라도 150ms 안정화는 건너뛰지 않습니다. 실제 총 소요 시간에는 OCR 계산·화면 변화·제스처·기존 설정 대기가 함께 포함되므로 대기 순서만으로 전체 개선량을 확정하지 않습니다.

| `drawable/nex_dialog_light.xml` | 라이트 팝업 배경 색상 참조 | 기존 팝업 형태 유지 |

상태 갱신은 250ms 주기를 유지하고 실제 문자열이 같은 경우에만 `setText`를 생략합니다. 지표를 덜 읽거나 정지·일시정지 처리를 늦추는 변경은 아닙니다. FloatingController의 마커 캐시나 실행 엔진 구조를 UI 수정과 함께 재설계하지 않았습니다.

## LEVEL 5 - Expert

### LEVEL 5 · 변경 조건과 구현 근거

| 확인 축 | 27차 내용 | 검토 기준 |
| --- | --- | --- |
| 기능 기반 | 16차 기반 일반 매크로·직전 차수 기능 유지 | OCR·영역·반복·중복·대기·취소·저장·제어 보존 |
| 캡처 시간 | 숨김 안정화와 pacer 대기를 겹치는 순서 | 숨김 150ms 및 API별 1100/500ms 간격 모두 유지 |
| 입력 품질 | 전체 화면 OCR·기존 모델 | ROI 자르기·다운샘플링·새 의존성 없음 |
| UI 범위 | Ui·RunHud·컨트롤·메인 화면 등 UI 8개 파일의 팔레트·중복 문구·간격·선택 표시 | 기능 삭제·실행 흐름 변경 없음 |
| 배포 묶음 | 최종 APK·소스·안내·전체 비교 | 최종 지문·버전·ABI·서명은 확정 결과와 대조 |

라이트 강조색은 `#365F9D`, 다크 강조색은 `#A9C7F5`입니다. 카드 안쪽 세로 여백은 14dp에서 16dp, 모서리는 8dp에서 10dp, 바깥 위·아래 여백은 4/6dp에서 6/8dp로 조정했습니다. RunHud 보조 정보 위에 5dp 간격을 두었습니다. 기존 화면 구성·나눔고딕 Bold와 밝고 어두운 테마 선택을 유지합니다.

`Ui.textIfChanged`는 현재 표시된 문구와 새 문구를 비교해 다를 때만 설정합니다. RunHud의 두 문구와 FloatingController의 상태·재생 문구에 적용하며, MainActivity의 기존 변경 비교도 공통 함수로 모았습니다. 재생 버튼의 접근성 설명과 RunHud의 표시 상태도 같은 값의 재설정을 피합니다. 이런 UI 변경에 별도 성능 개선 수치를 부여하지 않습니다.

### LEVEL 5 · 평가와 재현 시 구분할 항목

| 검사 묶음 | 필요한 기록 | 현재 상태 |

최종 APK의 SHA-256은 `a6ce7b3aa3889117a790e0cab33dd6c659253fe010bfa2d625d7222a4dcc85a8`입니다. 실제 UI 검사에서 같은 값 40회 갱신의 문구 콜백은 최초 1회였고, 문구를 바꾸자 누적 2회가 되었습니다. 이는 동일 문구 재설정 방지의 동작 근거이며 전체 속도 향상률은 아닙니다.

호스트 빌드와 겹친 초기 예비 속도값은 최종 비교 수치로 사용하지 않습니다. 같은 장치에서 제품 빌드 없이 별도 속도 비교를 끝냈습니다. 중단된 연속 검사와 새 실행 시간을 합산하지 않았으며 원래 60분 성공 기준도 변경하지 않았습니다. 남은 호스트 원값·메모리 표본·원문 복구 실패·최종 미확인 항목은 검증 결과에서 구분합니다.

단위·정적 검사는 실제 기기 동작의 대체가 아닙니다. 60분 검사는 같은 실행의 연속성을 확인하는 유한 관측이며 재시작을 숨긴 채 같은 실행으로 합치지 않습니다. 사용자의 블루스택 대신 전용 검사 장치를 사용합니다. 성능 향상률·장기 무중단·모든 게임의 인식률은 결과 없이 주장하지 않습니다.

최종 결과와 남은 한계는 [검증 결과](검증_결과.md)에, 납품 파일의 지문은 [파일 정보](파일정보.json)에 연결합니다. 공개 가능한 코드의 주석·공백을 포함한 실제 차이는 [전체 비교](https://github.com/PUVKID/PXE-Touch-Macro-Project/blob/main/docs/revision-audit/27차.md)에서 확인합니다. 문서 저장 자체를 실제 검사나 원격 게시의 증거로 사용하지 않습니다.
