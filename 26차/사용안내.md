# PXE 26차 사용 안내

**16차의 화면과 일반 매크로를 기준으로 만든 2.6.0입니다.** 시범 학습·행동 AI 메뉴와 모델 가져오기 기능은 포함하지 않습니다. 화면 글자를 읽는 한글 OCR은 앱에 내장되어 오프라인으로 동작합니다.

## 설치

`PXE_26차_v2.6_공용.apk` 하나를 노트10+ 또는 64비트 Android 에뮬레이터에 설치합니다. Android 11 이상을 지원합니다. 기존 앱을 삭제하지 말고 업데이트로 설치하세요. 먼저 중요한 매크로를 내보내 보관하는 편이 좋습니다. 16차와 앱 ID·개인 서명을 유지하며, 16차에서 저장한 매크로·탐지 설정·테마를 이어 읽습니다.

앱의 권한 안내에서 접근성 서비스와 화면 위 표시를 허용합니다. 앱이 실제로 제공하지 않는 화면 정보나 보안상 캡처가 금지된 화면을 강제로 읽지는 않습니다.

## 글자·영역·매크로 정하기

| 순서 | 설정 | 확인할 내용 |
| --- | --- | --- |
| 1 | 찾을 글자 입력 | 정확히 같은 문구면 일치, 일부 문구면 포함을 선택합니다. |
| 2 | 인식 방식 선택 | 게임처럼 이미지로 글자를 그리는 화면은 **한글 OCR**을 사용합니다. 화면 정보는 대상 앱이 제공하는 글자만 읽습니다. |
| 3 | 탐지 영역 그리기 | 필요한 글자와 여백을 포함하고 다른 버튼·비슷한 문구를 줄입니다. |
| 4 | 매크로 녹화 또는 동작 편집 | 터치·제스처·글자 조건·대기 등을 순서대로 구성합니다. |
| 5 | 같은 이름으로 저장 | 목록 탐지는 현재 편집본과 별개인 이름 있는 저장 매크로를 사용합니다. |
| 6 | 탐지에서 매크로 선택 후 시작 | 전체 실행 횟수·우선 영역·복귀·새로고침 시간을 확인합니다. |

안내 화면의 순서대로 글자 입력 → 영역 지정 → 녹화 → 시간 설정 → 실행 준비를 진행할 수 있습니다. 시간은 화면에 표시된 초·분 단위로 입력합니다.

## 15회 실행하고 다시 찾기

탐지 설정에서 실행할 매크로와 반복 **15회**를 선택합니다. 이는 저장한 매크로를 첫 동작부터 15회 실행하는 설정입니다. 동작 편집의 개별 반복 1~1000회는 해당 동작 하나에 적용되므로 둘을 구분하세요.

최대 6개의 우선 영역은 매번 1번부터 검사하고 처음 일치한 영역을 사용합니다. 완료 후 뒤로가기·복귀 대기를 거친 뒤, 완료 후 쉬는 시간과 그 이후 새로고침 간격에 따라 다시 찾습니다. 쉬는 시간과 새로고침 간격은 직접 변경할 수 있습니다. 중복 방지를 켰다면 같은 글자가 안정적으로 사라진 뒤 다시 나타나야 새 실행이 가능합니다. 중복 방지를 끄면 새로고침 뒤 같은 문구도 다시 실행할 수 있으니 목적에 맞게 선택하세요.

## 다음 글자가 나올 때 진행하기

동작 편집의 ‘글자 찾아 터치’ 또는 ‘글자 나타날 때까지 대기’에서 **글자가 나타날 때까지 계속 기다리기**를 켭니다. 기다리는 동안에도 정지할 수 있습니다. 글자가 아직 없다는 이유로 횟수를 소모하거나 뒤로가지는 않습니다.

‘인식 후 추가 대기 없이 다음 동작’은 완료 후 대기와 터치 전 재확인을 생략하는 빠른 옵션입니다. 화면 변화가 많아 정확도가 우선이면 끄고 사용하세요. ‘반복 · 시간 설정 → 다음 글자에 맞춰 진행’은 다음 글자가 사전에 없었다가 나타나는 연속 동작에서 대기를 줄입니다. 이 설정을 바꾼 뒤에도 사용하는 이름으로 다시 저장해야 목록 탐지에 반영됩니다.

‘계속 기다리기’를 끈 동작의 유한 대기 정책은 유지합니다. 창 조회 하나가 늦으면 그 조회의 실제 대기만 최소 1.5초 또는 설정한 글자 제한 중 긴 시간까지 허용합니다. 정상 OCR 계산 전체에 그 제한을 강제로 씌우지는 않습니다. 무한 글자 대기와 목록 탐지는 창 응답이 지연돼도 정지 가능한 대기를 유지합니다. 화면을 읽지 못한 오류를 ‘글자 없음’으로 간주해 잘못 누르지는 않습니다.

## 글자가 없을 때와 조건 분기

동작의 세부 설정에서 ‘글자가 없으면’을 정합니다. 뒤로가기 후 다시 찾기, 같은 화면에서 다시 확인, 위로 스크롤 후 다시 찾기, 다음 동작, 정지를 선택할 수 있습니다. 지정한 재시도 횟수를 모두 써도 없으면 중단하는 기존 정책입니다. ‘계속 기다리기’와 유한 재시도는 서로 다른 사용 방식입니다.

‘글자 조건 분기’는 글자가 있거나 없을 때 이동할 동작 번호를 각각 정합니다. 0은 다음 동작입니다. 예를 들어 확인할 글자 없음 → 뒤로가기 동작 번호 → 처음 찾기 동작 번호로 구성할 수 있습니다. 자신이 원하는 목표 화면을 확인하는 문구와 탐지 영역을 별도로 지정하세요.

## 실행 제어와 화면

| 기능 | 조작 |
| --- | --- |
| 일시정지·재개 | 컨트롤의 Ⅱ / ▶ |
| 완전 정지 | 정지 버튼 또는 접힌 PXE 아이콘 길게 누르기 |
| 접기·펼치기 | PXE 아이콘 터치 |
| 위치 이동 | PXE 아이콘을 끌어서 이동 |
| 투명도·크기·테마 | 앱 설정에서 조정하고 라이트·다크 중 선택 |
| 진행 확인 | 현재 동작·반복 진행·한 바퀴 시간·전체 경과 시간 확인 |
| 원인 확인 | 설정의 실행 기록·오류 기록 |

캡처와 한글 인식에는 실제 처리 시간이 필요합니다. 6개 에뮬레이터를 동시에 쓰는 속도나 모든 화면의 99% 인식률은 이 파일로 보장하지 않습니다. 테스트 환경과 실제 확인 범위는 같은 차수의 검증 결과에 구분해 기록합니다.

## Adobe만 찾기

| 항목 | 설정·동작 |
| --- | --- |
| 인식 방식 | **한글 OCR**: 화면에 보이는 실제 영문을 확인합니다. |
| 찾을 글자 | **Adobe**를 그대로 입력합니다. 한글 `어도비`는 입력하지 않습니다. |
| 비교 방식 | **일치**를 선택합니다. 포함은 `Adobe`가 들어간 더 긴 문구도 허용합니다. |
| 대소문자 | `ADOBE`도 허용하려면 대소문자 무시를 켜고, `Adobe`만 허용하려면 끕니다. |
| 영역 | 영문 버튼을 감싸고 옆의 한글·다른 버튼은 제외합니다. |
| 언어 구분 | 번역·발음·동의어 매칭을 사용하지 않습니다. `Adobe`와 `어도비`는 다른 글자입니다. |

화면 정보·자동 방식은 앱이 노출한 접근성 이름을 읽을 수 있습니다. 아이콘에 `Adobe`라는 접근성 이름이 붙은 경우 실제 표시 글자와 다를 수 있으므로, 화면에 보이는 영문만 고르려면 OCR을 명시적으로 선택합니다. 이미 저장한 탐지와 매크로 안의 글자 동작은 각각 설정하고 같은 이름으로 다시 저장하세요.

## 프로젝트 폴더 위치 변경

빌드 도구는 26차 기준 소스와 실제 빌드 사본의 상위 프로젝트 폴더를 기준으로 경로를 계산합니다. 프로젝트 전체의 차수·코드·실행환경 구조를 유지하면 특정 드라이브 이름에 고정되지 않습니다. 개인 서명 키·SDK·JDK·Gradle은 기존 빌드 안내의 상대 위치에 있어야 합니다. APK를 사용하는 기기의 설정과는 관계없는 개발용 경로 처리입니다.
