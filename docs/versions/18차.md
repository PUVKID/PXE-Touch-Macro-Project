### LEVEL 1 · 이 자료가 하는 일과 달라진 점

### LEVEL 1 · 실제 동작을 따라 읽기

하단 실행 상태창의 정보와 크기를 줄이고 터치로 접고 펼칠 수 있게 했습니다. 반복 설정의 완료 횟수와 현재 실행 중인 회차를 구분합니다.

실제 반복이 끝난 뒤에만 완료 수를 올립니다. 예를 들어 15회 설정에서 7회가 끝나고 다음 회차가 실행 중이면 완료7/15와8회째 실행 중을 구분해 표시합니다. 목록에 들어가서 실행하는 반복 수와 목록 전체를 돌아온 바퀴 수를 혼용하지 않습니다. 예시 숫자는 실행 화면에 고정하지 않습니다.

현재 단계는 짧은 문구로, 실행·대기·일시정지·완료·중단 상태는 색 이외의 글자로도 확인할 수 있습니다. 시간과 완료 바퀴 수는 펼친 창에서 계속 확인하고 기존 실행 기록의 상세 문구를 유지합니다.

펼친 상태창의 최대 폭을280dp로 줄이고 터치하면200×48dp의 한 줄 표시로 접습니다. 다시 터치하면 펼칩니다. 화면이 좁으면 사용 가능한 너비에 맞추고 기존 나눔고딕 Bold와 라이트·다크 테마를 유지합니다.

OCR은 그림에 있는 글자를 텍스트로 읽는 처리입니다. APK는 안드로이드 기기에 설치하는 앱 패키지입니다. 접근성 서비스는 기기의 별도 허용을 받아 화면 조작을 수행하는 안드로이드 기능입니다.

입력 — 매크로 동작·화면 글자·좌표·영역·반복 설정

처리 — 편집·저장 → 대상 앱/글자 확인 → 접근성 제스처 → 진행 갱신

출력 — 터치·플로팅 상태·매크로 JSON·동작/인식/오류 기록

### LEVEL 1 · 준비하고 확인할 것

해당 차수 Gradle 프로젝트의 manifest·리소스·SDK·JDK와 서명 입력을 준비합니다. 실제 기기의 접근성 서비스는 사용자가 직접 허용합니다. 공개 소스만으로 기존 서명 앱의 업데이트가 가능한 것은 아닙니다.

같은 차수의 완전한 프로젝트에서 빌드하고 기기에 설치한 뒤 접근성 서비스를 연결합니다. SDK·Gradle·서명과 차수별 개발 명령은 소스 README 또는 build.gradle을 확인합니다. 소스 일부나 설정 예제만 있는 묶음은 단독 APK가 아닙니다.

#### LEVEL 1 · 진행창 사용

실행하면 하단에 **7/15회 완료 · 8회째**처럼 실제 완료 횟수와 현재 실행 중인 회차를 구분합니다. 다음 줄의 **동작 2/4 · 글자 찾아 터치**는 매크로 안의 동작 번호입니다. 개별 동작 반복, 전체15회 반복, 목록 진입부터 복귀까지의 탐지 바퀴는 서로 다른 값입니다.

진행창을 한 번 누르면 최대200dp·높이48dp의 작은 한 줄 표시로 접습니다. 다시 누르면 최대280dp로 펼쳐 현재 단계와 이번·직전 한 바퀴 시간, 전체 경과, 완료 바퀴를 확인합니다. 접기 선택은 실행 중 갱신·캡처·일시정지·정지·다음 실행에도 유지됩니다. 화면 폭이 좁으면 가용 폭에 맞춥니다.

전체15회가 실제 끝난 뒤15/15로 표시합니다. 탐지 매크로는 복귀와 대기 중에도 직전15/15를 유지하고, 다음 항목에 들어갈 때0/15부터 시작합니다. 정지·일시정지 중에는 완료 횟수가 임의로 올라가지 않습니다. 원래 상세 실행 기록과 시간 측정은 유지하며 화면의 긴 문구만 줄임 표시합니다.

진행창에만 겹치는 자동 터치는 하단 표시만 잠깐 숨기고 위쪽 **■ 정지** 버튼을 유지합니다. 여러 터치 경로가 위쪽 제어창 자체에도 겹치는 경우에는 기존 충돌 보호를 우선합니다. 녹화 중에도 진행창을 숨겨 녹화 재생을 가로채지 않습니다. 라이트/다크와 나눔고딕Bold를 유지합니다.

#### LEVEL 1 · 16차의 적응 실행과 실제 입체 모델

매크로 설정의 **다음 글자에 맞춰 진행**은 기본 꺼짐입니다. 켜면 같은 인식 방식과 영역의 연속 글자 동작에서 다음 글자의 사전 부재를 확인한 경우, 완료 후 대기를 다음 조건 대기로 바꿔 새 글자가 보이면 진행합니다. 이미 보이는 조건·수동 대기·반복 간격·무작위 대기는 유지합니다. 바로 다음 글자 터치가 같은 위치를 가리키면 사라짐과 재등장을 확인합니다. 개별 동작의 명시적 반복이나 전체 반복 경계를 모두 차단하는 기능은 아닙니다. 목록 탐지의 기존 사라짐 확인 설정은 별도로 유지합니다. 기존 프로필의 숫자를 일괄 축소하거나 터치 전 재확인을 끄지 않습니다.

실행 측정은 단계·OCR·캡처·설정 대기의 실제 시간을 구분합니다. 단계 시간에는 하위 작업이 포함되므로 네 값을 더한 숫자를 전체 시간으로 사용하지 않습니다. 전체 반복의 외부 측정과 내부 집계를 구분합니다.

실행 준비보다 먼저 일시정지하거나 정지해도 이전 대기열 작업이 측정값을 다시 초기화하지 않도록 실행 세대를 확인합니다. 개별 글자 터치는 제어창 준비 뒤에 대상을 확인하고, 실제 전달 직전에 관측된 창 변경과 일시정지 세대를 다시 대조합니다. 이 추가 전달 검사는 개별 `TEXT_TAP` 경로에 적용합니다. 목록 진입 터치는 기존의 대상 확인과 중복 예약 순서를 유지합니다.

홈의 PXE 모델은 실제 OBJ 224정점·168면을 읽어 원근 투영·깊이 정렬·조명으로 그립니다. 상태가 바뀔 때 갱신하며 상시 애니메이션·예약 렌더 루프는 없습니다. 나눔고딕 Bold와 기존 라이트/다크·제어 흐름을 유지합니다.

15회 120초는 통제 시험에서 측정할 목표입니다. 실제 게임·사용자 블루스택의 성공률99% 또는 무오류를 코드만으로 보장하지 않습니다. 납품 검사 결과에 실제 실행 범위를 기록합니다.

#### LEVEL 1 · 매크로 저장과 실행 입력 검증

`Macro`는 schema1의 JSON으로 이름·시작 번호·전체 반복·반복 간격·시작 지연·최대 시간·동작 배열을 직렬화합니다. `validate`는 동작1~500개, 시작 번호가 실제 배열 범위 안인지 검사하고 활성 동작에 `Step.validate`를 적용합니다. 전체 반복은0~100,000, 간격·시작 지연은0~600,000ms, 최대 시간은0~1,440분 범위입니다.

`Step`은 동작 종류·좌표·검색영역·글자 비교·인식 출처·실패 정책·반복과 대기·분기 번호를 저장합니다. 입력 검증은 화면 비율 좌표와 유한값, 검색 영역의 좌우/상하 순서, 문구 존재, 정규식 문법, 앱 패키지명과 이동/분기 번호를 함께 확인합니다. 저장 JSON의 schema 통과와 실제 장치의 접근성/OCR 가용성은 별도 조건입니다.

1. 매크로를 선택하거나 만들고 각 동작·반복·대기를 확인합니다.
2. 글자 조건은 인식 방식과 검색 영역을 같이 지정합니다.
3. 대상 앱과 접근성 서비스 상태를 확인한 뒤 실행합니다.
4. 플로팅 제어의 정지·일시정지와 진행 기록을 확인합니다.

#### LEVEL 2 · 매크로 저장과 실행 입력 검증

`Macro`는 schema1의 JSON으로 이름·시작 번호·전체 반복·반복 간격·시작 지연·최대 시간·동작 배열을 직렬화합니다. `validate`는 동작1~500개, 시작 번호가 실제 배열 범위 안인지 검사하고 활성 동작에 `Step.validate`를 적용합니다. 전체 반복은0~100,000, 간격·시작 지연은0~600,000ms, 최대 시간은0~1,440분 범위입니다.

매크로 설정의 **다음 글자에 맞춰 진행**은 기본 꺼짐입니다. 켜면 같은 인식 방식과 영역의 연속 글자 동작에서 다음 글자의 사전 부재를 확인한 경우, 완료 후 대기를 다음 조건 대기로 바꿔 새 글자가 보이면 진행합니다. 이미 보이는 조건·수동 대기·반복 간격·무작위 대기는 유지합니다. 바로 다음 글자 터치가 같은 위치를 가리키면 사라짐과 재등장을 확인합니다. 개별 동작의 명시적 반복이나 전체 반복 경계를 모두 차단하는 기능은 아닙니다. 목록 탐지의 기존 사라짐 확인 설정은 별도로 유지합니다. 기존 프로필의 숫자를 일괄 축소하거나 터치 전 재확인을 끄지 않습니다.

실행 측정은 단계·OCR·캡처·설정 대기의 실제 시간을 구분합니다. 단계 시간에는 하위 작업이 포함되므로 네 값을 더한 숫자를 전체 시간으로 사용하지 않습니다. 전체 반복의 외부 측정과 내부 집계를 구분합니다.

실행 준비보다 먼저 일시정지하거나 정지해도 이전 대기열 작업이 측정값을 다시 초기화하지 않도록 실행 세대를 확인합니다. 개별 글자 터치는 제어창 준비 뒤에 대상을 확인하고, 실제 전달 직전에 관측된 창 변경과 일시정지 세대를 다시 대조합니다. 이 추가 전달 검사는 개별 `TEXT_TAP` 경로에 적용합니다. 목록 진입 터치는 기존의 대상 확인과 중복 예약 순서를 유지합니다.

홈의 PXE 모델은 실제 OBJ 224정점·168면을 읽어 원근 투영·깊이 정렬·조명으로 그립니다. 상태가 바뀔 때 갱신하며 상시 애니메이션·예약 렌더 루프는 없습니다. 나눔고딕 Bold와 기존 라이트/다크·제어 흐름을 유지합니다.

15회 120초는 통제 시험에서 측정할 목표입니다. 실제 게임·사용자 블루스택의 성공률99% 또는 무오류를 코드만으로 보장하지 않습니다. 납품 검사 결과에 실제 실행 범위를 기록합니다.

#### LEVEL 3 · 매크로 저장과 실행 입력 검증

`Macro`는 schema1의 JSON으로 이름·시작 번호·전체 반복·반복 간격·시작 지연·최대 시간·동작 배열을 직렬화합니다. `validate`는 동작1~500개, 시작 번호가 실제 배열 범위 안인지 검사하고 활성 동작에 `Step.validate`를 적용합니다. 전체 반복은0~100,000, 간격·시작 지연은0~600,000ms, 최대 시간은0~1,440분 범위입니다.

#### LEVEL 4 · 진행창 사용

진행창을 한 번 누르면 최대200dp·높이48dp의 작은 한 줄 표시로 접습니다. 다시 누르면 최대280dp로 펼쳐 현재 단계와 이번·직전 한 바퀴 시간, 전체 경과, 완료 바퀴를 확인합니다. 접기 선택은 실행 중 갱신·캡처·일시정지·정지·다음 실행에도 유지됩니다. 화면 폭이 좁으면 가용 폭에 맞춥니다.

전체15회가 실제 끝난 뒤15/15로 표시합니다. 탐지 매크로는 복귀와 대기 중에도 직전15/15를 유지하고, 다음 항목에 들어갈 때0/15부터 시작합니다. 정지·일시정지 중에는 완료 횟수가 임의로 올라가지 않습니다. 원래 상세 실행 기록과 시간 측정은 유지하며 화면의 긴 문구만 줄임 표시합니다.

진행창에만 겹치는 자동 터치는 하단 표시만 잠깐 숨기고 위쪽 **■ 정지** 버튼을 유지합니다. 여러 터치 경로가 위쪽 제어창 자체에도 겹치는 경우에는 기존 충돌 보호를 우선합니다. 녹화 중에도 진행창을 숨겨 녹화 재생을 가로채지 않습니다. 라이트/다크와 나눔고딕Bold를 유지합니다.

#### LEVEL 4 · 16차의 적응 실행과 실제 입체 모델

매크로 설정의 **다음 글자에 맞춰 진행**은 기본 꺼짐입니다. 켜면 같은 인식 방식과 영역의 연속 글자 동작에서 다음 글자의 사전 부재를 확인한 경우, 완료 후 대기를 다음 조건 대기로 바꿔 새 글자가 보이면 진행합니다. 이미 보이는 조건·수동 대기·반복 간격·무작위 대기는 유지합니다. 바로 다음 글자 터치가 같은 위치를 가리키면 사라짐과 재등장을 확인합니다. 개별 동작의 명시적 반복이나 전체 반복 경계를 모두 차단하는 기능은 아닙니다. 목록 탐지의 기존 사라짐 확인 설정은 별도로 유지합니다. 기존 프로필의 숫자를 일괄 축소하거나 터치 전 재확인을 끄지 않습니다.

실행 측정은 단계·OCR·캡처·설정 대기의 실제 시간을 구분합니다. 단계 시간에는 하위 작업이 포함되므로 네 값을 더한 숫자를 전체 시간으로 사용하지 않습니다. 전체 반복의 외부 측정과 내부 집계를 구분합니다.

실행 준비보다 먼저 일시정지하거나 정지해도 이전 대기열 작업이 측정값을 다시 초기화하지 않도록 실행 세대를 확인합니다. 개별 글자 터치는 제어창 준비 뒤에 대상을 확인하고, 실제 전달 직전에 관측된 창 변경과 일시정지 세대를 다시 대조합니다. 이 추가 전달 검사는 개별 `TEXT_TAP` 경로에 적용합니다. 목록 진입 터치는 기존의 대상 확인과 중복 예약 순서를 유지합니다.

홈의 PXE 모델은 실제 OBJ 224정점·168면을 읽어 원근 투영·깊이 정렬·조명으로 그립니다. 상태가 바뀔 때 갱신하며 상시 애니메이션·예약 렌더 루프는 없습니다. 나눔고딕 Bold와 기존 라이트/다크·제어 흐름을 유지합니다.

15회 120초는 통제 시험에서 측정할 목표입니다. 실제 게임·사용자 블루스택의 성공률99% 또는 무오류를 코드만으로 보장하지 않습니다. 납품 검사 결과에 실제 실행 범위를 기록합니다.

#### LEVEL 4 · 매크로 저장과 실행 입력 검증

`Macro`는 schema1의 JSON으로 이름·시작 번호·전체 반복·반복 간격·시작 지연·최대 시간·동작 배열을 직렬화합니다. `validate`는 동작1~500개, 시작 번호가 실제 배열 범위 안인지 검사하고 활성 동작에 `Step.validate`를 적용합니다. 전체 반복은0~100,000, 간격·시작 지연은0~600,000ms, 최대 시간은0~1,440분 범위입니다.

`Step`은 동작 종류·좌표·검색영역·글자 비교·인식 출처·실패 정책·반복과 대기·분기 번호를 저장합니다. 입력 검증은 화면 비율 좌표와 유한값, 검색 영역의 좌우/상하 순서, 문구 존재, 정규식 문법, 앱 패키지명과 이동/분기 번호를 함께 확인합니다. 저장 JSON의 schema 통과와 실제 장치의 접근성/OCR 가용성은 별도 조건입니다.

완료 반복 수와 현재 회차, 글자 부재와 화면 읽기 실패, 중지와 복구 대기를 구분합니다. 운영 로그에는 화면 인식 본문이 포함될 수 있어 공유 전 확인합니다.

**상황:** 서비스 연결 실패

**확인할 내용:** 기기 접근성 권한과 실제 서비스 연결을 확인합니다.

**상황:** 글자 탐지 실패

**확인할 내용:** 인식 방식·검색 영역·실제 접근성 텍스트와 화면 캡처 제한을 확인합니다.

**상황:** 좌표 또는 반복 불일치

**확인할 내용:** 화면 방향·비율 좌표·개별/전체/목록 반복을 나눠 확인합니다.

### 이 차수 원래 안내의 세부 조건

### 완료 횟수와 현재 작업

실제 반복이 끝난 뒤에만 완료 수를 올립니다. 예를 들어 15회 설정에서 7회가 끝나고 다음 회차가 실행 중이면 완료7/15와8회째 실행 중을 구분해 표시합니다. 목록에 들어가서 실행하는 반복 수와 목록 전체를 돌아온 바퀴 수를 혼용하지 않습니다. 예시 숫자는 실행 화면에 고정하지 않습니다.

현재 단계는 짧은 문구로, 실행·대기·일시정지·완료·중단 상태는 색 이외의 글자로도 확인할 수 있습니다. 시간과 완료 바퀴 수는 펼친 창에서 계속 확인하고 기존 실행 기록의 상세 문구를 유지합니다.

### 진행창 사용

실행하면 하단에 **7/15회 완료 · 8회째**처럼 실제 완료 횟수와 현재 실행 중인 회차를 구분합니다. 다음 줄의 **동작 2/4 · 글자 찾아 터치**는 매크로 안의 동작 번호입니다. 개별 동작 반복, 전체15회 반복, 목록 진입부터 복귀까지의 탐지 바퀴는 서로 다른 값입니다.

진행창을 한 번 누르면 최대200dp·높이48dp의 작은 한 줄 표시로 접습니다. 다시 누르면 최대280dp로 펼쳐 현재 단계와 이번·직전 한 바퀴 시간, 전체 경과, 완료 바퀴를 확인합니다. 접기 선택은 실행 중 갱신·캡처·일시정지·정지·다음 실행에도 유지됩니다. 화면 폭이 좁으면 가용 폭에 맞춥니다.

전체15회가 실제 끝난 뒤15/15로 표시합니다. 탐지 매크로는 복귀와 대기 중에도 직전15/15를 유지하고, 다음 항목에 들어갈 때0/15부터 시작합니다. 정지·일시정지 중에는 완료 횟수가 임의로 올라가지 않습니다. 원래 상세 실행 기록과 시간 측정은 유지하며 화면의 긴 문구만 줄임 표시합니다.

진행창에만 겹치는 자동 터치는 하단 표시만 잠깐 숨기고 위쪽 **■ 정지** 버튼을 유지합니다. 여러 터치 경로가 위쪽 제어창 자체에도 겹치는 경우에는 기존 충돌 보호를 우선합니다. 녹화 중에도 진행창을 숨겨 녹화 재생을 가로채지 않습니다. 라이트/다크와 나눔고딕Bold를 유지합니다.

### 16차의 적응 실행과 실제 입체 모델

매크로 설정의 **다음 글자에 맞춰 진행**은 기본 꺼짐입니다. 켜면 같은 인식 방식과 영역의 연속 글자 동작에서 다음 글자의 사전 부재를 확인한 경우, 완료 후 대기를 다음 조건 대기로 바꿔 새 글자가 보이면 진행합니다. 이미 보이는 조건·수동 대기·반복 간격·무작위 대기는 유지합니다. 바로 다음 글자 터치가 같은 위치를 가리키면 사라짐과 재등장을 확인합니다. 개별 동작의 명시적 반복이나 전체 반복 경계를 모두 차단하는 기능은 아닙니다. 목록 탐지의 기존 사라짐 확인 설정은 별도로 유지합니다. 기존 프로필의 숫자를 일괄 축소하거나 터치 전 재확인을 끄지 않습니다.

실행 측정은 단계·OCR·캡처·설정 대기의 실제 시간을 구분합니다. 단계 시간에는 하위 작업이 포함되므로 네 값을 더한 숫자를 전체 시간으로 사용하지 않습니다. 전체 반복의 외부 측정과 내부 집계를 구분합니다.

실행 준비보다 먼저 일시정지하거나 정지해도 이전 대기열 작업이 측정값을 다시 초기화하지 않도록 실행 세대를 확인합니다. 개별 글자 터치는 제어창 준비 뒤에 대상을 확인하고, 실제 전달 직전에 관측된 창 변경과 일시정지 세대를 다시 대조합니다. 이 추가 전달 검사는 개별 `TEXT_TAP` 경로에 적용합니다. 목록 진입 터치는 기존의 대상 확인과 중복 예약 순서를 유지합니다.

홈의 PXE 모델은 실제 OBJ 224정점·168면을 읽어 원근 투영·깊이 정렬·조명으로 그립니다. 상태가 바뀔 때 갱신하며 상시 애니메이션·예약 렌더 루프는 없습니다. 나눔고딕 Bold와 기존 라이트/다크·제어 흐름을 유지합니다.

15회 120초는 통제 시험에서 측정할 목표입니다. 실제 게임·사용자 블루스택의 성공률99% 또는 무오류를 코드만으로 보장하지 않습니다. 납품 검사 결과에 실제 실행 범위를 기록합니다.

### 매크로 저장과 실행 입력 검증

`Macro`는 schema1의 JSON으로 이름·시작 번호·전체 반복·반복 간격·시작 지연·최대 시간·동작 배열을 직렬화합니다. `validate`는 동작1~500개, 시작 번호가 실제 배열 범위 안인지 검사하고 활성 동작에 `Step.validate`를 적용합니다. 전체 반복은0~100,000, 간격·시작 지연은0~600,000ms, 최대 시간은0~1,440분 범위입니다.

`Step`은 동작 종류·좌표·검색영역·글자 비교·인식 출처·실패 정책·반복과 대기·분기 번호를 저장합니다. 입력 검증은 화면 비율 좌표와 유한값, 검색 영역의 좌우/상하 순서, 문구 존재, 정규식 문법, 앱 패키지명과 이동/분기 번호를 함께 확인합니다. 저장 JSON의 schema 통과와 실제 장치의 접근성/OCR 가용성은 별도 조건입니다.
