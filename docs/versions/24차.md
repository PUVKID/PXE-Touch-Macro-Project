### LEVEL 1 · 그림을 가르친다는 뜻

| 구분 | 동작·조건과 확인 범위 |
| --- | --- |
| 기본 매크로의 역할 | PXE의 기본 기능은 미리 정한 순서대로 글자를 찾고 화면을 누르는 **매크로**입니다. |
| 선택형 시각 AI 변경 | 24차는 선택형 AI에 글자 없는 아이콘도 가르치려는 변경입니다. |
| AI 기본 꺼짐 | AI는 처음에는 꺼져 있으며, 기존 매크로를 쓰는 데 켤 필요가 없습니다. |
| 이미지 시범의 입력 | 예를 들어 그림 버튼을 가르칠 때는 그때 보이는 글자와 화면의 색 배치, 사용자가 누른 그림 조각을 함께 기록합니다. |
| 현재 화면 위치 재탐색 | 다시 실행할 때는 예전 좌표를 그대로 누르는 대신 현재 화면에서 그림을 다시 찾은 위치를 사용합니다. |
| 중복·낯선 화면 대기 | 같은 그림이 두 개 있어 구별하기 어렵거나 처음 보는 화면이면 누르지 않고 기다립니다. |
| OCR의 뜻 | OCR은 화면 사진의 글자를 읽는 기능입니다. |
| RGB의 뜻 | RGB는 화면 색을 빨강·초록·파랑 값으로 나타내는 방법입니다. |
| 정책 모델의 역할 | 정책 모델은 이 관측을 보고 가르친 행동 중 하나를 고르는 작은 신경망입니다. |
| 확정 시범·가중치 갱신 | 사용자가 확인한 시범으로 가중치, 즉 행동 선택에 쓰는 내부 숫자를 바꿉니다. |
| 시범 저장·학습 구분 | 화면을 저장했다는 사실만으로 학습이 끝난 것은 아닙니다. |
| 동작별 선택 모드 분리 | 이미지 선택, 글자 대기, 일반 동작 선택은 각각 다른 입력이므로 앞에서 선택한 이미지 모드가 다음 동작에 남지 않아야 합니다. |



### LEVEL 1 · 예전 모델과 새 저장 파일

| 구분 | 동작·조건과 확인 범위 |
| --- | --- |
| 시각 정책 입력 구성 | 24차의 시각 정책은 글자와 이전 행동 등의 584개 값에 색 배치 576개를 더한 **1160개 입력**을 사용합니다. |
| F64의 의미 | F64는 내부 숫자를 64 비트로 저장한다는 뜻이며 정확도가 64%라는 뜻이 아닙니다. |
| 구형 모델 읽기 | 구형 584차원 모델을 읽는 기능도 남깁니다. |
| packed 저장 상태 | 새 모델은 v2 packed라는 묶음에 가중치뿐 아니라 시범, 행동 이름표, 난수 생성 상태와 학습 상태를 넣습니다. |
| 난수 상태의 역할 | 난수 생성 상태는 학습의 다음 계산을 이어 가는 데 필요한 기록입니다. |
| 파일 형식·이식 확인 | 파일 형식을 검사했더라도 다른 휴대 전화에 가져와 파일 선택 창으로 여는 과정까지 확인한 것은 아닙니다. |
| 개인 자료 비공개 | 개인 시범·화면·모델은 비공개로 보관합니다. |



### LEVEL 1 · 응답이 늦을 때 누르기를 반복하지 않기

| 구분 | 동작·조건과 확인 범위 |
| --- | --- |
| 늦은 입력·중복 위험 | 화면 작업의 답이 늦으면 한 번 더 누르고 싶을 수 있지만, 첫 입력이 뒤늦게 실행되면 두 번 눌릴 수 있습니다. |
| 지연 기준·동일 future | 그래서 일반 화면 작업의 5초와 제스처의 65초는 지연을 알리는 기준으로 쓰고 **처음 요청한 작업의 결과를 계속 기다립니다**. future는 이 결과를 받기 위한 대기 표에 해당합니다. |
| 입력 재전송 금지 | 새 대기 표를 만들어 같은 터치를 다시 보내지 않습니다. |
| 입력 없는 캡처 준비 | 아직 실제 입력을 하지 않은 화면 캡처 준비는 다르게 처리합니다. |
| 준비 취소·큐 제거 | 오래된 준비 작업을 취소하고 대기열에서 제거한 뒤 새 준비를 시도합니다. |
| 중단·권한·시간 경계 | 이때도 정지, 권한 해제, 서비스 종료, 회전과 사용자가 정한 전체 실행 시간 제한을 확인합니다. |
| 영구 무응답의 한계 | 영원히 응답이 없는 기기를 반드시 복구한다는 약속은 아닙니다. |

## LEVEL 2 - Explorer

[같은 수준 프로젝트](../읽기안내/레벨2.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨2.md)

### LEVEL 2 · 화면 관측과 행동 선택의 연결

| 구분 | 동작·조건과 확인 범위 |
| --- | --- |
| 행동 정책·실행 경계 | 24차의 변경은 **무엇을 할지 고르는 정책**과 **지금 어디를 눌러도 되는지 확인하는 실행 경계**를 함께 읽어야 이해할 수 있습니다. |
| 기본 매크로·선택 AI | 기존 매크로는 사용자가 정한 순서를 실행하며, 기본 꺼짐인 선택형 AI가 이를 대체하지 않습니다. |
| 정책 관측·행동 선택 | 새 정책은 시범의 OCR 글자와 RGB 색 배치를 입력으로 받고 가르친 행동을 선택합니다. |
| 현재 아이콘 위치 결정 | 선택이 이미지 터치라면 저장한 아이콘 외형 조각을 현재 화면에서 찾아 위치를 정합니다. |
| 행동 선택·좌표 구분 | 따라서 정책이 행동을 골랐다는 사실만으로 예전 좌표를 전달할 수는 없습니다. |
| 글자·그림 구별 조건 | 글자만 다른 두 화면과 글자는 같지만 그림이 다른 두 화면은 구별해야 할 조건이 다릅니다. |
| 입력 차원별 구성 | 1160차원 입력은 글자·이전 행동·상태를 담은 584차원과 RGB 배치 576차원을 결합합니다. |
| 불확실 관측의 대기 | 같은 그림이 중복되거나 새 화면이라 판단 근거가 부족하면 입력 없이 대기합니다. |
| 선택 모드 수명 | 이미지 선택 뒤 글자 대기나 일반 동작을 고를 때도 모드를 분리해야 이전 이미지 선택이 새 시범의 의미를 바꾸지 않습니다. |
| 확정 시범·실제 학습 | 학습에 쓰는 것은 사용자가 확정한 시범이며, 시범 저장과 실제 가중치 갱신은 서로 다른 과정입니다. |



### LEVEL 2 · 호환성과 이식은 다른 연결 단계

| 구분 | 동작·조건과 확인 범위 |
| --- | --- |
| 구형 신경망 구성 | 구형 글자 정책의 **584→32→K F64 MLP**는 584개 입력, 32개 중간 노드, K개 행동 출력을 가진 작은 신경망입니다. |
| 구형·신규 입력 호환 | 새 시각 정책과 구형 모델을 같은 입력 형식으로 억지 해석하지 않고 구형 584차원 읽기를 유지합니다. |
| packed 상태 묶음 | 새 v2 packed 묶음은 F64 가중치와 시범·행동 사전·RNG·학습 상태를 함께 저장합니다. |
| RNG·추가 학습 상태 | RNG는 난수 생성기의 상태로, 단순히 지금의 예측만 복제하는 것과 이어서 학습할 상태를 보존하는 것의 차이를 보여 줍니다. |


여기에는 세 경계가 있습니다.

| 검증 경계 | 확인할 대상 |
| --- | --- |
| 바이트 형식 | 파일의 바이트 형식이 맞는지 확인합니다. |
| 모델·학습 상태 | 읽은 모델과 학습 상태가 맞는지 확인합니다. |
| 다른 설치의 실제 이식 | 파일 선택·가져오기와 실행이 되는지 확인합니다. |

저장 형식 검사 통과를 세 번째 단계까지의 실측으로 확대할 수 없습니다.

개인 시범·화면·모델은 이 연결을 설명하는 공개 예제로 복제하지 않습니다.


### LEVEL 2 · 늦은 응답에서 재시도를 나누는 이유

| 구분 | 동작·조건과 확인 범위 |
| --- | --- |
| 요청·완료 시점 | 화면 작업은 요청 시점과 완료 시점이 다릅니다. |
| 입력 재전송 위험 | 터치가 이미 전달됐는데 결과만 늦는 경우, 같은 요청을 다시 보내면 중복 동작이 됩니다. |
| 지연 기준·원래 결과 | 그래서 UI 5초·제스처 65초는 **지연 관측 기준**으로 두고 원래 future에서 결과를 받습니다. |
| future 재생성 제한 | future를 새로 만들어 다시 입력하는 방식이 아닙니다. |
| 캡처 준비의 입력 경계 | 반대로 캡처 준비는 아직 입력이 없는 단계입니다. |
| 준비 작업 정리·재시도 | 오래된 준비 작업을 취소하고 큐에서 제거한 뒤 새 준비로 진행할 수 있습니다. |
| 일괄 재시도의 위험 | 이 차이를 무시하고 모든 시간 초과를 동일하게 재시도하면 중복 입력과 작업 누적이 생길 수 있습니다. |
| 공통 중단 조건 | 정지·권한 해제·서비스 종료·회전·전체 실행 기한은 두 경로 모두에서 별도로 살아 있습니다. |
| 대기·중단 조건 유지 | 기다림을 늘렸다는 사실이 이 중단 조건을 해제하지 않습니다. |

### LEVEL 3 · 사용할 버전과 자료부터 구분하기

24차를 확인할 때는 [사용 안내](../../24차/사용안내.md)와 [검증 기록](../../24차/검증_결과.md)을 먼저 함께 읽습니다.

| 구분 | 동작·조건과 확인 범위 |
| --- | --- |
| 주 기능·AI 기본값 | 일반 매크로가 주 기능이며 AI 기본값은 꺼짐입니다. |
| 이미지 시범 경로 | 그림 학습을 시험하려면 선택형 AI의 시범 경로를 사용해야 합니다. |
| 구형·시각 모델 입력 | 기존 글자 모델은 584 →32 →K F64 MLP이고, 시각 정책의 입력은 **1160차원 OCR +RGB**입니다. |
| 읽기 호환·신규 학습 | 구형 584차원 모델을 읽을 수 있다는 조건과 새 이미지 시범을 학습시키는 조건을 구분하십시오. |
| 현재 공용 판본 | 현재 공용 파일은 **버전 24 / 2.4.0**입니다. |
| **최종 파일 식별 근거** | 최종 크기와 SHA-256은 [24차 검증 결과](../../24차/검증_결과.md)의 최종 파일 표를 따릅니다. |
| **장치·통신 지원 범위** | ARM64와 x86_64를 지원하며 인터넷 권한 없이 동작합니다. |


### LEVEL 3 · 시범을 넣고 결과를 확인하는 순서

| 구분 | 동작·조건과 확인 범위 |
| --- | --- |
| 화면·행동 구분 | 1. 가르칠 화면과 행동을 구분합니다. |
| 이미지 시범의 근거 | 그림 행동에서는 시범의 OCR·RGB 배치와 아이콘 외형 조각이 함께 근거가 됩니다. |
| 이전 모드 잔존 확인 | 글자 대기 또는 일반 동작을 선택한 경우 이전 이미지 모드가 남아 있지 않은지도 확인할 항목입니다. |
| 사용자 확정 시범 학습 | 2. 사용자가 확인한 시범으로 학습합니다. |
| 저장·가중치 갱신 구분 | 파일 저장 여부만 보지 말고 정책 가중치 갱신을 별도 근거로 봅니다. |
| 정책 학습의 범위 | 정책이 하는 일은 등록한 행동의 선택이며 OCR 엔진 자체의 재학습이나 범용 LLM 학습이 아닙니다. |
| 현재 화면 위치 확인 | 3. 실행 때에는 현재 화면에서 다시 찾은 위치를 확인합니다. |
| 과거 좌표의 한계 | 시범 당시 좌표와 같다는 이유로 성공을 판단하지 않습니다. |
| 불확실 화면 대기 | 같은 그림이 겹치거나 새 화면인 경우 입력 없이 기다리는 조건을 확인합니다. |
| 내보내기 상태 확인 | 4. 내보내기 자료는 v2 packed의 가중치·시범·행동 사전·RNG·학습 상태를 함께 봅니다. |
| 형식·SAF 이식 확인 | 저장 형식 검사 결과가 있어도 다른 설치에서 SAF 파일 선택과 가져오기를 실제로 했다는 기록이 없으면 이식 완료로 기록하지 않습니다. |


개인 화면·시범·모델은 공개 결과 자료에 넣지 않습니다. 위 순서는 검토할 항목이며 이 문서를 읽는 사용자 환경에서 실제 시험을 마쳤다는 뜻은 아닙니다.


### LEVEL 3 · 지연과 정지를 판독하기

| 구분 | 동작·조건과 확인 범위 |
| --- | --- |

## LEVEL 5 - Expert

[같은 수준 프로젝트](../읽기안내/레벨5.md) · [같은 수준 프로필](https://github.com/PUVKID/PUVKID/blob/main/docs/읽기안내/레벨5.md)

### LEVEL 5 · 모델과 실행 구조

시각 정책은 글자·직전 행동·상태 584차원과 RGB 배치 576차원을 결합한 **1160차원 입력**을 사용합니다.

구형 584 →32 →K F64 MLP 읽기 호환도 제공합니다. v2 packed에는 F64 가중치·행동 사전·확정 시 범·RNG·학습 상태를 저장합니다.

OCR 엔진 자체를 재학습하거나 범용 언어 모델을 탑재하는 구조는 아닙니다.

| 구현 | 책임 |
| --- | --- |
| BehaviorVisual / BehaviorVisualPolicy | 화면 특징과 시각 행동 정책 |
| BehaviorAndroidBridge / BehaviorAndroidSession | 관측·시범·학습·실행 연결 |
| VisualMatcher | 저장한 외형 조각을 현재 화면에서 다시 탐색 |
| MacroService | 실행 세대·일시정지·취소·대상 앱·입력 경계 |
| FloatingController | 이동·접기·중단과 시범 모드 제어 |

### LEVEL 5 · 비동기 응답과 중복 입력

일반 UI 5초·제스처 65초는 지연을 관측하는 기준입니다.

이미 보낸 입력은 동일 future를 기다리며 재전송하지 않습니다.

입력 없는 캡처 준비만 오래된 작업 취소·큐 제거 뒤 새 준비를 시도합니다.

사용자 중단·권한 회수·서비스 종료·회전·전체 실행 기한은 계속 검사합니다.

화면을 읽지 못한 상태를 글자 없음으로 바꿔 뒤로 가기를 실행하지 않습니다.

### LEVEL 5 · 결과와 재현 자료

정상 빌드 13의 단위 44 클래스·280개와 린트 오류 0개·경고 4개를 확인했습니다. 실제 기기 시험은 기능 1개·시 각 2개이며 최종 빌드와의 결합 방식은 [24차 검증 결과](../../24차/검증_결과.md)에 기록했습니다. 단위 검사 수·기기 검사 수·시범 수·학습 단계 수를 같은 분모로 합치지 않습니다.
