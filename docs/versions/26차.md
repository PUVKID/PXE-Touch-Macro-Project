## LEVEL 1 - Beginner

## 직접 정한 순서대로 글자를 찾고 누르기

PXE는 화면의 글자를 읽고 사용자가 만든 순서대로 터치·스크롤·뒤로가기를 실행하는 앱입니다.  
이번 26차는 **16차의 화면과 일반 매크로**를 기준으로 합니다.  
사용자가 시범을 보여 주며 행동을 학습시키는 별도 AI는 포함하지 않습니다.  
OCR은 화면 사진에서 글자를 읽는 기능이며 계속 필요하므로 앱 안에 유지했습니다.  
인터넷 연결이 없어도 사용할 수 있습니다.

| 설정할 것 | 실제 동작 | 주의할 점 |
| --- | --- | --- |
| 글자와 네모 영역 | 지정한 영역에서 문구를 찾아 누릅니다. | 비슷한 문구와 다른 버튼을 영역에서 줄입니다. |
| 녹화 또는 동작 목록 | 저장한 순서대로 터치·대기·뒤로가기를 실행합니다. | 이름으로 저장한 매크로와 편집 중인 매크로는 구분합니다. |
| 반복 횟수 | 탐지한 항목에 들어가 저장 매크로를 지정 횟수 실행합니다. | 동작 하나의 반복과 전체 매크로 반복은 다릅니다. |
| 글자가 없을 때 | 기다리거나, 뒤로가기·스크롤 뒤 다시 찾습니다. | 계속 기다리기와 횟수가 있는 재시도는 다른 설정입니다. |
| 우선 영역과 새로고침 | 최대 6개 영역을 순서대로 확인하고 완료 후 다시 탐지합니다. | 같은 문구 중복 방지는 별도 설정입니다. |

### 설치에서 저장까지

| 구분 | 적용 내용 |
| --- | --- |
| 업데이트·권한 | 공용 APK를 기존 앱 위에 업데이트로 설치하고 권한 안내를 따릅니다. |
| 안내 순서 | 찾을 글자 → 탐지 영역 → 매크로 녹화 → 시간·반복 설정 → 실행 준비 순으로 안내 화면을 따라가세요. |
| 게임 인식 | 게임처럼 글자가 이미지로 그려지는 화면은 한글 OCR을 선택합니다. |
| 저장본 반영 | 이름으로 저장한 매크로를 수정했다면 같은 이름으로 다시 저장하고 탐지에서 그 이름을 선택해야 합니다. |

### 다음 글자와 속도 설정

| 구분 | 적용 내용 |
| --- | --- |
| 계속 기다리기 | 다음 버튼을 기다리고 싶다면 해당 글자 동작에서 ‘글자가 나타날 때까지 계속 기다리기’를 켭니다. |
| 부재 처리 | 글자가 없다는 이유로 멈추거나 바로 뒤로가지는 않습니다. |
| 빠른 옵션의 조건 | 인식 후 추가 대기 생략은 빠른 옵션이지만 터치 전 재확인도 생략하므로 정확도를 우선하면 꺼 두세요. |
| 적응 대기 | 서로 이어지는 글자 조건에는 ‘다음 글자에 맞춰 진행’ 옵션을 사용할 수 있습니다. |

| 재시도 종료 | 유한 재시도 횟수를 모두 써도 없으면 중단하는 정책은 유지합니다. |
| 오류와 글자 부재 | 화면을 읽을 수 없다는 오류와 실제로 글자가 없는 상황은 다릅니다. |

## LEVEL 2 - Explorer

## 탐지와 실행이 이어지는 순서

26차는 학습 모델이 다음 행동을 고르는 방식 대신, 사용자가 지정한 조건과 동작을 실행합니다.  
한글 OCR 모델은 글자를 읽는 부품으로만 사용합니다.  
화면 정보 방식은 대상 앱이 공개하는 글자 목록을 읽고, OCR은 캡처한 화면에서 읽습니다.  
자동 방식은 화면 정보 응답이 늦을 때 같은 실행에서 OCR로 전환할 수 있습니다.

| 입력·상태 | 처리 | 다음 상태 |
| --- | --- | --- |
| 찾을 문구·영역·인식 방식 | 현재 대상 앱을 확인하고 검색 | 일치 위치 또는 글자 대기 |
| 우선 영역 1~6 | 순서대로 확인하고 첫 일치 영역 선택 | 항목 진입 |
| 저장된 매크로와 실행 횟수 | 첫 동작부터 지정 횟수 실행 | 뒤로가기·복귀 |
| 완료 후 쉬는 시간 | 쉬는 동안 재실행하지 않음 | 새로고침·재탐지 |
| 중복 방지 켜짐 | 같은 문구가 안정적으로 사라질 때까지 차단 | 재등장 시 재실행 가능 |

### 입력 대상과 응답 수명

| 구분 | 적용 내용 |
| --- | --- |
| 대상 앱 재확인 | 글자 터치는 탐지 위치와 실제 입력 대상이 같은 앱인지 다시 확인합니다. |
| 오래된 응답 폐기 | 정지나 일시정지 전에 보낸 요청이 나중에 끝나더라도 그 오래된 결과로 입력하지 않습니다. |
| 조회 누적 방지 | 창 응답이 늦으면 새 요청을 계속 쌓지 않고 기존 요청을 기다립니다. |
| 별도 중단 조건 | 사용자가 정한 유한 대기, 잠금 화면, 방향 변경, 연결 종료와 정지는 별도로 유지합니다. |

### 분기·재시도·반복의 역할

| 구분 | 적용 내용 |
| --- | --- |
| 있음·없음 이동 | 조건 분기는 문구가 있을 때와 없을 때 이동할 동작 번호를 각각 정합니다. |
| 되돌아가서 재검색 | 뒤로가기 후 다시 찾기와 스크롤 후 다시 찾기는 정해 둔 횟수와 간격을 따릅니다. |
| 두 반복의 차이 | 개별 동작 반복은 그 동작 하나를 반복하고, 탐지의 15회는 선택한 매크로 전체를 반복합니다. |
| 저장본 적용 | 시각·시간 설정을 바꾼 편집본을 이름 있는 저장본에 다시 저장해야 목록 탐지에서 반영됩니다. |

### 인식 결과의 비교 조건

| 구분 | 적용 내용 |
| --- | --- |
| 유니코드 공백 | 글자 비교는 전각·유니코드·보이지 않는 공백을 공백 무시 옵션에서 처리합니다. |
| 빈 검색어 차단 | 검색어가 공백 제거 뒤 비면 아무 글자와 일치하지 않게 막습니다. |
| 필터·품질 보존 | 포함·일치·정규식과 순번·영역 필터는 유지하고, 화면 해상도나 내장 OCR 모델의 품질을 낮추지 않습니다. |

<a id="reading-level-3"></a>
## LEVEL 3 - Practitioner

## 설정과 저장을 맞춰 적용하기

공용 APK는 ARM64 휴대전화와 x86_64 에뮬레이터용 코드를 함께 포함합니다.  
Android 11 이상에서 기존 앱을 삭제하지 않고 업데이트로 설치합니다.  
기존 ID·서명을 유지하며 16차의 매크로 JSON, 목록 탐지 설정과 테마를 읽습니다.  
별도 AI 시범·행동 모델을 가져오는 기능은 없습니다.

| 설정 | 적용 범위 | 선택 기준 |
| --- | --- | --- |
| 검색 방식 | 각 글자 동작·목록 탐지에서 각각 설정 | 이미지로 그린 게임 문구는 한글 OCR |
| 공백·대소문자·비교 방식 | 현재 글자 조건 | 정확한 문구면 일치, 일부면 포함 |
| 계속 기다리기 | 글자 터치·글자 대기 | 다음 화면이 나올 때까지 기다릴 때 켬 |
| 인식 후 추가 대기 생략 | 완료 후 지연·터치 전 재확인 | 빨라질 수 있지만 화면 변화를 고려 |
| 다음 글자에 맞춰 진행 | 인접한 호환 글자 조건 | 다음 글자의 사전 부재가 확인된 경우 대기 단축 |
| 개별 반복 / 탐지 반복 | 한 동작 / 저장 매크로 전체 | 3회 동작과 전체 15회를 곱하지 않도록 확인 |
| 재시도·뒤로·스크롤 | 글자가 없는 유한 검색 | 횟수와 초를 정하고 종료 정책 확인 |
| 우선 영역·중복·복귀·새로고침 | 목록 탐지 | 동일 문구를 다시 실행할 조건을 정함 |

### 설정을 적용하는 순서

| 구분 | 적용 내용 |
| --- | --- |
| 영역·미리보기 | 처음에는 한 영역에서 인식 미리보기로 확인하고 녹화합니다. |
| 저장·낮은 반복 확인 | 이름으로 저장한 매크로를 선택해 낮은 반복으로 순서를 확인한 뒤 목표 횟수로 적용하세요. |
| 편집본과 저장본 | 수정한 현재 편집본이 탐지용 별도 저장본에 자동 반영되는 것은 아니므로 같은 이름으로 다시 저장해야 합니다. |
| 실행 상태 제어 | 정지·일시정지와 재개, 진행 표시와 오류 기록을 함께 사용합니다. |

### 재현 환경과 자료 경계

| 구분 | 적용 내용 |
| --- | --- |
| 빌드 도구 | 빌드는 JDK 17·Gradle 8.13·SDK 35를 사용하고 기존 개인 서명이 필요합니다. |
| 일반 폴더 사용 | 실제 일반 폴더의 빌드 사본을 사용하며 폴더 연결을 만들지 않습니다. |
| 경로 확인 | 소스의 빌드 안내와 Python 경로 인자를 확인합니다. |
| 비공개 제외 | 개인 키와 실행 원문은 공개·패키지에 넣지 않습니다. |
| 전용 기기 제한 | 기기 검사는 전용 장치 이름·설치 버전·서버를 확인한 도구로 제한합니다. |

## LEVEL 4 - Advanced

## 조회·인식·실행 수명 관리

제품은 16차의 Java View UI와 MacroService 실행기, JSON 모델·저장소, GesturePaths·FloatingController를 기반으로 합니다.  
UI와 리소스를 새 디자인으로 바꾸지 않고 버전 표시만 실제 설치 버전에서 읽습니다.  
시범 학습·행동 모델·ONNX 의존성은 포함하지 않습니다.

| 부분 | 26차 변경 | 유지한 경계 |
| --- | --- | --- |
| TextRules.Prepared | 검색어 정규화·정규식 컴파일을 한 탐지에서 재사용 | 포함·일치·정규식·대소문자 옵션 |
| Unicode 공백 | code point로 공백·ZWS·BOM을 선택 제거 | 공백 무시를 끄면 공백 보존 |
| 창 조회 QueryLane | 진행 중 조회 하나를 기다리고 추가 요청 누적 방지 | 실제 오류를 글자 부재로 바꾸지 않음 |
| 창 응답 시한 | 무한 대기는 계속 대기, 유한 동작의 실제 창 대기만 제한 | 정상 OCR 전체에 절대 시한을 씌우지 않음 |
| 취소·일시정지 | generation·pauseRevision·activeTime 확인 | 이전 응답으로 입력하지 않고 일시정지 시간 제외 |
| R8·리소스 축소 | 미사용 의존성과 리소스 제거 | 자체 앱·공유 프레임워크·OCR 공개 API·반사 대상 보존 |

### 대기·취소의 구현 조건

| 구분 | 적용 내용 |
| --- | --- |
| 유한 조회 상한 | 유한 동작의 창 조회 상한은 max(1500ms, 설정 timeout)이며 빠르게 완료한 정상 응답에는 만료 판단을 적용하지 않습니다. |
| 대기 중 보호 조건 | 대기 중 정지·연결·화면 잠금·방향·전체 실행 시간도 확인합니다. |
| 일시정지 세대 | pauseRevision이 달라지면 이전 응답을 폐기하고 재개 후 새 창을 확인합니다. |
| 취소 불가 조회 | 취소 불가능한 플랫폼 조회가 남아 있어도 큐에 계속 새 요청을 추가하지 않습니다. |

### OCR 보존과 실패 정책

| 구분 | 적용 내용 |
| --- | --- |

## LEVEL 5 - Expert

## 최종 소스·파일·실행 근거 대조

26차는 16차를 구현 기준으로 선택했고 직전 제품과의 전체 비교도 별도로 남깁니다.  
이전 차수의 성능·검사 수를 26차의 결과로 합치지 않습니다.  
16차 선택 소스의 보존 해시, 실제 빌드 사본과 기준 소스의 동일성, 버전·ABI·인증서·ZIP CRC와 내장 OCR 자산을 확인했습니다.

| 근거 | 확인 대상 | 해석의 범위 |
| --- | --- | --- |
| 단위·린트 | 비교 규칙·모델·영역·중복·시간·실행 상태·제품 코드 | 기기 동작 전체의 대체가 아님 |
| 실제 축소 APK 기기 검사 | 오프라인 OCR·영역·대기·지연 복구·반복·UI·제어 | 전용 Android 12 가상 장치 |
| 실제 업데이트 | 16차 설정 저장 → 26차 설치 → 설정 대조 | 앱 ID·개인 서명·저장 구조 유지 |
| 전체 비교·소스 | 추가·수정·삭제, 주석·공백·개발 도구 | 공개 가능한 코드 원문 전체 |
| 바이너리 정보 | 공용 APK 크기·SHA-256·두 ABI·기존 서명 | 크기 감소가 속도·인식률 수치는 아님 |
