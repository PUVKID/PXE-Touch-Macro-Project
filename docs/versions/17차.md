### LEVEL 1 · 이 자료의 목적과 달라진 점


17차는 화면 인식이 잠깐 늦거나 일시 실패할 때 곧바로 전체 실행이 끝나는 경로와 글자 미 발견 뒤의 긴 자동 스크롤을 다룹니다.

대상 창 또는 직접 선택한 화면 정보 읽기가 늦으면 **누르지 않고 하나의 조회를 기다립니다.**

 응답 뒤에는 새 화면으로 확인합니다.

자동 방식의 OCR 전환은 유지하지만 화면 정보 전용을 마음대로 OCR로 바꾸지 않습니다.

끝난 OCR 작업의 일시 사용 불가·시간 만료·취소는 새 화면으로 재시도하며 간격은 0.25초부터 최대 2초입니다. 작업에 쓰던 비트맵(화면 그림)의 수명과 OCR 하나 제한을 유지합니다. 피드백 알림 중단과 실제 접근성 연결 해제는 다릅니다. 이미 전달한 제스처를 자동으로 다시 보내지 않습니다.

**읽지 못함은 글자가 없음이 아닙니다.**

 읽기 실패만으로 뒤로가기·스크롤·중복 잠금 해제를 하지 않습니다.

정상 화면에 글자가 없을 때의 대기·실패 정책, 전체 실행 시간·정지·일시정지는 유지합니다.

권한·보안 캡처·미지원·잘못된 입력·미확정 내부 오류도 따로 봅니다.

자동 스크롤 두 경로의 이동은 이전 절반으로 줄였으며 수동 스와이프는 보존합니다.

### LEVEL 1 · 설정에서 화면 조작까지


매크로는 여러 번할 동작을 순서대로 적어 둔 목록입니다.

입력은 동작·찾을 글자·좌표·검색 영역·반복 설정입니다.

앱 화면인 MainActivity에서 편집하고 Store에 저장한 다음 MacroService가 대상 앱과 글자를 확인하여 Android 접근성 기능으로 손가락 동작에 해당하는 제스처를 전달합니다.

OCR은 화면 그림에서 글자를 읽는 기술이며 이 자료의 기술 분류는 Java·Android 접근성·ML Kit 한국어 OCR입니다.

결과는 실제 터치, 화면 위 제어 창의 상태, JSON 저장 파일, 동작·인식·오류 기록입니다.

JSON은 항목 이름과 값을 짝 지어 저장하는 형식입니다.

예를 들어 찾을 글자와 검색 영역을 지정했다면 먼저 해당 글자를 어디서 어떻게 읽는지 확인해야 합니다.

매크로를 선택하거나 만든 뒤 동작·반복·대기를 검토하고, 글자 인식 방식·영역을 정하고, 대상 앱과 접근성 서비스 연결을 확인한 다음 실행합니다.

화면 위 제어창에서 정지·일시정지와 진행 기록도 확인합니다.

**설정 저장과 실제 화면 조작 성공은 다른 확인 단계**입니다.

### LEVEL 1 · 빌드와 접근성 연결


소스는 앱을 만드는 재료이며 설치 파일인 APK와 다릅니다.

해당 차수의 완전한 Gradle 프로젝트, manifest(앱 구성), 리소스, wrapper JAR, SDK(Android 개발 도구), JDK(Java 개발 도구), 서명 입력이 필요합니다.

정확한 개발 명령과 버전은 해당 소스 README 또는 build.gradle에서 확인합니다.

완전한 프로젝트에서 빌드하고 기기에 설치한 뒤 사용자가 접근성 서비스를 직접 허용합니다.

**공개 코드만으로 APK 생성이나 기존 서명 앱의 업데이트를 보장하지 않습니다.**

 소스 일부나 설정 예제만으로 단독 앱을 만들 수도 없습니다.

### LEVEL 1 · 이어받은 적응 실행·측정·모델


‘다음 글자에 맞춰 진행’은 다음 조건이 준비되면 진행하는 선택이며 **기본 꺼짐**입니다.

켜도 모든 기다림을 없애지 않습니다.

같은 인식 방식·검색 영역의 연속 글자 동작에서 다음 글자가 미리 없었다고 확인한 경우에만 완료 후 대기를 다음 글자를 기다리는 시간으로 옮깁니다.

그 글자가 새로 나타나면 다음 단계로 갑니다.

이미 보이는 글자, 직접 넣은 대기, 반복 간격, 무작위 대기는 원래 의미를 유지하고 기존 프로필 숫자를 일괄 줄이지 않습니다.

누르기 전 재확인도 끄지 않습니다.

바로 다음 개별 글자 터치가 같은 위치라면 글자가 사라졌다 다시 나타나는 것을 확인합니다. 개별 동작의 명시적 반복과 전체 반복 경계의 모든 중복을 막는 설정은 아닙니다. 목록 탐지의 사라짐 확인은 별도입니다.

단계·OCR·캡처·설정 대기의 실제 시간을 구분합니다.

단계 시간 안에 하위 작업이 포함되므로 **네 시간을 더하면 전체 시간이 되지 않습니다.**

 전체 반복을 밖에서 잰 시간과 내부 집계도 다릅니다.

실행 준비 전에 일시정지·정지했을 때 예전 대기열 작업이 측정값을 다시 초기화하지 않도록 실행 세대를 확인합니다.

세대는 어느 실행의 작업인지 구별하는 값입니다.

개별 TEXT_TAP은 제어 창 준비 뒤 대상 앱을 확인하고 전달 직전 관측된 창 변화·일시 정지 세대를 다시 비교합니다. 목록 진입은 기존 대상 확인과 중복 예약 순서를 유지합니다. Android 창 전환과 입력 전달을 한 번에 묶어 모든 경합을 없앤다고 보장하지 않습니다.

홈 입체 모델은 OBJ라는 기하 파일의 실제 224 정점·168 면을 읽어 원 근·깊이·조명을 계산합니다.

상태 변경 때 다시 그리며 상 시 애니메이션이나 예약 렌더 루프는 없습니다.

나눔 고딕 Bold·라이트/다크·기존 제어를 유지합니다.

**15회 120초는 통제 시험 목표**이며 실제 게임·사용자 블루스 택 99% 또는 무오류의 증거가 아닙니다.

실제 실행 범위는 납품 검사 기록에서 확인합니다.
### LEVEL 1 · 당시 검사 수와 적용 한계


검사 수는 당시 정해 둔 환경에서 확인한 항목의 수입니다. ‘기기’ 검사는 Android에서 실행한 점검이고 ‘단위’ 검사는 작은 코드 논리의 점검입니다.

초 단위 두 숫자는 실제 소요와 허용 제한을 구분합니다.

**당시 통과 범위와 지금 모든 환경의 성공은 다릅니다.**

 SHA-256은 파일 식별 값이고 ABI는 실행할 CPU 구조입니다.

당시 구현자와 별도 검증자는 같은 최종 소스/APK로 각각 기기 104개(기본 52·추가 인식 12·적응 25·새 복 구/스크롤 15), 단위 100개를 통과했습니다.

단위 18 클래스·실패/오류/생략 0, 린 트 0입니다.

독립 기기 시간은 기본 335.312초/720초, 추가 인식 51.640초/240초, 적응 91.969초/480초, 복구 55.562초/240초입니다.

소유 Android31·CPU4·RAM2048MiB·1080×2280/420dpi에서 일 시 오류 복구·정지 1초 이내·중복 차단·오래된 목록 좌표 미터치·두 자동 스크롤 경로 절반 이동·수동 스와이프 보존을 확인했습니다.

### LEVEL 1 · 저장 형식과 입력 범위


저장 형식 schema1의 Macro는 이름·시작 번호·전체 반복·반복 간격·시작 지연·최대 시간·동작 목록을 담습니다.

동작은 1~500개이고 시작 번호는 그 목록 안에 있어야합니다.

전체 반복 0~100,000, 간격·시작 지연 0~600,000ms, 최대 시간 0~1,440분을 검사하며 활성 동작마다 Step 검사를 합니다. ms는 1,000분의 1초입니다.

범위에 0이 포함된다는 사실만으로 모든 항목의 0을 같은 뜻으로 읽지는 않습니다.

Step에는 동작 종류·좌표·검색 영역·글자 비교·인식 출처·실패 정책·반복과 대기·분기 번호가 있습니다.

좌표가 화면 비율로 표현된 유한한 수인지, 영역의 왼쪽/오른쪽과 위/아래 순서가 맞는지, 문구가 있는지 확인합니다.

글자 패턴 문법인 정규 식, 앱을 구별하는 패키지 명, 이동·분기 번호도 검사합니다.

**저장값 검사 통과는 접근성 연결이나 OCR 이용 가능성의 보장이 아닙니다.**

### LEVEL 1 · 결과와 오류 확인


‘지금 8회째’와 ‘8회를 끝냈다’는 다릅니다. **현재 회차와 완료 수를 따로 읽으십시오.**  화면을 제대로 읽었지만 글자가 없는 경우와 화면 자체를 읽지 못한 경우도 구분합니다. 정지와 복구 대기는 같은 상태가 아닙니다. 동작·인식·오류 기록에는 실제 화면 글자가 포함될 수 있으므로 공유 전에 내용을 확인합니다.

서비스 연결이 안 되면 기기 접근성 권한과 실제 연결부터 봅니다. 글자를 못 찾으면 인식 방식·검색 영역·접근성 글자·화면 캡처 제한을 확인합니다. 좌표나 반복이 맞지 않으면 화면 방향과 비율 좌표, 개별 동작·전체 매크로·목록 반복을 각각 확인합니다.

### LEVEL 1 · 직전 자료와 전체 변경


전체 비교는 무엇이 추가·수정·삭제됐는지 보여 주는 기록입니다.

아래 ‘+’는 늘어난 행, ‘−’는 없어진 행이며 기능 개수나 성능 점수가 아닙니다.

주석·공백·줄바꿈도 차이에 포함됩니다.

실행 코드처럼 줄로 비교하기 어려운 파일은 크기와 해시로 같은 파일인지 확인합니다.

설명에 없는 과거 차수나 측정 결과를 채워 넣지 않습니다.

### LEVEL 2 · 이 자료의 목적과 달라진 점


복구는 관측의 유효성과 실패 원인에 따라 달라집니다.

대상 창/명시 화면 정보 지연은 단일 조회를 유지한 무터치 대기이고, 완료 후 새 화면을 확인합니다.

AUTO의 기존 OCR 전환과 화면 정보 전용의 의미를 구분합니다.

완료된 OCR의 일시 사용 불가·시간 만료·취소는 0.25초~최대 2초 간격으로 새 관측을 시도하며 비트 맵 수명·단일 Task를 유지합니다.

**관측 실패가 정상 부재의 후속 행동으로 이어지지 않는 것**이 핵심입니다.

오류만으로 뒤로가기·스크롤·중복 해제를 하지 않으며 정상 부재의 대기/정책·전체 시간·정지·일시정지는 그대로입니다.

피드백 중단과 서비스 해제, 권한/보안/미지원/입력/미확정 내부 오류를 구분하고 전달한 입력을 재전송하지 않습니다.

짧아진 자동 스크롤과 수동 스와이프 보존도 서로 다른 변경 범위입니다.

### LEVEL 2 · 설정에서 화면 조작까지


편집·저장·관측·입력·진행 갱신은 서로 다른 단계입니다.

MainActivity의 동작/글자/좌표/영역/반복 설정이 Store를 거쳐 MacroService의 실행 입력이 됩니다.

서비스가 대상 앱과 글자를 확인한 다음 접근성 제스처를 전달하고 상태를 갱신합니다.

Java는 구현 언어, Android 접근성은 입력 전달 경로, ML Kit 한국어 OCR은 화면 글자 인식 구성 요소입니다.

이 연결의 출력은 실제 터치 외에도 플로팅 상태·매크로 JSON·동작/인식/오류 기록입니다.

사용 순서도 의존 관계를 따릅니다. 매크로와 동작·반복·대기를 먼저 고르고 글자 조건의 인식 방식과 검색 영역을 짝지어 지정합니다. 대상 앱·접근성 서비스가 준비된 뒤 실행하며 정지·일시정지와 기록을 확인합니다. 저장한 문구가 있어도 현재 화면과 영역이 맞지 않으면 같은 결과를 기대할 수 없습니다.

### LEVEL 2 · 빌드와 접근성 연결


빌드는 코드 외에 앱 manifest·리소스·wrapper JAR·SDK·JDK·서명 입력이 결합되어야합니다.

Gradle은 이 요소를 묶어 APK를 만드는 도구입니다.

소스의 공개 여부는 기존 앱의 서명과 업데이트 가능 여부를 결정하지 않습니다.

일부 소스/예제와 완전한 배포 프로젝트의 범위를 구분하십시오.

### LEVEL 2 · 이어받은 적응 실행·측정·모델


적응 대기는 고정 대기 전체를 삭제하는 기능이 아니라 다음 조건의 관측과 완료 후 대기의 관계를 바꿉니다.

기본 꺼짐인 옵션을 켜고, 인식 방식·영역이 같은 인접 글자 조건에서 다음 글자의 사전 부재가 확인되어야 대기를 이전합니다.

다음 글자가 새로 보이면 진행합니다.

**이미 존재하는 조건은 새 등장으로 취급하지 않습니다.**

 수동 대기·반복 간격·무작위 대기와 기존 프로필 수치·터치 전 재확인은 유지합니다.

같은 위치의 바로 다음 개별 글자 터치는 부재→재등장 관계를 확인합니다. 개별 반복·전체 반복 경계 전체의 중복 차단과 목록 사라짐 설정은 다른 범위입니다. 단계·OCR·캡처·설정 대기의 시간은 포함 관계가 있어 합산하지 않으며 외부 전체 반복 측정과 내부 집계도 구분합니다.

대기 열 작업과 실행의 연결은 세 대로 관리합니다.

준비보다 먼저 멈춘 실행의 과거 작업이 측정을 다시 초기화하면 안 됩니다.

개별 TEXT_TAP의 제어 창 준비 →대상 확인 →실제 전달 직전 창/일시 정지 세대 대조가 이를 실행 보호와 연결합니다.

목록 진입의 기존 대상 확인·중복 예약 순서는 별도로 유지합니다.

**관측된 변경의 차단과 OS 전체 경합의 원자 차단은 다릅니다.**

OBJ224 정점·168 면은 실제 모델의 기하이며 원근 투영·깊이 정렬·조명으로 표시합니다.

모델 갱신은 상태 변화와 연결되고 상시 애니메이션·예약 루프는 없습니다.

나눔 고딕 Bold와 라이트/다크·제어 흐름을 유지합니다. 15회 120초는 통제 시험 목표이고 실제 실행 범위를 확인해야 합니다.

게임·사용자 블루스 택 99%나 무오류는 이 설계에서 도출되지 않습니다.
### LEVEL 2 · 당시 검사 수와 적용 한계


검증은 기능별 기기 배치와 순수 단위·린트, 패키지/보존의 서로 다른 층으로 나뉩니다. **각 배치의 통과 수와 실행 환경을 함께 읽어야** 결과가 의미를 갖습니다. 시간 제한과 실소요, APK 동일성과 실제 기능 결과는 별도 근거입니다.

당시 구현자와 별도 검증자는 같은 최종 소스/APK로 각각 기기 104개(기본 52·추가 인식 12·적응 25·새 복 구/스크롤 15), 단위 100개를 통과했습니다.

단위 18 클래스·실패/오류/생략 0, 린 트 0입니다.

독립 기기 시간은 기본 335.312초/720초, 추가 인식 51.640초/240초, 적응 91.969초/480초, 복구 55.562초/240초입니다.

소유 Android31·CPU4·RAM2048MiB·1080×2280/420dpi에서 일 시 오류 복구·정지 1초 이내·중복 차단·오래된 목록 좌표 미터치·두 자동 스크롤 경로 절반 이동·수동 스와이프 보존을 확인했습니다.

### LEVEL 2 · 저장 형식과 입력 범위


Macro와 Step은 전체 계획과 개별 동작의 두 입력 계층입니다. schema1 Macro가 이름·시작 번호·전체 반복·간격·시작 지연·최대 시간·동작 배열을 직렬화하고, validate가 1~500개 동작과 배열 안 시작 번호를 확인한 뒤 활성 Step을 검사합니다.

반복 0~100,000, 간격/지연 0~600,000ms, 최대 시간 0~1,440분이 허용 범위입니다.

Step은 종류·좌표·영역·글자 비교·인식 출처·실패 정책·반복/대기·분기를 결합합니다. 유한 비율 좌표, 영역 순서, 문구 존재, 정규 식, 패키지 명과 이동/분기 번호 검증이 잘못된 저장 입력을 거릅니다. 이 계층을 통과해도 기기의 접근성/OCR 조건은 실행 시 별도로 확인해야 합니다.

### LEVEL 2 · 결과와 오류 확인


진행은 현재 회차와 완료 횟수, 관측은 정상 부재와 읽기 실패, 제어는 중지와 복구 대기로 나누어 해석합니다. 이 구분이 없으면 읽기 실패를 정상 조건으로 오해하거나 진행 중인 회차를 완료로 세게 됩니다. 운영 로그가 화면 인식 본문을 담을 수 있으므로 공유 경계도 확인합니다.

오류 지점과 점검 대상을 연결하십시오. 연결 실패는 접근성 권한/실제 서비스, 탐지 실패는 방식/영역/접근성 텍스트/캡처 제한, 좌표·반복 불일치는 화면 방향/비율 좌표/개별·전체·목록 반복입니다. 한 설정만 바꾸어 모든 문제를 해결했다고 판단할 근거는 없습니다.

### LEVEL 2 · 직전 자료와 전체 변경


변경 설명과 파일 비교는 역할이 다릅니다. 설명은 변화의 의미를, 전체 비교는 추가·수정·삭제와 주석·공백·개행까지의 근거를 제공합니다. 행 증감은 구현량이나 품질 지표로 환산할 수 없습니다. 바이너리는 크기·해시를 통해 동일성을 확인하고 실제 이전 자료가 확인된 범위만 연결합니다.

### LEVEL 3 · 이 자료의 목적과 달라진 점


대상 창/명시 화면 정보가 늦을 때 터치 없이 하나의 요청을 기다리고 응답 뒤 새 화면으로 재확인하는지 살펴보십시오.

AUTO OCR 전환과 화면 정보 전용에서 OCR을 임의 호출하지 않는 조건을 구분합니다.

완료된 OCR의 일시 사용 불가·시간 만료·취소는 새 화면 재시도와 0.25초~최대 2초 간격, 단일 Task·비트 맵 수명을 확인합니다.

**읽기 오류만으로 뒤로가기·스크롤·중복 잠금 해제가 생기지 않는지 대조**하고 정상 부재에서는 기존 대기/실패 정책을 확인합니다.

전체 실행 시간·정지·일시정지, 피드백 중단/실제 연결 해제, 권한·보안 캡처·미지원·입력·미확정 오류를 따로 읽습니다.

이미 전달한 제스처의 자동 재전송이 없어야 합니다.

자동 스크롤 두 경로의 절반 이동과 수동 스와이프 보존을 함께 확인하십시오.

### LEVEL 3 · 설정에서 화면 조작까지


실행 전에 매크로를 선택/생성하고 동작 순서, 반복, 대기 값을 확인하십시오. 글자 조건은 검색 방식과 검색 영역을 함께 지정합니다. 대상 앱과 접근성 서비스 연결을 확인한 뒤 실행하고 플로팅 제어의 정지·일시정지·진행 기록을 관찰합니다. 필요한 입력은 동작·화면 글자·좌표·영역·반복 설정입니다.

확인 경로는 MainActivity 편집 →Store 저장 →MacroService의 대상/글자 확인 →캡처·인식·접근성 제스처 →진행 갱신입니다.

Java·Android 접근성·ML Kit 한국어 OCR을 사용하는 이 경로에서 실제 터치뿐 아니라 JSON 저장 내용, 플로팅 상태, 동작/인식/오류 기록을 각각 확인하십시오.

**저장 파일만 확인하고 실행까지 성공했다고 판정하지 않습니다.**

### LEVEL 3 · 빌드와 접근성 연결


같은 차수의 소스 README와 build.gradle에서 SDK·JDK·Gradle·서명 조건을 확인하고 manifest·리소스·wrapper JAR를 포함한 프로젝트를 준비하십시오.

완전한 프로젝트에서 빌드한 APK를 설치한 다음 실제 기기의 접근성 서비스를 직접 허용합니다.

일부 소스나 설정 예제만 있는 묶음은 재빌드 가능한 단독 APK 프로젝트로 취급하지 않습니다.

공개 소스로 기존 개인 서명 앱을 업데이트할 수 있다고 가정하지 마십시오.

### LEVEL 3 · 이어받은 적응 실행·측정·모델


매크로 편집에서 ‘다음 글자에 맞춰 진행’이 기본 꺼짐인지 확인하십시오.

사용할 때는 인접 글자 조건의 인식 방식·영역이 같고 다음 글자의 사전 부재가 확인되는지 대조합니다.

그 경우 완료 후 대기를 다음 조건 대기로 이전하고 새 등장 때 진행합니다.

**기존 프로필 숫자와 터치 전 재확인을 보존**하며 이미 보이는 조건·수동 대기·반복 간격·무작위 대기를 따로 확인합니다.

바로 다음 개별 TEXT_TAP이 같은 위치라면 사라짐과 재등장을 확인하십시오.

명시적 개별 반복·전체 반복 경계 전체를 막는 기능으로 시험하지 않으며 목록 사라짐 확인 설정도 별도로 대조합니다.

실행 전 즉시 정지/일시 정지 후 대기 열 작업이 측정을 초기화하지 않는지, 개별 터치 준비 뒤 대상과 전달 직전 관측된 창·일시 정지 세대를 확인하는지 봅니다.

목록 진입은 기존 순서를 확인합니다.

Android 창 전환과 전 달의 원자성까지 검증한 것은 아닙니다.

단계·OCR·캡처·설정 대기를 각각 기록하되 단계에 하위 작업이 포함되므로 합계로 전체를 만들지 않습니다.

외부 전체 반복 시간과 내부 수치도 구분합니다.

홈 모델은 실제 OBJ224 정점·168 면의 원근·깊이·조명을 표시하고 상태가 변할 때 갱신하는지 확인합니다.

상시 애니메이션·예약 루프가 없는 설계와 나눔 고딕 Bold·라이트/다크·제어를 유지합니다.

**15회 120초 목표와 실제 납품 검사 관측을 대조**하고 게임·사용자 블루스 택 99%/무오류로 확대하지 마십시오.
### LEVEL 3 · 당시 검사 수와 적용 한계


아래 당시 검사 수·환경·소요/제한과 납품 파일을 대조하십시오. **이 문서 작성 중 새 기기 검사를 실행한 결과는 아닙니다.**  검사 기록의 범위를 넘어 게임·휴대폰·장기 성공으로 옮겨 적지 마십시오.

당시 구현자와 별도 검증자는 같은 최종 소스/APK로 각각 기기 104개(기본 52·추가 인식 12·적응 25·새 복 구/스크롤 15), 단위 100개를 통과했습니다.

단위 18 클래스·실패/오류/생략 0, 린 트 0입니다.

독립 기기 시간은 기본 335.312초/720초, 추가 인식 51.640초/240초, 적응 91.969초/480초, 복구 55.562초/240초입니다.

소유 Android31·CPU4·RAM2048MiB·1080×2280/420dpi에서 일 시 오류 복구·정지 1초 이내·중복 차단·오래된 목록 좌표 미터치·두 자동 스크롤 경로 절반 이동·수동 스와이프 보존을 확인했습니다.

### LEVEL 3 · 저장 형식과 입력 범위


저장 JSON의 schema1 과 Macro 필드인 이름·시작 번호·전체 반복·반복 간격·시작 지연·최대 시간·동작 배열을 확인하십시오.

동작 수 1~500개, 배열 안 시작 번호, 활성 Step 검증이 필요합니다.

전체 반복 0~100,000, 간격/시작 지연 0~600,000ms, 최대 시간 0~1,440분을 벗어난 값을 실행용으로 쓰지 않습니다.

개별 Step에서는 종류·좌표·검색 영역·글자 비교·인식 출처·실패 정책·반복·대기·분기 번호를 점검합니다. 비율 좌표의 유한성, 영역 좌우/상하 순서, 문구 존재, 정규 식 문법, 패키지 명, 이동/분기 번호를 확인하고 저장 검증 후에도 실제 접근성 서비스와 OCR 가용성을 별도로 시험하십시오.

### LEVEL 3 · 결과와 오류 확인


결과를 확인할 때 완료 반복 수와 현재 회차를 따로 기록하고, 글자 부재와 화면 읽기 실패, 중지와 복구 대기를 구분하십시오. 운영 로그의 화면 인식 본문을 검토한 뒤 필요한 범위만 공유합니다.

연결 실패 시 접근성 권한과 서비스 연결을 확인합니다. 탐지 실패는 인식 방식·검색 영역·접근성 텍스트·캡처 제한을 대조하십시오. 좌표/반복 불일치는 화면 방향·비율 좌표·개별/전체/목록 반복으로 나눠 확인합니다. 표시된 상태만으로 미실행 범위까지 검사했다고 기록하지 않습니다.

### LEVEL 3 · 직전 자료와 전체 변경


수정 범위를 재확인할 때 아래 전체 비교에서 추가·수정·삭제 파일을 열고 주석·공백·개행까지 대조하십시오. 표시된 행 증감과 바이너리 크기·해시를 보존합니다. 기능 설명만으로 모든 파일 변경을 확인했다고 처리하지 않으며 비교 대상이 없는 자료에 이전 번호를 만들어 넣지 않습니다.

### LEVEL 4 · 이 자료의 목적과 달라진 점


창/명시 노 드 지연은 단일 조회 수 명과 무터치 복구로 제한하며 결과 이후 새 관측을 요구합니다. AUTO의 OCR 전환은 보존하고 명시 화면 정보 정책은 변경하지 않습니다. OCR 재시도는 완료된 Task의 일시 사용 불가·시간 만료·취소에 한하며 0.25초~최대 2초 후퇴, 비트 맵 수명과 단일 OCR을 유지합니다.

**정상 부재와 인프라 실패를 상태 전이에서 분리**하여 오류가 뒤로가기·스크롤·중복 잠금 해제를 유발하지 않게 합니다.

정상 부재 정책·전체 기한·정지·일시정지를 보존하며 피드백 중단/서비스 해제·권한·보안·미지원·잘못된 입력·미확정 내부 오류를 합치지 않습니다.

이미 전달한 제스처 재전송은 하지 않습니다.

자동 스크롤 거리 절반 변경은 두 자동 경로에 한하고 수동 스와이프를 보존하는 영향 경계를 갖습니다.

### LEVEL 4 · 설정에서 화면 조작까지


입력 계약은 매크로 동작·화면 문구·비율 좌표·영역·반복 설정이고 실행 경계는 MainActivity/Store/MacroService로 나뉩니다.

편집과 영속화 후 대상 앱·문구 확인, 캡처/인식, 접근성 제스처, 진행 갱신을 수행합니다.

Android 접근성·Java·ML Kit 한국어 OCR이라는 기술 분류 안에서도 입력 전달과 글자 관측은 별도 책임입니다.

실제 터치·플로 팅 상태·JSON·동작/인식/오류 기록은 각 계층의 출력입니다.

운영 절차는 설정 검토→방식/영역 지정→대상/서비스 확인→실행과 제어 상태 관찰입니다. 정지·일시정지 접근과 진행 기록을 함께 확인해야 합니다. 이 경계를 수정할 때 저장값의 유효성과 런타임 화면 조건을 혼합하면 입력이 유효하다는 이유로 관측 단계를 생략하는 오류를 만들 수 있습니다.

### LEVEL 4 · 빌드와 접근성 연결


재현 단위는 Java 파일 집합이 아니라 같은 차수의 Gradle 프로젝트와 manifest·리소스·wrapper JAR·SDK·JDK·서명 입력입니다.

README/build.gradle이 차수별 도구 조건의 근거입니다.

빌드·설치와 사용자 접근성 허용은 분리되어 있으며 공개 소스는 기존 서명 업데이트의 충분조건이 아닙니다.

일부 소스/설정 예제를 전체 배포 단위로 확장 해석하지 않습니다.

### LEVEL 4 · 이어받은 적응 실행·측정·모델


적응 정책의 전제는 기본 false, 동일 인식 방식·영역, 인접 글자 조건, 다음 글자의 사전 부재입니다. after 대기를 다음 조건의 대기로 이전하고 새 등장에 반응하며 이미 보이는 조건·수동 대기·gap·무작위 대기·기존 프로필 수치·터치 전 재확인을 보존합니다.

**대기 이전의 조건을 약화하면 과거 화면을 새 조건으로 오인할 수 있습니다.**

 바로 다음 개별 글자 터치의 같은 위치에는 부재→재등장 가드가 있지만 모든 개별/전체 반복 경계나 목록 중복 설정을 대체하지 않습니다.

측정은 단계·OCR·캡처·설정 대기이며 포함 관계상 합계가 전체 시간이 아닙니다.

외부 반복 시간과 내부 누적의 측정 범위를 분리합니다.

초기화는 현재 실행 세대를 확인하여 즉시 정지·일시 정지 뒤 큐 작업의 재초기화를 막습니다.

TEXT_TAP은 제어 창 준비 후 대상 확인과 전달 직전 관측 창/일시 정지 세대를 대조합니다.

목록 진입의 대상/중복 예약 순서는 유지하며 Android 창 전환과 입력 전달의 원자성을 보증하지 않습니다.

표현 계층은 OBJ224 정점·168 면의 원근 투영·깊이 정렬·조명과 상태 변경 시 갱신입니다.

상시 애니메이션·예약 렌더 루프를 두지 않는 비용 선택과 나눔 고딕 Bold·라이트/다크·제어 흐름을 유지합니다.

**15회 120초는 수락을 확인할 통제 목표**이고 실제 실행 범위는 납품 검사에 결합해야 합니다.

제품 코드만으로 실제 게임·사용자 블루스 택 99% 또는 무오류를 주장하지 않습니다.
### LEVEL 4 · 당시 검사 수와 적용 한계


아래는 차수 당시의 소스/APK와 환경에 결합된 회귀 근거입니다. 검사 수를 통과 확률로 환산하지 않고 기능 배치·시간 예산·패키지 동일성·이전 파일 보존을 나누어 해석합니다. **검증 경계 밖 환경까지 일반화하지 않습니다.**

당시 구현자와 별도 검증자는 같은 최종 소스/APK로 각각 기기 104개(기본 52·추가 인식 12·적응 25·새 복 구/스크롤 15), 단위 100개를 통과했습니다.

단위 18 클래스·실패/오류/생략 0, 린 트 0입니다.

독립 기기 시간은 기본 335.312초/720초, 추가 인식 51.640초/240초, 적응 91.969초/480초, 복구 55.562초/240초입니다.

소유 Android31·CPU4·RAM2048MiB·1080×2280/420dpi에서 일 시 오류 복구·정지 1초 이내·중복 차단·오래된 목록 좌표 미터치·두 자동 스크롤 경로 절반 이동·수동 스와이프 보존을 확인했습니다.

### LEVEL 4 · 저장 형식과 입력 범위


직렬화 계약은 schema1 Macro의 이름·시작 번호·전체 반복·간격·시작 지연·최대 시간·동작 배열입니다. validate는 동작 수 1~500과 시작 인덱스의 실 배열 범위를 확인하고 활성 Step.validate를 호출합니다.

반복 0~100,000, 간격/지연 0~600,000ms, 최대 시간 0~1,440분이라는 경계를 런 타임 성공 여부와 혼합하지 않습니다.

Step의 종류·좌표·영역·문구 비교·인식 출처·실패 정책·반복/대기·분기 참조를 유지하며 유한 비율 좌표·영역 순서·문구·정규 식·패키지 명·이동/분기 번호를 검사합니다. 정적 저장 계약과 플랫폼 접근성/OCR 가용성을 별도 실패 계층으로 다루는 것이 확장 시 보존할 경계입니다.

### LEVEL 4 · 결과와 오류 확인


결과 모델에서 진행(현재/완료), 관측(부재/읽기 실패), 제어(정지/복구 대기)는 별도 축입니다. 이들을 합치는 변경은 완료 집계나 실패 정책을 왜곡할 수 있습니다. 운영 로그에 화면 인식 원문이 포함될 수 있으므로 공개 데이터와 분리합니다.

진단 경계는 접근성 권한/서비스 연결, 방식/검색 영역/접근성 텍스트/캡처 제한, 방향/비율 좌표/개별·전체·목록 반복으로 나뉩니다. 증상을 다른 계층의 성공으로 상쇄하지 않고 해당 계층의 조건을 확인해야 합니다.

### LEVEL 4 · 직전 자료와 전체 변경


전체 비교는 소스·설정·문서의 변경 추적 단위입니다. 추가/수정/삭제와 주석·공백·개행을 포함하고 바이너리는 크기/해시로 보존합니다. 행 증감은 의미상 변경과 일대일 대응하지 않으므로 기능 해석과 분리합니다. 확인된 이전 자료만 비교 기준으로 삼고 자료 공백을 추정으로 메우지 않습니다.

<a name="-핵심-기능과-보존-범위"></a>
## 핵심 기능과 보존 범위


**항목:** 1

**이 차수에서 확인할 내용:** 화면 인식이 잠깐 늦거나 일시 오류가 발생했을 때 실행 전체가 끝나는 경로를 고치고, 글자를 찾지 못한 뒤의 자동 스크롤을 짧게 만들었습니다.

**항목:** 2

**이 차수에서 확인할 내용:** 대상 창 조회와 명시적으로 선택한 화면 정보 읽기가 늦으면 터치하지 않고 응답을 기다립니다. 한 번에 하나의 조회만 유지하고 응답이 돌아온 뒤 새 화면으로 다시 확인합니다. 자동 인식의 기존 OCR 전환은 유지하며 화면 정보 전용 동작을 임의로 OCR로 바꾸지 않습니다.

**항목:** 3

**이 차수에서 확인할 내용:** 완료된 OCR 작업의 일시 사용 불가·시간 만료·취소는 새 화면으로 재시도합니다.

재시도 간격은 0.25초부터 최대 2초이며, 이전 작업의 비트 맵 수명과 단일 OCR 작업 제한을 유지합니다.

피드백 알림 중단과 실제 접근성 서비스 연결 해제를 구분하고, 이미 전달한 제스처를 자동으로 다시 실행하지 않습니다.

**항목:** 4

**이 차수에서 확인할 내용:** 읽기 실패를 글자 부재로 계산하지 않으므로 오류만으로 뒤로가기·스크롤·중복 잠금 해제가 일어나지 않습니다.

정상적으로 읽은 화면에 글자가 없는 경우의 기존 대기와 실패 정책, 사용자가 지정한 전체 실행 시간, 정지와 일시정지는 유지합니다.

권한·보안 캡처·미지원·잘못된 입력과 확인되지 않은 내부 오류는 구분합니다.

## 설치 환경과 실행·사용법


해당 차수 Gradle 프로젝트의 manifest·리소스·SDK·JDK와 서명 입력을 준비합니다. 실제 기기의 접근성 서비스는 사용자가 직접 허용합니다. 공개 소스만으로 기존 서명 앱의 업데이트가 가능한 것은 아닙니다.

### 이 차수 원래 안내의 세부 조건


### 실제 검사와 한계


구현자와 별도 검증자가 동일한 최종 소스와 APK로 각각 기기 104개(기본 52·추가 인식 12·적응 25·새 복 구/스크롤 15), 단위 100개를 통과했습니다.

단위 검사는 18 클래스·실패/오류/생략 0이고 린트 문제는 0개입니다.

독립 기기 검사 시간은 기본 335.312초/720초, 추가 인식 51.640초/240초, 적응 91.969초/480초, 복구 55.562초/240초입니다.

소유 Android31 기기(CPU4·RAM2048MiB·1080×2280/420dpi)에서 일 시 오류 복구·정지 1초 이내·중복 차단·오래된 목록 좌표 미터치·자동 스크롤 두 경로의 절반 이동·수동 스와이프 보존을 확인했습니다.

검사 기기에 실제 설치된 PC APK를 다시 읽어 납품 PC APK와 SHA-256이 같음을 확인했습니다.

### 적응 실행과 실제 입체 모델


매크로 설정의 **다음 글자에 맞춰 진행**은 기본 꺼짐입니다.

켜면 같은 인식 방식과 영역의 연속 글자 동작에서 다음 글자의 사전 부재를 확인한 경우, 완료 후 대기를 다음 조건 대기로 바꿔 새 글자가 보이면 진행합니다.

이미 보이는 조건·수동 대기·반복 간격·무작위 대기는 유지합니다.

바로 다음 글자 터치가 같은 위치를 가리키면 사라짐과 재등장을 확인합니다.

개별 동작의 명시적 반복이나 전체 반복 경계를 모두 차단하는 기능은 아닙니다.

목록 탐지의 기존 사라짐 확인 설정은 별도로 유지합니다.

기존 프로필의 숫자를 일괄 축소하거나 터치 전 재확인을 끄지 않습니다.

실행 측정은 단계·OCR·캡처·설정 대기의 실제 시간을 구분합니다. 단계 시간에는 하위 작업이 포함되므로 네 값을 더한 숫자를 전체 시간으로 사용하지 않습니다. 전체 반복의 외부 측정과 내부 집계를 구분합니다.

실행 준비보다 먼저 일시정지하거나 정지해도 이전 대기열 작업이 측정값을 다시 초기화하지 않도록 실행 세대를 확인합니다.

개별 글자 터치는 제어창 준비 뒤에 대상을 확인하고, 실제 전달 직전에 관측된 창 변경과 일시정지 세대를 다시 대조합니다.

이 추가 전달 검사는 개별 `TEXT_TAP` 경로에 적용합니다.

목록 진입 터치는 기존의 대상 확인과 중복 예약 순서를 유지합니다.

홈의 PXE 모델은 실제 OBJ 224 정점·168 면을 읽어 원근 투영·깊이 정렬·조명으로 그립니다. 상태가 바뀔 때 갱신하며 상시 애니메이션·예약 렌더 루프는 없습니다. 나눔 고딕 Bold와 기존 라이트/다크·제어 흐름을 유지합니다.

15회 120초는 통제 시험에서 측정할 목표입니다. 실제 게임·사용자 블루스 택의 성공률 99% 또는 무오류를 코드만으로 보장하지 않습니다. 납품 검사 결과에 실제 실행 범위를 기록합니다.

### 매크로 저장과 실행 입력 검증


`Macro`는 schema1의 JSON으로 이름·시작 번호·전체 반복·반복 간격·시작 지연·최대 시간·동작 배열을 직렬화합니다. `validate`는 동작 1~500개, 시작 번호가 실제 배열 범위 안인지 검사하고 활성 동작에 `Step.validate`를 적용합니다.

전체 반복은 0~100,000, 간격·시작 지연은 0~600,000ms, 최대 시간은 0~1,440분 범위입니다.

`Step`은 동작 종류·좌표·검색 영역·글자 비교·인식 출처·실패 정책·반복과 대기·분기 번호를 저장합니다.

입력 검증은 화면 비율 좌표와 유한 값, 검색 영역의 좌우/상하 순서, 문구 존재, 정규 식 문법, 앱 패키지 명과 이동/분기 번호를 함께 확인합니다.

저장 JSON의 schema 통과와 실제 장치의 접근성/OCR 가용성은 별도 조건입니다.
