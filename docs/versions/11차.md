### LEVEL 1 · 실제 동작을 따라 읽기

창 이벤트 기반 앱 확인과 AUTO 읽기 전환을 정리했습니다.

대상 앱 확인과 화면 읽기 요청을 제어하며 AUTO에서 접근성 읽기가 지연되면 OCR로 전환하는 경로를 보강합니다. 순수 모델 회귀·UTF-8·기기 검사 도구도 보관합니다.

MainActivity와 접근성 MacroService가 앱 진입·실행을 나눕니다. 원래 Gradle 프로젝트의 manifest·리소스·wrapper JAR·SDK·서명 입력을 함께 준비해야 하며 공개 코드만으로 설치 APK가 만들어진다고 보장하지 않습니다. 실제 기기 접근성 설정은 사용자가 직접 허용해야 합니다.

코드/의 차수 밖 NEX 자료와 실행점검/2차는 별도로 안내합니다. 실행점검/2차는 제품 앱의 2차가 아닙니다.

OCR은 그림에 있는 글자를 텍스트로 읽는 처리입니다. APK는 안드로이드 기기에 설치하는 앱 패키지입니다. 접근성 서비스는 기기의 별도 허용을 받아 화면 조작을 수행하는 안드로이드 기능입니다.

입력 — 매크로 동작·화면 글자·좌표·영역·반복 설정

처리 — 편집·저장 → 대상 앱/글자 확인 → 접근성 제스처 → 진행 갱신

출력 — 터치·플로팅 상태·매크로 JSON·동작/인식/오류 기록

### LEVEL 1 · 준비하고 확인할 것

해당 차수 Gradle 프로젝트의 manifest·리소스·SDK·JDK와 서명 입력을 준비합니다. 실제 기기의 접근성 서비스는 사용자가 직접 허용합니다. 공개 소스만으로 기존 서명 앱의 업데이트가 가능한 것은 아닙니다.

같은 차수의 완전한 프로젝트에서 빌드하고 기기에 설치한 뒤 접근성 서비스를 연결합니다. SDK·Gradle·서명과 차수별 개발 명령은 소스 README 또는 build.gradle을 확인합니다. 소스 일부나 설정 예제만 있는 묶음은 단독 APK가 아닙니다.

#### LEVEL 1 · 매크로 저장과 실행 입력 검증

`Macro`는 schema1의 JSON으로 이름·시작 번호·전체 반복·반복 간격·시작 지연·최대 시간·동작 배열을 직렬화합니다. `validate`는 동작1~500개, 시작 번호가 실제 배열 범위 안인지 검사하고 활성 동작에 `Step.validate`를 적용합니다. 전체 반복은0~100,000, 간격·시작 지연은0~600,000ms, 최대 시간은0~1,440분 범위입니다.

`Step`은 동작 종류·좌표·검색영역·글자 비교·인식 출처·실패 정책·반복과 대기·분기 번호를 저장합니다. 입력 검증은 화면 비율 좌표와 유한값, 검색 영역의 좌우/상하 순서, 문구 존재, 정규식 문법, 앱 패키지명과 이동/분기 번호를 함께 확인합니다. 저장 JSON의 schema 통과와 실제 장치의 접근성/OCR 가용성은 별도 조건입니다.

1. 매크로를 선택하거나 만들고 각 동작·반복·대기를 확인합니다.
2. 글자 조건은 인식 방식과 검색 영역을 같이 지정합니다.
3. 대상 앱과 접근성 서비스 상태를 확인한 뒤 실행합니다.
4. 플로팅 제어의 정지·일시정지와 진행 기록을 확인합니다.

`Macro`는 schema1의 JSON으로 이름·시작 번호·전체 반복·반복 간격·시작 지연·최대 시간·동작 배열을 직렬화합니다. `validate`는 동작1~500개, 시작 번호가 실제 배열 범위 안인지 검사하고 활성 동작에 `Step.validate`를 적용합니다. 전체 반복은0~100,000, 간격·시작 지연은0~600,000ms, 최대 시간은0~1,440분 범위입니다.

`Step`은 동작 종류·좌표·검색영역·글자 비교·인식 출처·실패 정책·반복과 대기·분기 번호를 저장합니다. 입력 검증은 화면 비율 좌표와 유한값, 검색 영역의 좌우/상하 순서, 문구 존재, 정규식 문법, 앱 패키지명과 이동/분기 번호를 함께 확인합니다. 저장 JSON의 schema 통과와 실제 장치의 접근성/OCR 가용성은 별도 조건입니다.

## 설치 환경과 실행·사용법

해당 차수 Gradle 프로젝트의 manifest·리소스·SDK·JDK와 서명 입력을 준비합니다. 실제 기기의 접근성 서비스는 사용자가 직접 허용합니다. 공개 소스만으로 기존 서명 앱의 업데이트가 가능한 것은 아닙니다.

같은 차수의 완전한 프로젝트에서 빌드하고 기기에 설치한 뒤 접근성 서비스를 연결합니다. SDK·Gradle·서명과 차수별 개발 명령은 소스 README 또는 build.gradle을 확인합니다. 소스 일부나 설정 예제만 있는 묶음은 단독 APK가 아닙니다.

<a name="-실행-경로와-제약"></a>
### 실행 경로와 제약

MainActivity와 접근성 MacroService가 앱 진입·실행을 나눕니다. 원래 Gradle 프로젝트의 manifest·리소스·wrapper JAR·SDK·서명 입력을 함께 준비해야 하며 공개 코드만으로 설치 APK가 만들어진다고 보장하지 않습니다. 실제 기기 접근성 설정은 사용자가 직접 허용해야 합니다. 

코드/의 차수 밖 NEX 자료와 실행점검/2차는 별도로 안내합니다. 실행점검/2차는 제품 앱의 2차가 아닙니다. 


[공개 파일 전체 비교·공백·주석·크기·해시](../revision-audit/11%EC%B0%A8.md)

### 매크로 저장과 실행 입력 검증

`Macro`는 schema1의 JSON으로 이름·시작 번호·전체 반복·반복 간격·시작 지연·최대 시간·동작 배열을 직렬화합니다. `validate`는 동작1~500개, 시작 번호가 실제 배열 범위 안인지 검사하고 활성 동작에 `Step.validate`를 적용합니다. 전체 반복은0~100,000, 간격·시작 지연은0~600,000ms, 최대 시간은0~1,440분 범위입니다.

`Step`은 동작 종류·좌표·검색영역·글자 비교·인식 출처·실패 정책·반복과 대기·분기 번호를 저장합니다. 입력 검증은 화면 비율 좌표와 유한값, 검색 영역의 좌우/상하 순서, 문구 존재, 정규식 문법, 앱 패키지명과 이동/분기 번호를 함께 확인합니다. 저장 JSON의 schema 통과와 실제 장치의 접근성/OCR 가용성은 별도 조건입니다.
