# 21차·진입 글자 확인과 새 글자로 시작

목록 글자를 눌러 들어간 화면에서 확인 글자를 읽고 매크로 실행 여부를 결정하도록했습니다. 확인 글자가 없거나 설정한 다른 글자가 보이면 뒤로 가서 1 순위부터 다시 찾습니다.

일시정지·계속 실행을 명확하게 표시하고, 실행 중 글자를 바꾸어 시작하면 새 설정으로 처음부터 실행합니다.

**기술 분류:** Android 접근성 · Java · ML Kit 한국어 OCR

### LEVEL 1 · 이 자료의 목적과 달라진 점


21차는 목록에서 글자를 눌러 들어간 뒤 **정말 원하는 화면인지 한 번 더 확인**하는 버전입니다.

진입 화면 확인은 기본 꺼짐입니다.

목록의 글자만 같아도 들어간 화면이 다를 수 있으므로, 확인 글자가 보일 때만 매크로를 실행하도록 설정할 수 있습니다.

정해진 시간 동안 없거나 사용자가 적은 ‘되돌아갈 글자’가 보이면 뒤로 가서 1 순위부터 찾습니다.

두 글자가 함께 보이면 되돌아갈 글자를 우선 합니다.

잘못 들어간 항목은 완료 횟수나 정상 완료 후 쉬는 시간에 넣지 않습니다.

일시정지 뒤 ‘계속 실행’은 멈춘 위치를 유지합니다. 반면 실행 중 찾을 글자를 바꾸고 ‘시작’을 누르면 새 설정으로 처음부터 시작합니다. 이전 화면 읽기가 늦게 끝나도 새 실행을 덮지 않도록 실행별 번호를 구분했습니다. 기존 녹화·반복·새로고침·중복 방지·대상 앱 보호는 유지합니다.

기존 차수도 보존합니다.

### LEVEL 1 · 설정에서 화면 조작까지


21차의 구체적인 준비 순서는 같은 앱 ID·서명의 21차를 기존 앱 위에 설치해 저장 매크로를 유지하고, 목록 글자·1~6 순위 영역·실행 매크로·반복 횟수를 정하는 것입니다.

홈의 진입 화면 확인에서 확인 글자·확인 시간·필요한 확인 영역을 지정한 뒤 선택적으로 되돌아갈 글자를 넣습니다.

앱 ID는 앱을 구별하는 이름, 서명은 업데이트할 앱이 같은 배포 주체의 것인지 확인하는 정보입니다.

확인 글자와 복귀 글자의 우선순위, 일시 정지 후 이어 가기와 새 글자로 시작하기는 앞의 설명대로 구분합니다.

매크로는 여러 번할 동작을 순서대로 적어 둔 목록입니다.

입력은 동작·찾을 글자·좌표·검색 영역·반복 설정입니다.

앱 화면인 MainActivity에서 편집하고 Store에 저장한 다음 MacroService가 대상 앱과 글자를 확인하여 Android 접근성 기능으로 손가락 동작에 해당하는 제스처를 전달합니다.

OCR은 화면 그림에서 글자를 읽는 기술이며 이 자료의 기술 분류는 Java·Android 접근성·ML Kit 한국어 OCR입니다.

결과는 실제 터치, 화면 위 제어 창의 상태, JSON 저장 파일, 동작·인식·오류 기록입니다.

JSON은 항목 이름과 값을 짝 지어 저장하는 형식입니다.

예를 들어 찾을 글자와 검색 영역을 지정했다면 먼저 해당 글자를 어디서 어떻게 읽는지 확인해야 합니다.

매크로를 선택하거나 만든 뒤 동작·반복·대기를 검토하고, 글자 인식 방식·영역을 정하고, 대상 앱과 접근성 서비스 연결을 확인한 다음 실행합니다.

화면 위 제어창에서 정지·일시정지와 진행 기록도 확인합니다.

설정 저장과 실제 화면 조작 성공은 다른 확인 단계입니다.

### LEVEL 1 · 빌드와 접근성 연결


소스는 앱을 만드는 재료이며 설치 파일인 APK와 다릅니다.

해당 차수의 완전한 Gradle 프로젝트, manifest(앱 구성), 리소스, wrapper JAR, SDK(Android 개발 도구), JDK(Java 개발 도구), 서명 입력이 필요합니다.

정확한 개발 명령과 버전은 해당 소스 README 또는 build.gradle에서 확인합니다.

완전한 프로젝트에서 빌드하고 기기에 설치한 뒤 사용자가 접근성 서비스를 직접 허용합니다.

공개 코드만으로 APK 생성이나 기존 서명 앱의 업데이트를 **보장하지 않습니다**.

 소스 일부나 설정 예제만으로 단독 앱을 만들 수도 없습니다.

### LEVEL 1 · 화면과 집중 검사 범위


화면을 새로 배치하는 대신 기존 Android 화면을 유지하면서 검정·흰색 바탕과 파란 포인트 색으로 정돈했습니다.

아래의 4 탭, 작은 진행 창, 실제 입체 OBJ 모델, 나눔고딕 Bold700도 그대로입니다.

라이트·다크와 폭 320dp의 작은 화면을 확인하는 범위이며 긴 설정과 하단 조작은 스크롤해 접근합니다. dp는 Android에서 화면 크기 차이를 고려하는 표시 단위입니다.

새 이미지 시안 제작과 전면 재배치는 취소된 요청입니다.

[진입 검사 계획](../../21차/source/tools/entry-check-plan.json)은 기본 23개와 작은 화면 5개로 구성됩니다.

OCR이나 캡처 복구가 오래 걸렸다면 **정상 화면을 다시 읽은 시점부터 확인 시간**을 보장합니다.

실제 키보드를 연 상태에서도 새 설정 창의 저장·취소에 접근하도록 조정했습니다.

여러 번 뒤로 가던 중 일시 정지해도 이미 돌아간 횟수를 잊지 않으며 연결 해제 직후 남은 정지 버튼도 처리합니다.

기존 기기 회귀 120개의 검사와 시간 상한은 유지합니다.

여기서 계획 수를 새 통과 수로 바꾸어 적지는 않습니다. 24 시간·장기 시험과 선택 성능 비교는 실행하지 않았습니다.

### LEVEL 1 · 이어받은 적응 대기와 입체 표시


‘다음 글자에 맞춰 진행’은 기본 꺼짐입니다.

같은 인식 방식과 영역을 쓰는 연속 글자 동작에서 다음 글자가 미리 없었던 경우에만, 완료 후 쉬는 시간을 다음 글자 기다림에 쓰고 글자가 나타나면 진행합니다.

이미 보이는 조건·수동 대기·반복 간격·무작위 대기는 바꾸지 않습니다.

바로 다음 터치가 같은 위치면 글자가 사라졌다 다시 나타나는지 확인하지만, 모든 개별 반복·전체 반복의 중복을 막는 기능은 아닙니다.

목록 탐지의 사라짐 확인은 별도이고 기존 프로필 숫자를 줄이거나 터치 전 재확인을 끄지 않습니다.

단계 시간 안에는 OCR·캡처·설정 대기가 들어갈 수 있으므로 네 시간을 더하면 같은 시간을 두 번 셉니다.

전체 반복을 밖에서 잰 시간과 앱 내부 집계도 구별합니다.

실행 준비 전에 정지/일시정지하면 이전 대기열이 측정을 다시 초기화하지 않도록 실행 번호를 확인합니다.

개별 글자 터치(TEXT_TAP)는 제어창 준비 뒤 대상을 확인하고 전달 직전에 창 변화·일시정지 번호를 다시 봅니다.

목록 진입은 기존 대상 확인·중복 예약 순서를 유지합니다.

OBJ 모델은 입체 도형의 점 224개와 면 168개를 읽고 원근·앞뒤 순서·조명을 계산해 그립니다.

상태가 바뀔 때 갱신하며 상시 애니메이션/예약 렌더 루프는 없습니다.

라이트/다크·Bold 글꼴·제어는 유지합니다.

**15회 120초는 통제 시험 목표**이며 실제 게임이나 사용자 블루스택의 99% 성공·무오류 결과가 아닙니다.

### LEVEL 1 · 저장 형식과 입력 범위


저장 형식 schema1의 Macro는 이름·시작 번호·전체 반복·반복 간격·시작 지연·최대 시간·동작 목록을 담습니다.

동작은 1~500개이고 시작 번호는 그 목록 안에 있어야합니다.

전체 반복 0~100,000, 간격·시작 지연 0~600,000ms, 최대 시간 0~1,440분을 검사하며 활성 동작마다 Step 검사를 합니다. ms는 1,000분의 1초입니다.

범위에 0이 포함된다는 사실만으로 모든 항목의 0을 같은 뜻으로 읽지는 않습니다.

Step에는 동작 종류·좌표·검색 영역·글자 비교·인식 출처·실패 정책·반복과 대기·분기 번호가 있습니다.

좌표가 화면 비율로 표현된 유한한 수인지, 영역의 왼쪽/오른쪽과 위/아래 순서가 맞는지, 문구가 있는지 확인합니다.

글자 패턴 문법인 정규식, 앱을 구별하는 패키지 명, 이동·분기 번호도 검사합니다.

저장값 검사 통과는 접근성 연결이나 OCR 이용 가능성의 보장이 아닙니다.

### LEVEL 1 · 결과와 오류 확인


‘지금 8회째’와 ‘8회를 끝냈다’는 다릅니다. 현재 회차와 완료 수를 따로 읽으십시오.  화면을 제대로 읽었지만 글자가 없는 경우와 화면 자체를 읽지 못한 경우도 구분합니다. 정지와 복구 대기는 같은 상태가 아닙니다. 동작·인식·오류 기록에는 실제 화면 글자가 포함될 수 있으므로 공유 전에 내용을 확인합니다.

서비스 연결이 안 되면 기기 접근성 권한과 실제 연결부터 봅니다. 글자를 못 찾으면 인식 방식·검색 영역·접근성 글자·화면 캡처 제한을 확인합니다. 좌표나 반복이 맞지 않으면 화면 방향과 비율 좌표, 개별 동작·전체 매크로·목록 반복을 각각 확인합니다.

### LEVEL 1 · 직전 자료와 전체 변경


전체 비교는 무엇이 추가·수정·삭제됐는지 보여 주는 기록입니다.

아래 ‘+’는 늘어난 행, ‘−’는 없어진 행이며 기능 개수나 성능 점수가 아닙니다.

주석·공백·줄바꿈도 차이에 포함됩니다.

실행 코드처럼 줄로 비교하기 어려운 파일은 크기와 해시로 같은 파일인지 확인합니다.

설명에 없는 과거 차수나 측정 결과를 채워 넣지 않습니다.

### LEVEL 2 · 이 자료의 목적과 달라진 점


목록 탐지와 진입 후 확인은 서로 다른 조건입니다.

목록에서 후보를 선택한 뒤 확인 글자를 읽어 실행 여부를 결정합니다.

**기본 꺼짐**인 진입 확인을 켜면 확인 글자 존재가 매크로 시작 조건이 되고, 유한 시간의 부재나 선택한 되돌아갈 글자가 복귀 조건이 됩니다.

두 조건이 동시에 보일 때는 **복귀 글자가 우선**합니다.

잘못 진입한 항목은 정상 완료 집계·완료 후 대기에 연결하지 않습니다.

실행 제어는 계속 실행과 새 시작으로 나뉩니다. 일시정지는 현재 위치를 보존하고, 실행 중 문구 변경 후 시작은 새 설정의 처음으로 전환합니다. 이때 이전 OCR·창 조회·정리 처리가 뒤늦게 끝나도 새 상태를 덮지 않도록 실행 세대로 분리합니다. 녹화·반복·갱신·중복 방지·대상 보호는 이 전환과 함께 유지됩니다.


### LEVEL 2 · 설정에서 화면 조작까지


저장 매크로를 유지하는 설치 경로는 같은 앱 ID·서명의 21차를 기존 앱 위에 설치하는 방식입니다.

목록 글자·1~6 순위 영역·실행 매크로·반복 횟수를 먼저 정하고, 홈의 진입 화면 확인에서 확인 글자·시간·필요한 영역과 선택적 복귀 글자를 지정합니다.

목록에서 찾는 조건과 들어간 뒤 확인하는 조건을 나누어 설정해야 두 단계의 역할을 구분할 수 있습니다.

실제 확인·복귀·새 시작은 위에서 설명한 조건과 실행 세대에 연결됩니다.

편집·저장·관측·입력·진행 갱신은 서로 다른 단계입니다.

MainActivity의 동작/글자/좌표/영역/반복 설정이 Store를 거쳐 MacroService의 실행 입력이 됩니다.

서비스가 대상 앱과 글자를 확인한 다음 접근성 제스처를 전달하고 상태를 갱신합니다.

Java는 구현 언어, Android 접근성은 입력 전달 경로, ML Kit 한국어 OCR은 화면 글자 인식 구성 요소입니다.

이 연결의 출력은 실제 터치 외에도 플로팅 상태·매크로 JSON·동작/인식/오류 기록입니다.

사용 순서도 의존 관계를 따릅니다. 매크로와 동작·반복·대기를 먼저 고르고 글자 조건의 인식 방식과 검색 영역을 짝지어 지정합니다. 대상 앱·접근성 서비스가 준비된 뒤 실행하며 정지·일시정지와 기록을 확인합니다. 저장한 문구가 있어도 현재 화면과 영역이 맞지 않으면 같은 결과를 기대할 수 없습니다.

### LEVEL 2 · 화면과 집중 검사 범위


흑백·파란색 팔레트는 기존 네이티브 화면 구성 위에 적용합니다. 4 탭·OBJ 모델·작은 진행 창·나눔고딕 Bold700을 유지하면서 공통 색·선·조작 영역을 정리했습니다.

라이트/다크와 320dp 조건을 구분하고 하단 동작·긴 설정은 스크롤 접근을 사용합니다.

취소된 새 이미지 시안/전면 재배치를 구현 성과에 포함하지 않습니다.

진입 확인의 시간은 정상 관측과 연결됩니다.

긴 OCR·캡처 복구가 확인 시간을 소모한 것으로 끝나지 않도록 정상 프레임을 읽은 뒤 확인 시간을 보장합니다.

키보드가 열린 설정창의 저장/취소, 연속 복귀 중 일시정지 후 남은 복귀 횟수, 연결 해제 뒤 잔류 정지 버튼도 상태 경계의 일부입니다. [집중 계획](../../21차/source/tools/entry-check-plan.json)은 기본 23 +작은 화면 5이며 기존 기기 회귀 120개와 상한은 보존합니다.

이 숫자는 각 계획의 범위이고 24 시간·장기 시험·선택 성능 비교를 실행했다는 뜻은 아닙니다.

### LEVEL 2 · 이어받은 적응 대기와 입체 표시


적응 대기는 다음 조건의 사전 부재를 전제로 합니다.

기본 꺼짐 옵션을 켜고 같은 방식/영역의 연속 글자 동작을 사용할 때 완료 후 대기를 다음 조건 대기로 옮깁니다.

이미 보인 조건·수동 WAIT·반복 간격·무작위 대기는 유지합니다.

같은 위치의 다음 글자 터치는 부재→재등장을 확인하지만 모든 명시 반복/전체 반복을 차단하지는 않습니다.

목록 사라짐 설정·프로필 숫자·터치 전 재확인은 별도로 보존합니다.

측정의 계층도 분리합니다.

단계에는 OCR·캡처·설정 대기가 포함되어 합산하면 중복이며 외부 반복 시간과 내부 집계도 다릅니다.

준비 이전 정지/일시 정지와 이전 큐 작업을 실행 세대로 구별해 재초기화를 막습니다.

TEXT_TAP의 제어 창 준비 후 대상 확인과 전달 직전 창/일시 정지 세대 확인은 목록 진입의 기존 대상 확인/중복 예약 순서와 범위가 다릅니다.

홈의 OBJ 224 정점·168 면은 원근 투영·깊이 정렬·조명을 통해 표시하고 상태 변경으로 갱신합니다. 상시 애니메이션·예약 렌더 루프는 없으며 기존 라이트/다크·Bold·제어를 유지합니다. 15회 120초라는 목표와 이 표시 구조를 게임 99% 성공이나 무오류 실 측으로 연결할 수는 없습니다.

### LEVEL 2 · 저장 형식과 입력 범위


Macro와 Step은 전체 계획과 개별 동작의 두 입력 계층입니다. schema1 Macro가 이름·시작 번호·전체 반복·간격·시작 지연·최대 시간·동작 배열을 직렬화하고, validate가 1~500개 동작과 배열 안 시작 번호를 확인한 뒤 활성 Step을 검사합니다.

반복 0~100,000, 간격/지연 0~600,000ms, 최대 시간 0~1,440분이 허용 범위입니다.

Step은 종류·좌표·영역·글자 비교·인식 출처·실패 정책·반복/대기·분기를 결합합니다. 유한 비율 좌표, 영역 순서, 문구 존재, 정규식, 패키지 명과 이동/분기 번호 검증이 잘못된 저장 입력을 거릅니다. 이 계층을 통과해도 기기의 접근성/OCR 조건은 실행 시 별도로 확인해야 합니다.

### LEVEL 2 · 결과와 오류 확인


진행은 현재 회차와 완료 횟수, 관측은 정상 부재와 읽기 실패, 제어는 중지와 복구 대기로 나누어 해석합니다. 이 구분이 없으면 읽기 실패를 정상 조건으로 오해하거나 진행 중인 회차를 완료로 세게 됩니다. 운영 로그가 화면 인식 본문을 담을 수 있으므로 공유 경계도 확인합니다.

오류 지점과 점검 대상을 연결하십시오. 연결 실패는 접근성 권한/실제 서비스, 탐지 실패는 방식/영역/접근성 텍스트/캡처 제한, 좌표·반복 불일치는 화면 방향/비율 좌표/개별·전체·목록 반복입니다. 한 설정만 바꾸어 모든 문제를 해결했다고 판단할 근거는 없습니다.

### LEVEL 2 · 직전 자료와 전체 변경


변경 설명과 파일 비교는 역할이 다릅니다. 설명은 변화의 의미를, 전체 비교는 추가·수정·삭제와 주석·공백·개행까지의 근거를 제공합니다. 행 증감은 구현량이나 품질 지표로 환산할 수 없습니다. 바이너리는 크기·해시를 통해 동일성을 확인하고 실제 이전 자료가 확인된 범위만 연결합니다.

### LEVEL 3 · 이 자료의 목적과 달라진 점


같은 앱 ID·서명의 21차를 기존 앱 위에 설치하여 저장 매크로를 유지하는 경로를 사용합니다.

잘못 진입한 항목의 완료 수와 완료 후 대기는 늘리지 않습니다.

 일시정지/계속 실행은 현재 위치 유지, 문구 변경 후 시작은 새 설정의 처음부터 실행이라는 차이를 구분하십시오.

늦은 이전 OCR·창 조회·정리가 새 실행에 반영되지 않는 경계를 함께 확인합니다. 녹화·반복·새로 고침·중복 방지·대상 보호를 유지하며 제품 비교는 19 →21입니다.

### LEVEL 3 · 설정에서 화면 조작까지


실행 전에 매크로를 선택/생성하고 동작 순서, 반복, 대기 값을 확인하십시오. 글자 조건은 검색 방식과 검색 영역을 함께 지정합니다. 대상 앱과 접근성 서비스 연결을 확인한 뒤 실행하고 플로팅 제어의 정지·일시정지·진행 기록을 관찰합니다. 필요한 입력은 동작·화면 글자·좌표·영역·반복 설정입니다.

확인 경로는 MainActivity 편집 →Store 저장 →MacroService의 대상/글자 확인 →캡처·인식·접근성 제스처 →진행 갱신입니다.

Java·Android 접근성·ML Kit 한국어 OCR을 사용하는 이 경로에서 실제 터치뿐 아니라 JSON 저장 내용, 플로팅 상태, 동작/인식/오류 기록을 각각 확인하십시오.

저장 파일만 확인하고 실행까지 성공했다고 판정하지 않습니다.

공개 소스로 기존 개인 서명 앱을 업데이트할 수 있다고 가정하지 마십시오.

### LEVEL 3 · 화면과 집중 검사 범위


라이트와 다크에서 기존 4 탭·작은 진행 창·OBJ·나눔고딕 Bold700을 확인하십시오.

흑백 바탕과 파란 주 동작/선택 표시를 사용하며 화면 구조는 유지합니다. 320dp 작은 화면과 긴 설정에서는 스크롤로 하단 동작에 접근하고 실제 키보드를 열어 저장·취소를 조작합니다.

취소된 새 시안 제작·전면 재배치를 납품 범위에 넣지 않습니다.

[entry-check-plan.json](../../21차/source/tools/entry-check-plan.json)의 기본 23개와 작은 화면 5개에서 진입 조건과 제어 경계를 확인합니다.

긴 OCR·캡처 복구 뒤 정상 화면을 읽은 시점부터 확인 시간이 보장되는지, 여러 번 복귀 중 일시 정지해도 이미 수행한 횟수가 유지되는지, 연결 해제 직후 정지 버튼이 처리되는지 대조합니다.

기존 기기 회귀 120개/상한을 유지하며 실행 결과는 [검증 기록](../../21차/검증_결과.md)에서 별도로 읽으십시오.

### LEVEL 3 · 이어받은 적응 대기와 입체 표시


적응 옵션을 사용할 때 기본 꺼짐에서 시작해 동일 방식/영역의 연속 글자 조건을 확인하십시오.

다음 글자의 사전 부재가 확인될 때만 완료 후 대기가 다음 조건 대기로 바뀝니다.

이미 보이는 조건, 수동 대기, 반복 간격, 무작위 대기는 유지되어야 합니다.

같은 위치의 다음 터치는 사라짐/재등장을 확인하되 모든 개별/전체 반복 차단으로 해석하지 않습니다.

목록의 별도 사라짐 설정, 기존 숫자, 터치 전 재확인을 보존합니다.

단계·OCR·캡처·설정 대기는 중첩되므로 합산하지 말고 외부 전체 반복 시간과 내부 집계를 구분하여 읽으십시오.

준비 전 일시 정지/정지 이후 이전 큐가 측정을 재초기화하지 않는지 확인합니다.

개별 TEXT_TAP은 제어 창 준비 뒤 대상 확인과 전달 직전 창 변경/일시 정지 세대 대조를 수행하며 목록 진입은 기존 대상 확인/중복 예약 순서입니다.

홈 OBJ 224 정점·168 면의 실제 투영·깊이 정렬·조명과 상태 변경 갱신을 확인합니다. 상시 애니메이션/예약 루프는 없고 나눔고딕 Bold·라이트/다크·제어를 유지합니다. 15회 120초는 측정 목표입니다. 납품 검사 범위만 결과로 읽고 실제 게임·사용자 블루스택 99%나 무오류를 주장하지 않습니다.

### LEVEL 3 · 저장 형식과 입력 범위


저장 JSON의 schema1 과 Macro 필드인 이름·시작 번호·전체 반복·반복 간격·시작 지연·최대 시간·동작 배열을 확인하십시오.

동작 수 1~500개, 배열 안 시작 번호, 활성 Step 검증이 필요합니다.

전체 반복 0~100,000, 간격/시작 지연 0~600,000ms, 최대 시간 0~1,440분을 벗어난 값을 실행용으로 쓰지 않습니다.

개별 Step에서는 종류·좌표·검색 영역·글자 비교·인식 출처·실패 정책·반복·대기·분기 번호를 점검합니다. 비율 좌표의 유한성, 영역 좌우/상하 순서, 문구 존재, 정규식 문법, 패키지 명, 이동/분기 번호를 확인하고 저장 검증 후에도 실제 접근성 서비스와 OCR 가용성을 별도로 시험하십시오.

### LEVEL 3 · 결과와 오류 확인


결과를 확인할 때 완료 반복 수와 현재 회차를 따로 기록하고, 글자 부재와 화면 읽기 실패, 중지와 복구 대기를 구분하십시오. 운영 로그의 화면 인식 본문을 검토한 뒤 필요한 범위만 공유합니다.

연결 실패 시 접근성 권한과 서비스 연결을 확인합니다. 탐지 실패는 인식 방식·검색 영역·접근성 텍스트·캡처 제한을 대조하십시오. 좌표/반복 불일치는 화면 방향·비율 좌표·개별/전체/목록 반복으로 나눠 확인합니다. 표시된 상태만으로 미실행 범위까지 검사했다고 기록하지 않습니다.

### LEVEL 3 · 직전 자료와 전체 변경


수정 범위를 재확인할 때 아래 전체 비교에서 추가·수정·삭제 파일을 열고 주석·공백·개행까지 대조하십시오. 표시된 행 증감과 바이너리 크기·해시를 보존합니다. 기능 설명만으로 모든 파일 변경을 확인했다고 처리하지 않으며 비교 대상이 없는 자료에 이전 번호를 만들어 넣지 않습니다.

### LEVEL 4 · 이 자료의 목적과 달라진 점


진입 확인을 목록 탐지 이후, 선택 매크로 시작 이전의 결정 경계로 둡니다. 기본 꺼짐이며 확인 글자의 존재와 유한 시간 부재, 선택적 복귀 글자의 존재를 구분합니다. 복귀 글자는 동시 관측 시 우선합니다. 잘못 진입한 항목을 완료 횟수나 정상 완료 후 대기에 반영하지 않아 탐지 성공과 매크로 완료의 집계를 분리합니다.

일시정지/계속 실행은 동일 실행 위치를 유지하지만 문구 변경 뒤 시작은 **새로운 실행**입니다. 이전 세대의 OCR·창 조회·정리 결과가 새 실행 상태를 덮지 않는 경계를 보강했습니다. 녹화·반복·새로고침·중복 방지·대상 보호를 유지한 채 실행 수명만 구별해야 합니다.

과거 제품과 시험 자료를 모두 보존하며 시험 차수를 제품 기능 기준으로 임의 승격하지 않습니다.

### LEVEL 4 · 설정에서 화면 조작까지


배포/설정의 전제는 동일 앱 ID·서명의 21차 업데이트를 통한 저장 매크로 유지입니다.

목록 글자·1~6 순위 영역·실행 매크로·반복 횟수 설정 뒤 홈의 진입 확인에서 확인 글자·시간·영역·선택적 복귀 글자를 구성합니다.

UI에서 입력한 두 조건은 동시 관측 우선순위와 유한 부재 시 복귀에 연결되며, 일시 정지의 위치 보존과 문구 변경 후 새 시작의 세대 전환을 혼합하지 않습니다.

입력 계약은 매크로 동작·화면 문구·비율 좌표·영역·반복 설정이고 실행 경계는 MainActivity/Store/MacroService로 나뉩니다.

편집과 영속화 후 대상 앱·문구 확인, 캡처/인식, 접근성 제스처, 진행 갱신을 수행합니다.

Android 접근성·Java·ML Kit 한국어 OCR이라는 기술 분류 안에서도 입력 전달과 글자 관측은 별도 책임입니다.

실제 터치·플로 팅 상태·JSON·동작/인식/오류 기록은 각 계층의 출력입니다.

운영 절차는 설정 검토→방식/영역 지정→대상/서비스 확인→실행과 제어 상태 관찰입니다. 정지·일시정지 접근과 진행 기록을 함께 확인해야 합니다. 이 경계를 수정할 때 저장값의 유효성과 런타임 화면 조건을 혼합하면 입력이 유효하다는 이유로 관측 단계를 생략하는 오류를 만들 수 있습니다.

### LEVEL 4 · 빌드와 접근성 연결


재현 단위는 Java 파일 집합이 아니라 같은 차수의 Gradle 프로젝트와 manifest·리소스·wrapper JAR·SDK·JDK·서명 입력입니다.

일부 소스/설정 예제를 전체 배포 단위로 확장 해석하지 않습니다.

### LEVEL 4 · 화면과 집중 검사 범위


UI 변경은 네이티브 배치·4 탭·작은 진행 창·OBJ·나눔고딕 Bold700을 유지한 공통 토큰 정리입니다. 흑백 바탕과 파란 주 동작/선택 표시, 라이트/다크, 320dp의 스크롤 접근을 다룹니다. 새 이미지 시안·전 면 레이아웃 교체는 취소되어 변경 경계 밖입니다.

시간 정책은 복구 지연과 유효한 관측 구간을 분리합니다.

긴 OCR·캡처 복구 뒤 정상 화면을 얻은 시점부터 진입 확인 시간을 보장하고 키보드 상태에서도 저장/취소 경로를 유지합니다.

연속 뒤로가기의 누적 복귀 횟수는 일시정지 후에도 보존하며 연결 해제 직후 잔류 정지 버튼을 처리합니다. [집중 명세](../../21차/source/tools/entry-check-plan.json)의 기본 23/작은 화면 5와 기존 회귀 120개/시간 상한은 별도 계약입니다.

명세 존재를 실측 통과나 장기 안정성으로 바꾸지 않습니다.

### LEVEL 4 · 이어받은 적응 대기와 입체 표시


적응 실행의 전제는 기본 꺼짐, 동일 인식 방식/영역, 연속 글자 조건의 사전 부재입니다.

이를 만족하면 after 성격의 완료 대기를 다음 조건 대기로 이전합니다.

기존 조건·수동 WAIT·gap·무작위 대기는 유지합니다.

동일 위치 다음 터치의 부재→재등장 가드와 목록의 사라짐 설정은 범위가 다르고 명시 반복/전체 반복을 전부 차단하지 않습니다.

기존 프로필 값과 전달 전 재확인을 약화하지 않습니다.

성능 집계는 단계에 OCR·캡처·설정 대기가 포함되는 구조이므로 서로 배타적인 측정으로 합산할 수 없습니다.

외부 벽시계와 내부 집계를 분리합니다.

준비 이전 pause/stop에 대한 실행 세대 확인이 이전 큐의 측정 초기화를 막고, TEXT_TAP은 제어 창 준비 후 대상 조회와 main 전달 직전 창/일시 정지 세대 확인을 수행합니다.

목록 진입의 대상 확인/중복 예약 순서는 그대로입니다.

OBJ의 224 정점·168 면을 원근 투영·깊이 정렬·조명으로 렌더링하되 상태 변화 시 갱신하여 상시 애니메이션/예약 루프를 두지 않습니다.

나눔고딕 Bold·라이트/다크·제어 흐름은 보존합니다. 15회 120초는 통제 측정의 목표이며 코드 구조만으로 실제 게임/블루스택 성공률 99% 또는 무오류를 도출하지 않습니다.

### LEVEL 4 · 저장 형식과 입력 범위


직렬화 계약은 schema1 Macro의 이름·시작 번호·전체 반복·간격·시작 지연·최대 시간·동작 배열입니다. validate는 동작 수 1~500과 시작 인덱스의 실 배열 범위를 확인하고 활성 Step.validate를 호출합니다.

반복 0~100,000, 간격/지연 0~600,000ms, 최대 시간 0~1,440분이라는 경계를 런 타임 성공 여부와 혼합하지 않습니다.

Step의 종류·좌표·영역·문구 비교·인식 출처·실패 정책·반복/대기·분기 참조를 유지하며 유한 비율 좌표·영역 순서·문구·정규식·패키지 명·이동/분기 번호를 검사합니다. 정적 저장 계약과 플랫폼 접근성/OCR 가용성을 별도 실패 계층으로 다루는 것이 확장 시 보존할 경계입니다.

### LEVEL 4 · 결과와 오류 확인


결과 모델에서 진행(현재/완료), 관측(부재/읽기 실패), 제어(정지/복구 대기)는 별도 축입니다. 이들을 합치는 변경은 완료 집계나 실패 정책을 왜곡할 수 있습니다. 운영 로그에 화면 인식 원문이 포함될 수 있으므로 공개 데이터와 분리합니다.

진단 경계는 접근성 권한/서비스 연결, 방식/검색 영역/접근성 텍스트/캡처 제한, 방향/비율 좌표/개별·전체·목록 반복으로 나뉩니다. 증상을 다른 계층의 성공으로 상쇄하지 않고 해당 계층의 조건을 확인해야 합니다.

### LEVEL 4 · 직전 자료와 전체 변경


전체 비교는 소스·설정·문서의 변경 추적 단위입니다. 추가/수정/삭제와 주석·공백·개행을 포함하고 바이너리는 크기/해시로 보존합니다. 행 증감은 의미상 변경과 일대일 대응하지 않으므로 기능 해석과 분리합니다. 확인된 이전 자료만 비교 기준으로 삼고 자료 공백을 추정으로 메우지 않습니다.

<a name="️-화면과-사용-흐름"></a>
## 화면과 사용 흐름


1. 같은 앱 ID·서명의 21차를 기존 앱 위에 설치해 저장 매크로를 유지합니다.
2. 목록 글자·1~6 순위 영역·실행 매크로·반복 횟수를 정합니다.
3. 홈의 진입 화면 확인을 열고 확인 글자·확인 시간·필요한 확인 영역을 지정합니다.
4. 선택적으로 되돌아갈 글자를 넣습니다. 확인 글자와 함께 보이면 되돌아갈 글자를 우선합니다.
5. 확인 글자가 보이면 매크로를 실행하고, 유한 대기 동안 없거나 되돌아갈 글자가 보이면 뒤로 가서 1 순위부터 찾습니다.
6. 일시정지/계속 실행은 현재 위치를 유지합니다. 글자를 바꾼 뒤 시작하면 새 설정으로 처음부터 실행합니다.

<a name="-이-차수-원래-안내의-세부-조건"></a>
### 이 차수 원래 안내의 세부 조건


### 기존 구조와 흑백·파란색 화면


기존 네이티브 화면·하단 4 탭·실제 OBJ 모델·작은 진행 창·나눔고딕 Bold700을 유지합니다.

바탕과 보조 영역은 흑백 계열로 정돈하고 주 동작과 선택에 파란색을 사용합니다.

라이트와 다크·320dp 작은 화면의 실제 기능 화면을 확인하며, 하단 동작과 긴 설정은 스크롤로 접근합니다.

새 이미지 시안 제작과 전면 재배치는 취소된 요청입니다.

새 집중 명세는 [entry-check-plan.json](../../21%EC%B0%A8/source/tools/entry-check-plan.json)의 기본 23개·작은 화면 5개입니다.

긴 OCR·캡처 복구 후 정상 화면을 읽은 시점부터 확인 시간을 다시 보장하며, 실제 키보드를 연 상태에서도 진입 설정의 저장·취소를 조작하도록 새 설정 창을 조정합니다.

여러 번 뒤로 가는 도중 일시 정지해도 이미 수행한 복귀 횟수를 유지하고, 연결 해제 직후 남아 있던 정지 버튼도 처리합니다.

기존 120개 기기 회귀의 검사와 상한은 유지합니다. 24 시간·장기 시험과 선택 성능 비교는 실행하지 않습니다.

### 적응 실행과 실제 입체 모델


매크로 설정의 **다음 글자에 맞춰 진행**은 기본 꺼짐입니다.

켜면 같은 인식 방식과 영역의 연속 글자 동작에서 다음 글자의 사전 부재를 확인한 경우, 완료 후 대기를 다음 조건 대기로 바꿔 새 글자가 보이면 진행합니다.

이미 보이는 조건·수동 대기·반복 간격·무작위 대기는 유지합니다.

바로 다음 글자 터치가 같은 위치를 가리키면 사라짐과 재등장을 확인합니다.

개별 동작의 명시적 반복이나 전체 반복 경계를 모두 차단하는 기능은 아닙니다.

목록 탐지의 기존 사라짐 확인 설정은 별도로 유지합니다.

기존 프로필의 숫자를 일괄 축소하거나 터치 전 재확인을 끄지 않습니다.

실행 측정은 단계·OCR·캡처·설정 대기의 실제 시간을 구분합니다. 단계 시간에는 하위 작업이 포함되므로 네 값을 더한 숫자를 전체 시간으로 사용하지 않습니다. 전체 반복의 외부 측정과 내부 집계를 구분합니다.

실행 준비보다 먼저 일시정지하거나 정지해도 이전 대기열 작업이 측정값을 다시 초기화하지 않도록 실행 세대를 확인합니다.

개별 글자 터치는 제어창 준비 뒤에 대상을 확인하고, 실제 전달 직전에 관측된 창 변경과 일시정지 세대를 다시 대조합니다.

이 추가 전달 검사는 개별 `TEXT_TAP` 경로에 적용합니다.

목록 진입 터치는 기존의 대상 확인과 중복 예약 순서를 유지합니다.

홈의 PXE 모델은 실제 OBJ 224 정점·168 면을 읽어 원근 투영·깊이 정렬·조명으로 그립니다. 상태가 바뀔 때 갱신하며 상시 애니메이션·예약 렌더 루프는 없습니다. 나눔고딕 Bold와 기존 라이트/다크·제어 흐름을 유지합니다.

15회 120초는 통제 시험에서 측정할 목표입니다. 실제 게임·사용자 블루스택의 성공률 99% 또는 무오류를 코드만으로 보장하지 않습니다. 납품 검사 결과에 실제 실행 범위를 기록합니다.

### 매크로 저장과 실행 입력 검증


`Macro`는 schema1의 JSON으로 이름·시작 번호·전체 반복·반복 간격·시작 지연·최대 시간·동작 배열을 직렬화합니다. `validate`는 동작 1~500개, 시작 번호가 실제 배열 범위 안인지 검사하고 활성 동작에 `Step.validate`를 적용합니다.

전체 반복은 0~100,000, 간격·시작 지연은 0~600,000ms, 최대 시간은 0~1,440분 범위입니다.

`Step`은 동작 종류·좌표·검색 영역·글자 비교·인식 출처·실패 정책·반복과 대기·분기 번호를 저장합니다.

입력 검증은 화면 비율 좌표와 유한 값, 검색 영역의 좌우/상하 순서, 문구 존재, 정규식 문법, 앱 패키지 명과 이동/분기 번호를 함께 확인합니다.

저장 JSON의 schema 통과와 실제 장치의 접근성/OCR 가용성은 별도 조건입니다.

21차는 19차 제품을 기준으로 한 새 요청이며, 사용자가 중단한 20차 장기 시험을 재개하지 않습니다.

16차에서 도입한 적응 실행·시간 측정·입체 표시를 이어받습니다. [16차의 같은 수준 설명](16차.md#user-content-reading-level-5)과 이 차수의 변경을 비교합니다.

19차에서 21차로 이어지는 실제 파일 비교입니다.
