## LEVEL 1 · 처음 사용하는 분을 위한 설명

| 하는 일 | 이번 화면 변경 | 확인할 점 |
|---|---|---|
| 글자 찾기 | 입력창과 버튼의 간격·테두리 정돈 | 찾을 문구와 인식 방식을 먼저 확인 |
| 매크로 편집 | 동작 목록·더보기·설정의 조작 표시 통일 | 현재 편집본을 이름으로 다시 저장 |
| 화면 모드 | 라이트·다크·기기 설정 선택 유지 | 테마 선택 저장과 화면 가독성은 기기 검사 필요 |
| 키보드 조작 | 선택 가능한 항목의 포커스 테두리 추가 | 포커스는 현재 키보드로 조작할 항목을 뜻함 |

PXE는 사용자가 만든 터치·기다리기·뒤로가기 순서를 실행하는 앱입니다. 매크로는 이런 동작을 순서대로 저장한 목록이고, OCR은 화면을 그림처럼 읽어 글자를 찾는 처리입니다. 한글 OCR 모델은 앱 안에 있으며 인터넷으로 화면을 보내 읽는 방식이 아닙니다. 화면 정보 방식은 대상 앱이 제공하는 글자 정보를 읽습니다.

예를 들어 화면의 `Adobe`를 찾으려면 찾을 글자에 그대로 입력하고, 그림처럼 표시된 글자는 한글 OCR을 선택합니다. 필요한 버튼 주위에 탐지 영역을 지정하고 실행할 매크로와 반복 횟수를 확인합니다. 한글 `어도비`와 영문 `Adobe`를 같은 글자로 바꾸어 찾지는 않습니다. 입력·영역·녹화·시간 설정·실행 준비 순서를 안내 화면에서 따라갈 수 있습니다.

| 단계 | 사용자가 하는 일 | 앱에서 확인할 내용 |
|---|---|---|
| 준비 | 중요한 매크로 내보내기 | 기존 앱을 삭제하지 않고 업데이트할 조건 확인 |
| 설정 | 글자·최대 6개 우선 영역·매크로 지정 | 우선순위와 현재 저장본 일치 |
| 실행 | 탐지 시작 | 진행·반복·대기 상태 표시 |
| 제어 | 일시정지·재개·정지 또는 단축창 이동 | 정지와 일시정지는 다른 동작 |

일반 메인 버튼과 입력창은 최소 48dp를 기준으로 하며, 긴 글자가 있으면 높이가 늘어납니다. dp는 기기마다 화면 크기가 달라도 조작 크기를 비슷하게 맞추는 Android 단위입니다. 모서리·색·선택 표시를 정리했지만 앱이 누르는 위치나 OCR 모델을 바꾼 것은 아닙니다. Rust는 앱을 만드는 PC에서 색상 목록을 생성하는 데 사용합니다. 사용자가 별도로 Rust를 설치해 앱을 조작할 필요는 없습니다.

이번 차수의 빌드·단위 102개·린트와 실제 UI·제어·OCR 검사 11개 방법은 통과했습니다. 독립 내용·명세 검토와 로컬 묶음 대조를 마쳤습니다. 원격 반영은 게시 커밋과 별도 확인 기록을 따릅니다. 예전 27차의 54.5분 관측은 호스트 재부팅으로 60분 최종 판정이 끝나지 않은 기록이며 28차 성공 결과가 아닙니다. 26차 최종본은 유지합니다. 보안 화면이나 흐린 글자는 인식이 제한될 수 있으므로 실제 대상 앱에서 미리보기로 확인해야 합니다.

### LEVEL 1 · 멈추지 않고 설정을 바꾸는 순서

| 상황 | 사용할 조작 | 의미 |
|---|---|---|
| 앱으로 돌아와 편집 | 일시정지 중 표시 확인 | 편집 중에는 자동 입력을 잠시 멈춤 |
| 같은 작업 이어가기 | 계속 실행 | 기존 실행의 남은 순서를 이어감 |
| 새 글자로 바꾸기 | 글자 변경 뒤 시작 | 새 입력을 검사하고 새 작업으로 시작 |
| 완전히 끝내기 | 정지 | 현재 작업 종료 |
| 글자 편집을 취소 | 단축창 편집에서 취소 | 원래 실행이 계속되는 조건이면 다시 이어감 |

앱의 탐지·동작·글자·설정 네 탭에서 실행 제어를 볼 수 있습니다. 메인 앱에 들어올 때 자동 일시정지되는 동작을 없애지 않고, 지금 멈춘 상태와 계속 실행 버튼을 함께 표시했습니다. 단축창의 글자 창은 실행 중 열면 잠시 멈추고, 적용 없이 닫았으며 같은 실행이 그대로 남아 있으면 원래 실행을 이어갑니다. 이미 일시정지했던 실행을 임의로 재개하지는 않습니다. 동작 목록 구조 편집·좌표·녹화는 여전히 별도의 정지 조건이 있습니다.

작은 하단 위젯의 `1/15`는 현재 반복/전체 반복을 뜻하며 모든 작업 완료 개수는 아닙니다. 숫자 부분을 끌어 위치를 바꾸고 화살표로 상세를 펼칩니다. 펼친 화면에서 진행·시간·일시정지·정지를 확인합니다. 설정의 하단 위젯 불투명도는 40~100%이며 기본 95%입니다. 노란 선의 해 아이콘은 Orbit 참고 분위기를 반영한 상태 장식이고 AI가 아닙니다. 이번에 뺀 3D 장식도 학습 기능과 별개입니다.

실제 기기에서는 75번의 OCR 터치와 화면 진입·뒤로가기 각5회를 같은 앱 프로세스·서비스로 수행했습니다. 마지막 정지 뒤 전체 관측은65.9초이며 60분 장기 검사가 아닙니다.

## LEVEL 1 - Beginner

### LEVEL 1 · 기존 순서를 유지하며 기다림 다듬기

PXE는 화면 글자를 찾아 사용자가 정한 순서대로 터치·제스처·뒤로가기를 실행합니다. OCR은 화면 사진에서 글자를 읽는 기능입니다. 앱 안에 한글 OCR이 들어 있어 인터넷 연결 없이 사용할 수 있습니다. 이번에는 다음 행동을 새로 학습하는 AI를 추가하지 않았습니다.

| 사용자가 정할 것 | 앱의 동작 | 확인할 점 |
| --- | --- | --- |
| 글자와 탐지 영역 | 지정한 문구를 찾아 위치 확인 | 비슷한 글자·다른 버튼을 영역에서 줄입니다. |
| 녹화 또는 동작 목록 | 저장한 순서대로 실행 | 이름 있는 저장본과 현재 편집본을 구분합니다. |
| 반복과 복귀 시간 | 정한 횟수 뒤 목록으로 돌아가 다시 찾기 | 동작 하나의 반복과 매크로 전체 반복은 다릅니다. |
| 기다리기·분기 | 문구가 나타나길 기다리거나 다른 동작으로 이동 | 유한 재시도와 계속 기다리기를 구분합니다. |
| 최대 6개 우선 영역·중복 방지 | 영역 순서대로 찾고 같은 글자 재실행 제한 | 완료 글자가 사라져야 다시 실행되는 조건을 확인합니다. |

### LEVEL 1 · 이번 화면과 대기 변경

| 부분 | 27차에서 다듬은 점 |
| --- | --- |
| 캡처 준비 | 컨트롤을 숨긴 뒤 화면이 안정되길 기다리는 시간과 다음 캡처까지의 간격을 함께 기다립니다. |
| 글자 읽기 | 기존 전체 화면과 해상도를 유지합니다. 글자 그림을 작게 줄여서 속도를 내지 않습니다. |
| 화면 색상 | 검정·흰색과 차분한 파란 포인트로 화면·팝업·컨트롤 색상을 맞췄습니다. |
| 상태 표시 | 같은 문구를 계속 다시 넣지 않고 실제 문구가 바뀔 때 갱신합니다. |
| 가독성 | 연결 상태와 선택한 탐색 항목, 카드와 상태창의 간격을 정리했습니다. |

화면 위 컨트롤이 캡처에 섞이지 않게 잠시 숨기는 시간과, 캡처를 너무 자주 요청하지 않게 두는 간격이 있습니다. 두 기다림을 차례로 더하던 부분을 겹치게 했지만, **각각 필요한 시간은 모두 유지합니다.** 실제로 얼마나 빨라지는지는 27차 측정 결과로 확인해야 합니다.

### LEVEL 1 · 준비와 제어

| 순서·상황 | 할 일 |
| --- | --- |
| 설치 | 기존 앱을 삭제하지 않고 업데이트하고 권한 안내를 따릅니다. 중요한 매크로는 내보내 보관합니다. |
| 설정 | 글자 → 영역 → 녹화 → 시간·반복 → 실행 준비 순서로 진행합니다. 이미지 글자는 한글 OCR을 선택합니다. |
| 저장 | 수정한 매크로는 사용하는 이름으로 다시 저장하고 탐지에서 선택합니다. |
| 실행 중 | Ⅱ / ▶로 일시정지·재개하고 정지 버튼으로 멈춥니다. |
| 예상과 다른 화면 | 문구·영역·조건 분기를 확인합니다. 대상 앱이 불명확하면 바로 터치하지 않는 정책입니다. |
| 결과 확인 | [검증 결과](../../27차/검증_결과.md)에서 실제 확인 범위를 읽습니다. 중단된 연속 검사의 복구 관측과 별도 속도 비교를 구분합니다. 60분 통과로 표시하지 않습니다. |

## 직접 정한 순서대로 글자를 찾고 누르기

PXE는 화면의 글자를 읽고 사용자가 만든 순서대로 터치·스크롤·뒤로가기를 실행하는 앱입니다. 이번 26차는 **16차의 화면과 일반 매크로**를 기준으로 합니다. 사용자가 시범을 보여 주며 행동을 학습시키는 별도 AI는 포함하지 않습니다. OCR은 화면 사진에서 글자를 읽는 기능이며 계속 필요하므로 앱 안에 유지했습니다. 인터넷 연결이 없어도 사용할 수 있습니다.

| 설정할 것 | 실제 동작 | 주의할 점 |
| --- | --- | --- |
| 글자와 네모 영역 | 지정한 영역에서 문구를 찾아 누릅니다. | 비슷한 문구와 다른 버튼을 영역에서 줄입니다. |
| 녹화 또는 동작 목록 | 저장한 순서대로 터치·대기·뒤로가기를 실행합니다. | 이름으로 저장한 매크로와 편집 중인 매크로는 구분합니다. |
| 반복 횟수 | 탐지한 항목에 들어가 저장 매크로를 지정 횟수 실행합니다. | 동작 하나의 반복과 전체 매크로 반복은 다릅니다. |
| 글자가 없을 때 | 기다리거나, 뒤로가기·스크롤 뒤 다시 찾습니다. | 계속 기다리기와 횟수가 있는 재시도는 다른 설정입니다. |
| 우선 영역과 새로고침 | 최대 6개 영역을 순서대로 확인하고 완료 후 다시 탐지합니다. | 같은 문구 중복 방지는 별도 설정입니다. |

### 설치에서 저장까지

| 구분 | 적용 내용 |
| --- | --- |
| 업데이트·권한 | 공용 APK를 기존 앱 위에 업데이트로 설치하고 권한 안내를 따릅니다. |
| 안내 순서 | 찾을 글자 → 탐지 영역 → 매크로 녹화 → 시간·반복 설정 → 실행 준비 순으로 안내 화면을 따라가세요. |

## 그림을 가르친다는 뜻

PXE의 기본 기능은 미리 정한 순서대로 글자를 찾고 화면을 누르는 **매크로**입니다.

24차는 선택형 AI에 글자 없는 아이콘도 가르치려는 변경입니다.

| 역할·조건 | 동작과 확인할 내용 |
| --- | --- |
| 매크로와 선택형 AI | AI는 처음에는 꺼져 있으며, 기존 매크로를 쓰는 데 켤 필요가 없습니다. |
| 그림 시범의 관측 | 예를 들어 그림 버튼을 가르칠 때는 그 때 보이는 글자와 화면의 색 배치, 사용자가 누른 그림 조각을 함께 기록합니다. |
| 현재 위치 결정 | 다시 실행할 때는 예전 좌표를 그대로 누르는 대신 현재 화면에서 그림을 다시 찾은 위치를 사용합니다. |
| 중복 후보·낯선 화면 | 같은 그림이 두 개 있어 구별하기 어렵거나 처음 보는 화면이면 누르지 않고 기다립니다. |
| OCR 글자 읽기 | OCR은 화면 사진의 글자를 읽는 기능입니다. |
| RGB 색 배치 | RGB는 화면 색을 빨강·초록·파랑 값으로 나타내는 방법입니다. |
| 정책의 행동 선택 | 정책 모델은 이 관측을 보고 가르친 행동 중 하나를 고르는 작은 신경망입니다. |
| 확정 시범의 가중치 갱신 | 사용자가 확인한 시범으로 가중치, 즉 행동 선택에 쓰는 내부 숫자를 바꿉니다. |

화면을 저장했다는 사실만으로 학습이 끝난 것은 아닙니다.

이미지 선택, 글자 대기, 일반 동작 선택은 각각 다른 입력이므로 앞에서 선택한 이미지 모드가 다음 동작에 남지 않아야합니다.

<a id="level-1--예전-모델과-새-저장-파일"></a>

## 예전 모델과 새 저장 파일

24차의 시각 정책은 글자와 이전 행동 등의 584개 값에 색 배치 576개를 더 한 **1160개 입력**을 사용합니다.

F64는 내부 숫자를 64 비트로 저장한다는 뜻이며 정확도가 64%라는 뜻이 아닙니다.

| 역할·조건 | 동작과 확인할 내용 |
| --- | --- |
| 구형 입력 모델 읽기 | 구형 584차원 모델을 읽는 기능도 남깁니다. |
| v2 packed 저장 항목 | 새 모델은 v2 packed라는 묶음에 가중치뿐 아니라 시범, 행동 이름표, 난수 생성 상태와 학습 상태를 넣습니다. |
| 학습 재개용 난수 상태 | 난수 생성 상태는 학습의 다음 계산을 이어 가는 데 필요한 기록입니다. |

파일 형식을 검사했더라도 다른 휴대 전화에 가져와 파일 선택 창으로 여는 과정까지 확인한 것은 아닙니다.

개인 시범·화면·모델은 비공개로 보관합니다.

## 응답이 늦을 때 누르기를 반복하지 않기

| 역할·조건 | 동작과 확인할 내용 |
| --- | --- |
| 지연 관측 | 화면 작업의 답이 늦으면 한 번 더 누르고 싶을 수 있지만, 첫 입력이 뒤늦게 실행되면 두 번 눌릴 수 있습니다. |
| 일반 화면 작업 | **5초**는 지연을 알리는 기준이며 **처음 요청한 작업의 결과를 계속 기다립니다**. |
| 제스처 | **65초**는 지연을 알리는 기준이며 **처음 요청한 작업의 결과를 계속 기다립니다**. |
| future의 의미 | future는 이 결과를 받기 위한 대기 표에 해당합니다. |
| 원요청 결과 대기 | 새 대기 표를 만들어 같은 터치를 다시 보내지 않습니다. |

| 캡처 준비 재시도 | 오래된 준비 작업을 취소하고 대기열에서 제거한 뒤 새 준비를 시도합니다. |
| 정지·권한·실행 기한 | 이때도 정지, 권한 해제, 서비스 종료, 회전과 사용자가 정한 전체 실행 시간 제한을 확인합니다. |

영원히 응답이 없는 기기를 반드시 복구한다는 약속은 아닙니다.
