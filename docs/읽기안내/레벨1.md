### LEVEL 1 · 기능과 확인 범위 비교

| 확인할 항목 (Checklist) | 본문의 핵심 조건 |
| --- | --- |
| 기능·동작 | 사용자는 글자·영역·우선순위·반복을 정하고 앱이 안내하는 접근성·화면 읽기 권한을 허용합니다. 실행 중 작은 창으로 멈추거나 이어 할 수 있고 AI를 쓰려면 별도로 켜고 직접 시범을 보여 줍니다. |
| 입력·처리·출력 | 입력은 사용자가 정한 동작과 현재 화면 글자입니다. 앱은 조건을 비교해 터치·대기·이동을 실행하고 진행 상태·설정·기록을 남깁니다. AI 시범은 사용자가 보여 준 작업을 따로 저장합니다. |
| 결과·한계 | 현재 AI는 시범 OCR 특징의 작은 행동 모델입니다. 과거 한국어 자연어 모델은 실패했고 앱에 자산을 넣지 않았습니다. 행동 시범이 동작했다고 사람의 모든 말을 알아듣는 AI가 완성된 것은 아닙니다. |


PXE는 Android 화면에서 **조건이 맞을 때만 정해 둔 동작을 하는 앱**입니다. 매크로는 사람이 저장한 동작 목록입니다. 예를 들어 화면에서 “확인”이라는 글자를 찾은 뒤 그 위치를 누르고 다음 화면을 기다리도록 만들 수 있습니다. 이것은 사용자가 정한 예시이며 모든 앱에서 이미 성공했다는 뜻은 아닙니다. OCR은 화면 사진에서 글자를 읽는 기능이고, 접근성 정보는 Android가 제공하는 버튼·글자 정보를 뜻합니다.

## LEVEL 1 · 입력과 동작을 어떻게 연결하나요

먼저 대상 앱, 찾을 글자, 화면에서 찾을 범위, 눌러야 할 동작을 지정합니다. 좌표 터치는 정한 위치를 누르고, 글자 터치는 **지금 읽힌 글자의 위치**를 사용합니다. 글자를 기다리는 동작은 조건이 보일 때까지 입력을 보내지 않습니다. 반복 횟수와 동작 사이 대기는 별도 설정입니다. 목록을 새로 읽는 반복과 목록 안에서 실행하는 매크로 반복을 한 숫자로 섞어 읽으면 안 됩니다.

앱 위의 작은 제어창에서 시작·일시정지·계속 실행·정지를 구분합니다. 일시정지는 현재 위치를 보존하는 기능이고, 정지는 이번 실행을 끝내는 기능입니다. 완료 횟수는 실제로 끝난 횟수입니다. 가령7회가 끝나고8회째를 기다린다면 완료7회와 진행 중8회째는 다릅니다.

## LEVEL 1 · 안전하게 준비하고 확인하는 순서

사용 안내에서 자신의 Android 버전과 앱 서명을 확인하고 기존 매크로를 보존합니다. 접근성 권한과 화면 읽기는 사용자가 허용해야 합니다. 앱을 선택한 다음 동작·글자·영역·반복·대기를 읽어 보고 작은 범위부터 확인합니다. 저장 버튼을 눌렀다는 사실만으로 다른 앱을 제대로 읽고 누를 수 있다는 뜻은 아닙니다. 화면이 달라지거나 대상 앱이 맞지 않으면 오래된 위치를 누르지 않는 경계를 유지합니다.

현재 공용 파일은 ARM64 휴대전화와 x86_64 기반64비트 에뮬레이터를 위한 한 APK입니다. 설치 가능 조건과 실제 기능 검사는 다릅니다. 파일이 크기 때문에 공개 저장소에서는 APK 자체 대신 **크기·해시와 다시 만드는 소스**를 안내합니다. 해시는 파일이 같은지 비교하는 지문이며, 파일이 무조건 안전하다는 보증은 아닙니다.

## LEVEL 1 · 그림을 가르치는 기능은 어디까지 됐나요

기존 매크로가 주 기능이고 **AI는 기본 꺼짐**입니다.23차는 사용자가 확인한 시범의 글자 특징으로 행동을 배우는 작은 오프라인 모델을 사용했습니다.24차에는 글자와 그림·색 배치로부터 시범을 배우는 모델을 더했습니다. 자신이 예측한 결과를 자동으로 정답 삼아 배우는 방식과는 구분합니다. 이것은 대화하는 범용 언어모델이 아니며 개인 화면·시범·가중치는 공개하지 않습니다.

23차 전용 시험에서는 시범2회와 학습192단계, 자동 터치1회, 종료 뒤 추가 입력0을 확인했습니다. 그 결과를24차 그림 학습 성공으로 옮겨 적지 않습니다.24차는 실제 그림 검사에서 여러 번 실패했고, 완료 버튼·화면 경로 겹침을 고친 그 뒤 a15·a16도 전체 성공하지 못했습니다. 최신 상태는 아래에서 따로 설명합니다.

## LEVEL 1 · 통과와 실패를 읽는 법

정상 빌드10은 단위검사280개를 통과했습니다. 단위검사는 합성 입력이나 분리한 기능을 검사하는 것으로, 실제 모든 게임에서의 성공과 다릅니다. 실제 a7에서는 응답 복구19개가 통과했지만 원래15초 반복 검사는 실패했습니다. 별도 a9에서15회 동작이18.833초에 끝났어도 탐지 화면으로 돌아왔다는 확인에 실패해 전체 성공은 아닙니다. 단순히 빨랐다는 이유로 기능 실패를 지우지 않습니다.

화면 응답이 늦으면 입력을 다시 보내지 않고 기다리거나 새 화면으로 확인합니다. **기다릴 수 있다는 것과 작업이 반드시 끝난다는 것은 다릅니다.** 사용자 정지·권한 해제·서비스 종료·전체 시간 제한은 계속 적용합니다.24시간 운용·모든 앱·다른 설치로 모델 이식은 아직 보장하지 않습니다.

## LEVEL 1 · 빌드10과 a14 당시의 후속 관측

정상 제품의 a14 시험은23개 중22개가 통과했지만 그림을 눌러야 하는 첫 검사1개가20초 안에 터치를 확인하지 못해 실패했어요. 응답 복구19개와 기존 재생2개, 두 번째 그림 검사1개 통과를 전체 성공으로 읽지 않아요. 원본 복원은 끝났고 전체608.375초는 설치·증거·복원까지 포함해요. 앞선a13 실패와 원복303.906초도 남겨요. 이후 선택 모드를 보존하는 수리는 호스트 검사와 코드 컴파일만 확인했고 당시 새 기기 결과는 없었습니다. 사용자 블루스택의 글자 미발견 현상은 원인을 조사 중이에요.

MainActivity는 편집 화면, Macro·Step은 저장 목록과 한 동작의 검사, MacroService는 Android 접근성 실행, FloatingController는 화면 위 제어창을 맡습니다. 서비스 연결이 끝나거나 화면 방향이 바뀔 때 실행 상태를 정리합니다.

## LEVEL 1 · 동작 목록과 한 동작의 설정을 읽기

매크로(Macro)는 여러 동작을 묶은 목록이고 Step은 그 안의 한 동작입니다. 예를 들어 “확인 누르기, 잠시 기다리기”가 한 목록입니다. **전체 목록을 몇 번 할지와 같은 동작을 몇 번 할지는 별개**입니다. 21차 기본값은 목록 시작번호1, 전체 반복1회, 반복 간격1000ms, 시작 전3000ms, 최대30분이고 adaptiveWait는 false, 즉 적응 대기가 꺼져 있습니다. 1000ms는1초입니다. 저장 형식의 버전 표시는 schema1입니다. 목록에는1~500개 동작을 넣으며 전체 반복은0~100,000, 간격과 시작 지연은0~600,000ms, 전체 시간은0~1,440분 범위로 검사합니다. 범위의0이 모든 항목에서 같은 뜻이라는 가정으로 입력하지 말고 해당 사용 안내를 확인합니다. 실행에 쓰는 활성 동작은 각각 Step.validate 검사를 받습니다.

새 Step의 TAP은 한 번 누르기이며 기본 좌표50/50%는 화면 가운데입니다. 기본 인식 AUTO는 접근성 정보와 OCR을 사용하는 선택이고, CONTAINS는 찾을 글자를 포함하는지 비교하며, STOP은 실패하면 정지하는 정책입니다. 기본 누름100ms, 동작 뒤 대기500ms, 개별 반복1회, 글자 대기 제한3000ms, 재시도3회, 재시도 간격1000ms입니다. 허용값은 좌표0~100%의 유한한 수, 위치 보정(오프셋)±50%, 개별 반복1~1000회, 재시도0~100회, 재검색 간격300~600,000ms, 같은 글자의 몇 번째인지 정하는 occurrence1~100입니다. 검색 사각형의 앞뒤 순서, 정규식 문법, 대상 앱 패키지명과 분기번호도 검사합니다. 계속 기다리기와 즉시 진행은 **글자 터치·글자 대기에만** 적용하며 다른 동작의 대기를 한꺼번에 없애지 않습니다.

## LEVEL 1 · 누르기 외의 기능과 글자 비교

짧게 한 번, 두 번, 길게 누르기는 서로 다른 터치입니다. 스와이프는 한 경로로 밀기, 다중 터치는 여러 손가락 경로, 곡선은 굽은 경로, 확대·축소는 손가락 사이 간격을 바꾸는 동작입니다. 녹화는 직접 만든 경로를 다시 쓰는 기능입니다. 제스처 입력은1~20개 경로와 경로당1~512개 점으로 제한됩니다. 글자 기능은 누르기·기다리기·조건 분기·확인을 제공합니다. “확인”과 완전히 같아야 하면 일치, “확인하기”에도 반응하려면 포함, 일정한 글자 모양의 규칙을 쓰려면 정규식을 선택합니다. 정규식은 정해진 문법이 있으므로 잘못 쓰면 저장 검사가 거절할 수 있습니다.

ACCESS는 Android가 제공한 글자 정보, OCR은 화면 사진의 글자 읽기, AUTO는 자동 선택입니다. 실패 정책에는 정지, 건너뛰기, 뒤로 가서 재시도, 재시도, 스크롤 후 재시도가 있어 다음 동작이 달라집니다. 앱을 잘못 누르지 않도록 처음에는 정지 정책과 작은 시험부터 확인합니다. TextRules는 NFKC라는 문자 모양 정리, 공백 정리, 소문자 변환을 한 뒤 일치·포함을 비교하고 정규식 검색도 제공합니다. 화면에 적힌 원문 전체를 학습하거나 고치는 기능이라는 뜻은 아닙니다.

## LEVEL 1 · 저장과 화면 읽기가 실패할 때

설정은 Android의 SharedPreferences 안에 JSON이라는 글자 형식으로 저장합니다. 불러오기 실패 시 예제로 돌아갈 수 있으므로 **저장 버튼과 모든 실패의 무손실 복구는 다릅니다**. SetupFlow의 초안·백업도 이 한계를 없애지 않습니다. 같은 앱 ID와 서명으로 업데이트해야 하는 조건을 확인하고 원본 설정을 보존합니다.

CaptureRequests는 끝나지 않은 캡처를 최대2개로 막습니다. CapturePacer는 실제 응답이 온 뒤 Android API30에서는1.1초, API31 이상에서는0.5초를 기준으로 기다립니다. 너무 잦다는 거절을 받으면 최대12초까지 늘리고 성공하면 기준까지 조금씩 회복합니다. QueryLane은 화면 읽기를 동시에 겹쳐 보내지 않으며, WatchGate의 중복 잠금은 글자가 두 번 이상 연속 없고 최소 부재 시간도 지나야 풀립니다. 위자드는 완료 후 새로고침 대기 켜짐(waitForRefresh=true), 중복 방지 꺼짐(preventDuplicate=false)이 기본입니다. 완료 뒤 쉬기와 글자가 사라져야 다시 들어가는 조건은 다릅니다.

## LEVEL 1 · 준비 도구와 오류를 확인하는 순서

소스를 앱으로 만드는 빌드에는 Java17, Gradle8.13, Android SDK35와 Python이 필요하고 최소 Android API30을 확인합니다. 원래14차 구성의 AGP8.9.1은 Android 빌드 도구, ML Kit 한국어16.0.1은 글자 인식 라이브러리 버전입니다. 차수마다 실제 설정을 확인하며 과거 버전을 최신 전체의 고정값으로 바꾸어 읽지 않습니다. source에서 gradlew.bat의 :app:assembleRelease는 앱 만들기, :app:testDebugUnitTest는 단위 검사, :app:lintDebug는 정적 검사, :app:assembleReleaseAndroidTest는 기기 검사 앱 만들기입니다. -PNEX_PC는 ARM64와 x86_64를 함께 넣는 공용 산출물 선택입니다. 개인 서명키는 제공하지 않으며 빌드 스크립트는 실제 일반 폴더를 사용합니다.

서비스 연결이 안 되면 기기의 접근성 설정, 글자 인식이 멈추면 캡처·OCR 단계와 오류 기록·기기 지원을 확인합니다. 위치가 틀리면 화면 방향·0~100% 좌표·검색 영역, 저장 거절이면 Step의 시간·좌표·분기 범위를 봅니다. 빌드 실패는 Gradle 설정·Manifest·리소스·SDK·서명키, 제어창이 사라지면 서비스 연결·창 토큰을 확인합니다. 일반 실행 기록은 최근150줄이고 읽은 화면 본문·찾는 문구가 들어갈 수 있습니다. ErrorJournal은128KiB 파일 두 개를 번갈아 쓰며 오류 종류·상태를 남깁니다. 외부 공유 전 로그 내용을 확인합니다.

## LEVEL 1 · 이전 화면과 차수를 함께 이해하기

초기1~3차는 제어창 분리와 녹화·곡선·다중 터치·영역/위치 보정을 넓혔고,4~5차는 새로고침→탐지→선택 매크로→복귀를 추가했습니다. 5차의 탐지 기본15회는 매크로 전체 반복과 곱하지 않습니다. 6차는 최대6개 우선 영역·대상 앱·중복 잠금·완료 후 대기·단계 안내·임시 녹화,8~9차는 별도 화면 읽기·캡처 간격과 저장된 탐지 설정 재생을 다룹니다. 10~11차는 하단 탐색·카드·창 이벤트 확인·AUTO 지연 시 OCR 전환,12~13차는 계속 대기·늦은 결과 폐기·접힌 패널 정지·캡처2개/OCR Task1개·연결 종료 처리를 보강했습니다.

14차의 청록 화면·48dp 터치 영역·시스템 모션과 글자 재확인 뒤 사라지면 원래 대기를 재개하는 수정은 이전 기록입니다. 15차는 인식 방식 노출·캡처 간격 회복·탐지 반복 대기 축소·선택형 즉시 진입·설정 접기를 적용했고 전체 화면 OCR의 중심점 필터는 유지합니다. 21차는 확인 글자와 되돌아갈 글자를 구분하며 되돌아갈 글자가 우선입니다. 확인이 유한 대기 안에 없으면 뒤로 가서1순위부터 재탐색하고 잘못 들어간 항목은 완료 수와 완료 뒤 쉬기에 넣지 않습니다. 라이트·다크 화면은 전용 Android12 캡처이고 모든 기기의 화면 보증은 아닙니다. 19차 당시 기기120개·단위109개/20클래스·린트0과20차 장기 시험 중단은 각각의 기록입니다. 최종.json은7개 TEXT_TAP 설정이며 실행점검-2차와 차수 밖 NEX 자료도 제품 차수와 구분합니다.

## LEVEL 1 · 자연어 실험과 행동 학습의 차이

한국어 문장을 계획으로 바꾸려던 Transformer 실험은 개발 문제64개 중11개(11/64)만 맞혀 실패했습니다. 새 요약은 **17.2%(소수 첫째 자리 반올림)**이며 원값17.1875%를 보존합니다. 언어모델 자산은 앱에0개(assets0)입니다. 23차 당시의 작은 행동 MLP는 총584개 입력, 즉 글자512+직전 행동64+상태8을 받아32개 중간 노드를 거쳐 행동K개를 다룹니다. 총584개를 모두 OCR 글자라고 부르면 틀립니다. 시범을 보고 행동을 배우는 성공과 한국어 전체 명령 이해의 성공은 별개입니다.

### LEVEL 1 · 확정된24차 검사와 납품

기능검사 한 개에서 정해 둔 동작15개를 한 바퀴 실행했습니다. 앱 전체를15바퀴 실행한 결과와 구분합니다. 그림 검사 두 개도 통과했지만, 모든 앱에서의 정확도나 1년 무오류를 확인한 것은 아닙니다.

| 확인 항목 | 실제 결과 | 해석 범위 |
| --- | --- | --- |
| 기능 검사 | 1개 통과, 한 Watch 사이클에서 동작15회·완료1회 | 매크로 전체15사이클의 측정이 아닙니다. |
| 기능 시간 | 사이클4035ms, 측정 전체4629ms | 합성 단일 환경의 관측이며 실제 게임 속도가 아닙니다. |
| 시각 검사 | 2개 모두 통과 | 첫 검사 시범2회·학습256단계·이동 아이콘1회, 완료 뒤 추가입력0회입니다. |

기존 매크로와 디자인을 유지하며 AI는 기본 꺼짐입니다. 작은 오프라인 행동 정책으로, 범용 LLM이 아닙니다. 다른 휴대전화의 실제 가져오기·모든 게임·24시간·1년 무오류 운용과 경량화 완료는 확인하지 않았습니다. 앞선 a7~a16 및 설치·복원 준비의 실패는 보존합니다.

앞의 초기 APK 값과 확인 대기는 당시 기록입니다. 현재 최종 APK SHA-256은 `6b45cc8c7b3dc43bedc1f91811e3de63bd583e22ee3830a9fff2a2cee7f489c6`이며, ZIP SHA-256은 `2f5d0652f960b9b7bdefdf280e426fc37d9302e4bb4f50af35e3535cc8776dcb`입니다.



### 이전 표 문구의 출처 구분

이전 표의 `정상빌드6661/280PASS`는 출처가 미확정인 압축 문구로 인용 보존합니다. 현재 빌드 번호나 검사 분모로 사용하지 않습니다. 현재 확정값은 **정상 빌드13·44클래스280개 단위 검사 통과**이며 실패·오류·건너뜀은0입니다.


현재24차는 글자·직전행동·상태584차원과 RGB 화면 배치576차원을 합친 **1160차원 시각 정책**을 사용하고 구형584차원 모델 읽기를 지원합니다. 앞의584차원 설명은23차 모델의 이력이며 [현재24차 확정표](#current-24-final-level-1)와 구분합니다.
