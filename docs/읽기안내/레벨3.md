## LEVEL 3 · 설치와 매크로 실행 준비

공용 APK는 Android API30 이상, ARM64 또는 x86_64를 대상으로 합니다. 같은 앱 ID와 서명으로 업데이트하는 조건을 확인하고 기존 매크로를 보존합니다. 접근성 권한과 화면 읽기 허용은 실제 장치에서 확인해야 합니다. 매크로 동작·인식 방식·검색 영역·실패 정책·반복·대기를 검토한 다음 대상 앱을 선택합니다. 찾을 글자와 화면이 다를 때 오래된 좌표를 누르도록 임의로 우회하지 않습니다.

저장된 탐지 설정이 없으면 재생을 시작하지 않는 경계를 유지합니다. 목록 글자·우선 영역·실행할 매크로·반복 횟수·진입 확인을 구분합니다. 일시정지는 현재 위치를 유지하며, 새 글자로 다시 시작하는 것은 새 설정으로 처음부터 실행하는 흐름입니다. 완료 횟수와 현재 회차, 실행·대기·중단을 상태 글자로 확인합니다.

## LEVEL 3 · 소스를 빌드할 때 확인할 입력

공개 빌드 안내에 따라 실제 Python·JDK17·Gradle8.13·Android SDK35와 자신의 서명 환경을 준비합니다. 공개 저장소는 개인 키·비밀번호·운영 복원 자료를 제공하지 않습니다. 빌드 스크립트는 일반 작업 폴더를 사용하고 조상 경로의 링크를 거절합니다. PowerShell7에서 해당 차수 source의 빌드.ps1을 실행하며 단위·린트·공용 앱·Android 검사 APK 과제를 유지합니다. **기기 설치·검사는 빌드와 별도**입니다.

정상 빌드10에서 전체 소스 동기화7.921초, 공용 빌드52.234초를 관측했습니다. 제품78,473,602바이트의 SHA-256은6661e8367263de35eb83cb7c4f7d1d417ba382837313543d5da29c8b4830062a입니다. 이 값은 해당 파일 식별용이며 다른 빌드에서 바이트가 같다고 보장하지 않습니다. APK는64MiB 공개 한도를 넘으므로 저장소에는 크기·해시와 재현 소스를 제공합니다.

## LEVEL 3 · 결과와 실패 확인 절차

빌드10의 단위 결과는44클래스·280개·실패0·오류0·건너뜀0입니다. 린트 오류·치명적 오류0개, 경고4개는 보존했습니다. 실행한 과제와 UP-TO-DATE 재사용을 구분해야 하며 빌드8·9의 같은 단위 결과 재사용을 새280회 실행으로 더하지 않습니다. 서명·ABI·CRC·네트워크 권한 부재·필수 클래스 확인은 실제 기기 기능 통과와 다른 항목입니다.

실기에서는 먼저 대상 버전과 검사 선택을 확인하고 성공·실패·미실행을 나눕니다. a7은 응답19개가 통과했지만 재생2개 중1개 실패, a9는15회·18.833초 뒤 복귀 단언 실패, a10·a11은 시각 검사 실패입니다. a12는 진단 APK의 관측이며 일반 제품 결과로 쓰지 않습니다. 설치·증거·복원이 포함된 전체 경과를 매크로 사이클 시간으로 읽지 않습니다.

## LEVEL 3 · 모델과 장기 운용을 평가할 때

AI는 기본 꺼짐이고, 사용자가 확인한 시범·교정만 학습합니다.23차의 시범2회·192단계·자동 터치1회·종료 뒤 입력0과 가져온 뒤 추가64단계는 그 버전의 전용 시험 근거입니다.24차의1160차원 시각 정책은 전체 실기 통과 전입니다. 별도120초 기능 검사의90초 목표와 기존15초 속도 기준을 혼용하지 않습니다. 다른 설치로 이식·실제 SAF 선택·모든 게임·24시간은 미검증이며 중단한 장기 시험을 임의로 재개하지 않습니다.

## LEVEL 3 · 빌드10과 a14 당시의 후속 관측

당시 a14 대상 제품의 전체 선택23개 중22개 통과·1개 실패를 확인했습니다. timeout19와원Float2는통과,Visual은둘째통과·첫째아이콘터치20초대기실패입니다. tests 요약21개에 원문 혼합 결과1PASS/1FAIL을 따로 더해 읽으며 원복true·cleanup없음·전체608.375초를 기능 결과와 구분합니다. a13실패와303.906초원복을보존합니다. 이후 Bridge 선택모드 수리는 호스트GREEN2·SDK PASS이나 당시 새 기기0이므로 해당 결과를 a14와 합쳐 전체 통과로 표시하지 않습니다. 사용자 블루스택 글자 미발견은 추가 조사 중입니다.

## LEVEL 3 · 저장 전에 확인할 실제 입력값

21차 설정을 재현할 때 Macro 기본값 시작번호1·전체 반복1·간격1000ms·시작대기3000ms·최대30분·adaptiveWait=false를 확인합니다. schema1 JSON은 동작1~500, 전체 반복0~100,000, 간격/시작 지연0~600,000ms, 전체시간0~1,440분을 검사하고 활성 Step을 개별 검증합니다. 탐지 반복 기본15회가 전체 반복과 곱해지는 것으로 입력하지 않습니다. Step 초기값 TAP/50·50%/AUTO/CONTAINS/STOP과 duration100ms/after500ms/repeat1/timeout3000ms/retries3/retryDelay1000ms를 저장 전 화면 값과 대조합니다.

좌표는0~100% 유한값, 오프셋±50%, 개별 반복1~1000, 재시도0~100, 재검색 간격300~600,000ms, occurrence1~100입니다. 검색 영역의 순서·정규식·패키지·분기번호가 거절되면 해당 값을 먼저 수정합니다. 계속 기다리기와 즉시 진행은 TEXT_TAP/TEXT_WAIT에서만 사용하며 목록 즉시 진입은 별도 설정입니다. JSON 이름과 UI 설명을 바꿀 때 기존 저장 호환도 확인합니다.

## LEVEL 3 · 기능별 작은 실행을 구성하기

터치 종류는 단일·두 번·길게 누르기, 스와이프·다중 터치·곡선·확대·축소·녹화 경로입니다. 제스처1~20경로/경로당1~512점 한도를 지킵니다. 글자 터치·대기·분기·확인을 쓸 때 비교 일치/포함/정규식, 출처 AUTO/ACCESS/OCR, 실패 정지/건너뛰기/뒤로 재시도/재시도/스크롤 재시도를 각각 선택합니다. TextRules는 NFKC·공백·소문자 정규화와 정규식 검색을 제공하므로 대소문자·띄어쓰기 예를 넣어 예상 비교를 확인합니다.

기본꺼짐 진입 확인을 켠 시험은 목록1~6 우선순위→진입→확인 문구→실행 순서로 확인합니다. 되돌아갈 문구가 동시에 있으면 복귀 우선, 유한 시간 안에 확인 문구가 없으면 뒤로 가서1순위부터 다시 찾습니다. 오진입은 완료와 휴식에 넣지 않습니다. 일시정지 후 계속은 위치를 유지하고 글자를 바꿔 시작하면 새 설정 처음부터인지 확인합니다.

## LEVEL 3 · 저장·캡처·중복 잠금 오류 확인

SharedPreferences JSON 불러오기 실패는 예제 복귀 경로가 있으므로 원본을 먼저 보존합니다. SetupFlow 초안/백업만으로 무손실을 보장하지 않습니다. CaptureRequests 미완료 최대2, QueryLane 동시 읽기 제한, CapturePacer의 응답 후 API30 1.1초/API31+0.5초·간격 거절 최대12초·성공 시 회복을 각각 읽습니다. WatchGate 중복 해제는 연속 부재 두 번 이상과 최소 부재 시간의 결합입니다. 위자드 기본 waitForRefresh=true/preventDuplicate=false를 확인하고 완료 후 쉬기와 중복 해제를 혼동하지 않습니다.

서비스가 안 붙으면 접근성 설정을, OCR 무응답은 캡처/인식 단계·오류·기기 지원을, 좌표 오차는 방향/백분율/영역을 확인합니다. 저장 거절은 Step.validate 시간·좌표·분기, 빌드 실패는 Gradle·Manifest·리소스·SDK·서명 입력, 제어창 소실은 서비스·창 토큰으로 좁힙니다. 최근150줄 일반 로그에는 인식 본문·탐지 문구가 들어갈 수 있습니다. 별도 ErrorJournal128KiB×2는 오류 종류·상태의 순환 기록입니다. 공유할 로그를 직접 확인합니다.

## LEVEL 3 · 실제 Gradle 과제와 산출물 분리

원래14차 Java17/AGP8.9.1/Gradle8.13/SDK35·최소API30·ML Kit 한국어16.0.1을 해당 차수와 대조합니다. 최신 차수의 빌드 안내와 Python·개인 서명 환경을 준비한 뒤 source에서 아래 과제를 실행하는 계약입니다. 이 문서 수리에서 과제를 재실행한 것은 아닙니다.

```powershell
.\gradlew.bat :app:assembleRelease :app:testDebugUnitTest :app:lintDebug :app:assembleReleaseAndroidTest -PNEX_PC
```

공용 선택 -PNEX_PC는 ARM64와 x86_64를 함께 넣습니다. 제품 APK·단위 결과·린트 결과·검사 APK를 구분하고 일반 실제 폴더 사용·서명키 비공개·업데이트 동일서명을 지킵니다. 단위/린트 통과를 기기 실행으로 세지 않습니다.

## LEVEL 3 · 보관 자료를 실행 근거로 읽기

1~3차에서 제어창 분리·녹화/곡선/다중터치/영역보정을,4~5차에서 탐지 루프를,6차에서 최대6영역·대상 앱·중복 잠금·완료 대기·5단계 안내와 임시 녹화를 찾습니다. 8~9차의 별도 읽기/간격 조절과 저장 탐지 설정 없는 재생 거절,10~11차 하단 탐색/카드·창 이벤트 대상 확인·AUTO OCR 전환,12~13차 계속 대기·늦은 결과 폐기·접힌 정지·캡처2/OCR Task1·서비스 종료를 버전별 검사와 묶습니다.

14차 청록·48dp·시스템 모션·글자 소실 뒤 대기 재개/TEXT_NOT_FOUND,15차 인식 방식 노출·간격 회복·탐지 대기 축소·즉시 진입·접기와 전체 OCR 중심점 필터 유지도 각각 확인합니다. 21차 라이트·다크 이미지는 전용Android12 캡처입니다.19차120기기/109단위·20클래스/린트0은 과거 관측이고20차24시간은 중단됐습니다. 최종.json은7개 TEXT_TAP 설정, 실행점검-2차는 별도 점검, 차수 밖 NEX는 보존자료입니다. 앱 버전과 설정 파일을 바꾸어 읽지 않습니다.

## LEVEL 3 · 모델 결과의 원값과 실패 읽기

자연어 Transformer의11/64는 실패한 개발 평가로, 원값17.1875%를 보존하며 새 요약은17.2%(소수 첫째 자리 반올림)입니다. assets0이므로 언어모델이 앱에 탑재된 것으로 실행하지 않습니다. 행동 MLP의 총584입력=글자512+직전행동64+상태8,32중간층,K행동,F64는 다른 과제입니다. 23차192단계·OCR17·터치1·종료후0·동일 설치 별도저장소/새ID 가져오기 추가64·원복30/잔류0을 그 버전에만 대응시킵니다. 최초97 ZIP 실패·수정82/Bundle98도 보존하고 전체207.468초를 매크로 속도로 환산하지 않습니다.

## LEVEL 3 · 빌드12와 a15·a16의 최신 확인 범위

검사 결과를 대조할 때 빌드12의 단위44클래스280개 실제 실행(실패/오류/건너뜀0), 린트 Warning4, 빌드와 산출물 실행기 exit0을 먼저 확인합니다. 새 기기 실행은0이므로 이 빌드의 실제 기능 성공 칸을 채우지 않습니다.

a15 선택23개는22통과/1실패입니다. 응답19·기존재생2·시각둘째1의 통과와 첫 시각의 완료 버튼 null을 별도로 기록합니다. 첫 실패는 이미지 처리20초 초과가 아니라 처리 뒤 단회 탐색 실패입니다. 캡처/OCR5/5·busy=false를 버튼 존재 검사로 대체하지 않습니다. 당시 버튼 bounds/노드가 없어 준비 경합은 미확정입니다. 관리시간523.547초를 사이클 시간으로 사용하지 않습니다.

a16의 기능1PASS와시각1PASS/1FAIL, complete=false/restoration_complete=false를 결과지에서 함께 읽습니다. 복원완료를 표시하지 않고 이전 입력과 빌드12를 분리합니다. 현재 납품 최종은23차이며24차 새실기·최종교체는 PENDING입니다.

제품 파일 식별값은78,473,602바이트·SHA-256 `9c1981f56570923f6ca2b127cf12ebd815207286c9e3dee62ee8947f24183a92`입니다.

현행 reading_levels_gate.py10093바이트 존재를 확인했으나 본작업 gate 통과0입니다. 독립검토·두gate·프로필/프로젝트/차수 같은수준 원격확인을 후속 검증으로 남깁니다. 다른설치·실제SAF·모든게임·24시간·1년은 실행확인되지 않았습니다.

## LEVEL 3 · 원문 납품·보관본의 평가 범위

23차 최종의 공용 APK와 사용 안내를 각각 확인하고 당시 중앙4검사(단위255·언어모델/계획59 포함), Java CPU4·heap512MiB를 과거 결과로 기록합니다. 당시 새 기기·Gradle·지연주입·24시간은 미실행이므로 최신280단위에 더하지 않습니다. 이전21차2.1.0은 기존 배치와 흑백·파란 포인트를 유지한 보관본입니다. 개인 키·프로필·실행 원문·APK·캐시 제외도 확인합니다. MainActivity는 매크로·글자·설정 편집, Macro/Step은 JSON과 검증, MacroService는 접근성 실행, FloatingController는 제어창을 맡습니다. 입력 목록·글자·좌표가 인식/조건/제스처를 거쳐 실제 터치·상태·로그로 나오는 순서를 대조합니다.
