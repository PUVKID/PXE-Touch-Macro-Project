## LEVEL 3 - Practitioner

### LEVEL 3 · 적용 순서와 설정 범위

기존 매크로·목록 탐지·테마 저장 구조를 유지합니다. Android 11 이상에서 기존 앱을 삭제하지 않고 같은 앱 ID와 서명의 APK로 업데이트하는 조건입니다. 실제 APK와 업데이트 보존 검사 결과는 [검증 결과](../../27차/검증_결과.md)를 기준으로 확인합니다.

| 준비·설정 | 적용 범위 | 확인 방법 |
| --- | --- | --- |
| 한글 OCR / 화면 정보 / 자동 | 목록 탐지와 개별 글자 동작 각각 | 이미지에 그려진 글자는 OCR으로 미리보기 |
| 포함·일치·정규식·공백·대소문자 | 현재 검색 조건 | 원하는 문구·유사 문구가 다르게 처리되는지 확인 |
| 계속 기다리기 / 유한 재시도 | 글자 동작 | 부재 시 대기·뒤로·스크롤·정지 정책 확인 |
| 개별 반복 / 탐지 반복 | 한 동작 / 저장 매크로 전체 | 낮은 횟수로 확인한 뒤 목표 반복 적용 |
| 우선 영역·중복·복귀·새로고침 | 목록 탐지 | 같은 글자 재실행 조건과 초·분 단위 확인 |
| 저장본 선택 | 이름 있는 매크로 | 편집 뒤 같은 이름으로 재저장 |

`Adobe`만 찾으려면 OCR·일치·적절한 영역을 선택합니다. `어도비`와 번역·발음으로 연결하지 않습니다. 대소문자 무시 여부도 별도로 확인합니다. 화면 정보는 앱이 제공한 접근성 이름을 읽으므로 보이는 영문과 다를 수 있습니다.

| 하단 상태창 | 주 상태와 시간 정보 사이 간격 | 실제 상태가 바뀔 때 문구 갱신 |

### LEVEL 3 · 결과를 읽는 순서

| 결과 항목 | 현재 상태 | 확정 시 필요한 근거 |
| --- | --- | --- |
| 제품 빌드·정적 검사 | APK 빌드·단위 106개 통과·린트 오류 0·경고 0 | 최종 APK와 검사 결과 대조 |
| OCR 반복·속도 | 75회 성공 · 5구간 평균 9.1초 | 같은 조건의 26차 평균 10.2초와 별도 비교 |
| 60분 연속 운용 | 중단 · 최종 판정 미완료 | 호스트 마지막 표본 247바퀴·OCR 3,705회. 종료 JUnit·호스트 종료 관측 없음 |
| 실제 UI | 검사 메서드 1개 통과·화면 6개 확인 | 같은 값 40회 갱신 시 콜백 1회, 실제 변경 뒤 2회 |
| 캡처 복구 | 검사 메서드 3개 통과 | 해당 검사 조건의 복구 동작 |
| 업데이트 보존 | 26→27 업데이트 설치 성공, 앱 ID·서명·저장 구조 유지 | 16→26 실제 설정 보존 근거 재사용. 모든 사용자 파일 제공자를 새로 재시험한 결과는 아님 |

연속 운용에서 중간에 앱이나 서비스를 재시작하면 단일 연속 실행과 구분해야 합니다. 전용 검사 장치를 사용하며 사용자의 블루스택을 검사 대상으로 조작하지 않습니다. 60분 결과가 확보되더라도 수년간 모든 환경에서 멈추지 않는다는 보장은 아닙니다.

## 설정과 저장을 맞춰 적용하기

공용 APK는 ARM64 휴대전화와 x86_64 에뮬레이터용 코드를 함께 포함합니다. Android 11 이상에서 기존 앱을 삭제하지 않고 업데이트로 설치합니다. 기존 ID·서명을 유지하며 16차의 매크로 JSON, 목록 탐지 설정과 테마를 읽습니다. 별도 AI 시범·행동 모델을 가져오는 기능은 없습니다.

| 설정 | 적용 범위 | 선택 기준 |
| --- | --- | --- |
| 검색 방식 | 각 글자 동작·목록 탐지에서 각각 설정 | 이미지로 그린 게임 문구는 한글 OCR |
| 공백·대소문자·비교 방식 | 현재 글자 조건 | 정확한 문구면 일치, 일부면 포함 |
| 계속 기다리기 | 글자 터치·글자 대기 | 다음 화면이 나올 때까지 기다릴 때 켬 |
| 인식 후 추가 대기 생략 | 완료 후 지연·터치 전 재확인 | 빨라질 수 있지만 화면 변화를 고려 |
| 다음 글자에 맞춰 진행 | 인접한 호환 글자 조건 | 다음 글자의 사전 부재가 확인된 경우 대기 단축 |
| 개별 반복 / 탐지 반복 | 한 동작 / 저장 매크로 전체 | 3회 동작과 전체 15회를 곱하지 않도록 확인 |
| 재시도·뒤로·스크롤 | 글자가 없는 유한 검색 | 횟수와 초를 정하고 종료 정책 확인 |
| 우선 영역·중복·복귀·새로고침 | 목록 탐지 | 동일 문구를 다시 실행할 조건을 정함 |

## 시범을 넣고 결과를 확인하는 순서

1. 가르칠 화면과 행동을 구분합니다.

그림 행동에서는 시범의 OCR·RGB 배치와 아이콘 외형 조각이 함께 근거가 됩니다.

글자 대기 또는 일반 동작을 선택한 경우 이전 이미지 모드가 남아 있지 않은지도 확인할 항목입니다.

| 역할·조건 | 동작과 확인할 내용 |
| --- | --- |
| 확정 시범의 가중치 갱신 | 2. 사용자가 확인한 시범으로 학습합니다. |
| 가중치 확인 | 파일 저장 여부만 보지 말고 정책 가중치 갱신을 별도 근거로 봅니다. |

정책이 하는 일은 등록한 행동의 선택이며 OCR 엔진 자체의 재학습이나 범용 LLM 학습이 아닙니다.

3. 실행 때에는 현재 화면에서 다시 찾은 위치를 확인합니다.

시범 당시 좌표와 같다는 이유로 성공을 판단하지 않습니다.

| 역할·조건 | 동작과 확인할 내용 |
| --- | --- |
| 중복 후보·낯선 화면 | 같은 그림이 겹치거나 새 화면인 경우 입력 없이 기다리는 조건을 확인합니다. |
| 가중치 확인 | 4. 내보내기 자료는 v2 packed의 가중치·시범·행동 사전·RNG·학습 상태를 함께 봅니다. |

저장 형식 검사 결과가 있어도 다른 설치에서 SAF 파일 선택과 가져오기를 실제로 했다는 기록이 없으면 이식 완료로 기록하지 않습니다.

개인 화면·시범·모델은 공개 결과 자료에 넣지 않습니다.

위 순서는 검토할 항목이며 이 문서를 읽는 사용자 환경에서 실제 시험을 마쳤다는 뜻은 아닙니다.

## 지연과 정지를 판독하기

| 작업 종류 | 지연 관측 기준 | 결과 대기 |
| --- | --- | --- |
| 일반 UI | **5초** | 원래 future에서 결과를 받습니다. |
| 제스처 | **65초** | 원래 future에서 결과를 받습니다. |

위 기준을 넘긴 경우에도 **지연 관측과 종료를 구분하십시오.**

24차 설계는 원래 게시한 작업의 **동일 future**를 기다리며 터치·뒤로가기 등을 재전송하지 않습니다.

실제 입력이 이미 전달됐을 수 있으므로 응답을 받지 못했다는 사실만으로 새 입력을 보내면 안 됩니다.

| 역할·조건 | 동작과 확인할 내용 |
| --- | --- |
| 캡처 준비 재시도 | 입력 없는 캡처 준비는 오래된 작업 취소·큐 제거 뒤 새 준비로 확인합니다. |
| 중단 조건 | 관측에서는 정지·권한 해제·서비스 종료·회전·전체 시간 제한이 여전히 적용되는지도 함께 확인합니다. |

영구 무응답 환경의 자동 복구를 수락 기준 충족으로 추정하지 않습니다.



## 24차에서 확인한 결과

단위 검사 280개와 전용 기능 1개·시 각 2개를 확인했습니다.

기능 검사의 동작 15회는 한 Watch 사이클이며 전체 매크로 15 사이클을 뜻하지 않습니다.

최종 APK 지문과 실제 시험의 적용 범위는 [24차 검증 결과](../../24차/검증_결과.md)에 한 번만 정리했습니다.
