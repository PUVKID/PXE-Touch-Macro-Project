`source/theme-engine/Cargo.toml`과 Rust 소스를 보존합니다. Windows 실행 파일은 로컬 생성 산출물이며 공개 소스에서는 먼저 Rust 빌드와 복사 절차가 필요합니다. `tools/generate_astryx.py`는 각 모드에 `--format android --mode <모드>`와 여섯 색상 인자를 전달합니다. 출력 XML의 이름·값을 지정 팔레트와 대조한 뒤 `_light`·`_dark` 접미어를 붙여 `app/src/main/res/values/astryx_colors.xml`의 12색을 생성합니다. Ui의 여섯 색상 함수와 테마·팝업이 이 리소스를 소비합니다. 기존 팔레트와 같은 값이며 성능 개선 측정은 없습니다.

| 공개 반영 | 문서·전체 비교·동일 수준 링크・원격 화면 | 준비 중, 게시 미확인 |

빌드 단계는 Rust 색상 생성 뒤 실제 빌드 사본을 동기화하고 Gradle의 `:app:assembleRelease :app:testDebugUnitTest :app:lintDebug -PNEX_PC`를 실행합니다. 도구 경로·JDK·SDK·서명은 빌드 안내의 환경 변수로 지정합니다. 생성 도구의 프로세스 성공만으로 Android 설치 성공을 단정하지 않으며 단위 검사 수·skipped·오류·경고도 실제 보고서에서 확정해야 합니다.

Graphify의 이전 그래프 수치를 최신 동결 소스의 규모로 쓰지 않습니다. 재시작·HUD·prepareGesture·Main 질의와 실제 소스 대조 및 최종 장식 삭제 뒤 갱신은 완료했고 그래프 수를 검사 개수·성능·기능 완전성으로 환산하지 않습니다. 네 기준 파일의 동일성은 재사용할 수 있으나 새 재시작·진행 위젯·UI의 기기 검사를 대체하지 않습니다. 블루스택과 기본 ADB 서버는 조작 대상에서 제외하고 전용 Android 12 장치를 사용하도록 준비했습니다.

28차 APK는 32,718,940바이트이며 SHA-256과 빌드 결과는 검증 결과에 확정했습니다. 전용 Android12 설치와 UI·제어·OCR 기기 11개 방법은 통과했고 독립 내용·명세 검토와 로컬 패키지 대조를 마쳤습니다. 원격 반영은 게시 커밋과 별도 확인 기록을 따릅니다. 27차 장기 검사의 중단을 PASS로 바꾸거나 새 실행과 합산하지 않습니다. 모든 기기와 미래 입력의 무결함·무중단을 보장하지 않습니다. 결과와 한계는 [검증 결과](../../28차/검증_결과.md), 파일별 변경은 [변경 기록](../../28차/변경기록.md)에서 대조합니다.

### LEVEL 5 · 최신 요구에 따른 구현·평가 범위

| 항목 | 직접 대조한 구현·정의 | 결과 해석 |
|---|---|---|
| 16차 기준 4파일 | WatchConfig·Step·Macro·CapturePacer의 16/26/현재28 SHA-256 동일 | 기본 정의 보존, 실행 속도 실측과 별개 |
| 재시작 | 연결·녹화·설정 검사 → 스냅샷 → 이전 세대 무효화 → 새 실행 | 기존 start/startWatch guard와 새 API를 구분 |
| 메인 제어 | 모든 탭에 paused/running 문구·벡터 제어 | onResume 자동 일시정지 보존 |
| HUD | compact 104×44dp, expanded 너비 280dp·높이 wrap-content | 화면 폭과 실제 측정 높이로 clamp |
| 설정 저장 | hud_x/y·hud_expanded·hud_opacity | 불투명도 40~100%, 기본 95% |
| 표시 문자 | 반복 현재/전체·무한이면 ∞ | 완료한 바퀴 수와 혼동하지 않음 |
| Rust | cargo test 6 passed, release 빌드 로그, 2팔레트 출력 대조 | Windows 빌드 기능, Android 런타임 아님 |

Rust 단위 6개는 대비·혼합·입력 보존·잘못된 인자·두 모드/출력 형식·잘못된 색상 거부를 포함하며 실패·무시·filtered out은 0개입니다. release 컴파일 로그의 38.23초는 해당 Rust 빌드 시간이며 Android 실행 속도나 성능 개선률이 아닙니다. 공개 소스에서 실행 파일은 제외하므로 theme-engine의 빌드 스크립트로 먼저 컴파일하고 target/release/astryx-theme.exe를 theme-engine/astryx-theme.exe로 복사합니다.

초기 범위 Android 단위 106개 통과와 초기 린트 오류 0·경고 12는 이전 입력의 근거입니다. 생성 리소스 전환으로 남은 미사용 기존 색상 12개를 정리했으며, 새 제어·진행 위젯·재시작·장식 제거를 반영한 제품 빌드·최종 린트는 통과했고 UI·제어·OCR 기기 11개 방법은 통과했습니다. 독립 내용·명세 검토와 로컬 소스 묶음 대조를 마쳤습니다. 원격 반영은 GitHub의 해당 커밋과 별도 확인 기록으로 구분합니다. 제거한 장식 OBJ를 읽던 전용 테스트 1개 실패 원문을 보존했고, 제품 참조가 없는 장식 소스·전용 검사 원본을 보존 후 제거했습니다. 장식 전용 4개 검사를 제외한 남은 단위 102개 통과를 확인했으며 매크로 수락 기준을 바꾼 것은 아닙니다. 최신 린트 오류1·경고2의 원인은 줄바꿈 상수·drawable 로딩·미사용 아이콘이었으며 원문을 보존하고 수정 후 오류0·경고0을 확인했습니다. MainControls28Test 3개·Control28Test 6개·Ui28Test 1개·Sustained26Test의 5바퀴 검사1개, 총11개 방법이 실제 통과했습니다. fixture에서 일부 상태를 만든 검사는 모든 제품 화면의 hover/focus/선택/비활성 검증을 뜻하지 않습니다.

최신 Graphify는 707노드·2264연결·31커뮤니티이며 APK 지문은 검증 결과에 확정했습니다. 새 장기 실행은 수행 결과가 없으며 27차의 54.5분 중단 기록은 그대로 보존합니다. 현재 28차는 변경 영향 검증판·준비본이고 기존 26차 최종본을 유지합니다.

각 실행 원문은 INSTRUMENTATION_STATUS_CODE 0과 최종OK(1/3/6/1), INSTRUMENTATION_CODE -1이며 호스트명령 종료코드0과 연결했습니다. JUnit 시간과 앱 내부 경과는 다릅니다. 5바퀴의 누적경과는13,517/26,043/38,401/51,245/64,089ms이고 마지막정지후 전체 65,890ms(65.9초)입니다. 새60분 장기 결과가 아니며 전체 기존 기능의 전수 재실행을 뜻하지 않습니다.

Control 최초2실패 원문은 보존했습니다. 원인은 fixture 설정REGEX 누출과 입력창 표시 전 조회였고 EXACT 초기화·4초 조건 대기 후 검사 APK만 재빌드했습니다. 제품 APK SHA-256은 바뀌지 않아102개 단위와 린트0 근거를 재사용합니다. crash buffer는 조회 당시 비어 있었으며 모든 미래 crash 부재를 보장하지 않습니다. 캡처는 대상폴더 생성 누락으로 첫 ADB pull이 실패한 뒤 폴더를 만들고 26파일 수집에 성공했습니다. 진단 1장을 비공개로 보존·제외한 25장을 정리했고, 잔상 없는 작은/펼친 HUD를 다시 확보해 직접 시각 검토했습니다. 캡처 전용으로 검사 1개를 추가 실행했으며 고유 통과 방법 수 11개에 중복 합산하지 않았습니다. 실제 4장 시각검토와 전체 이미지·모든 상태 검토는 구분합니다. 독립 내용·명세 검토와 로컬 패키지 대조를 마쳤습니다. 공개 상태는 게시 커밋과 별도 확인 기록으로 구분합니다.

| 배포 묶음 | 최종 APK·소스·안내·전체 비교 | 최종 지문·버전·ABI·서명은 확정 결과와 대조 |

라이트 강조색은 `#365F9D`, 다크 강조색은 `#A9C7F5`입니다. 카드 안쪽 세로 여백은 14dp에서 16dp, 모서리는 8dp에서 10dp, 바깥 위·아래 여백은 4/6dp에서 6/8dp로 조정했습니다. RunHud 보조 정보 위에 5dp 간격을 두었습니다. 기존 화면 구성·나눔고딕 Bold와 밝고 어두운 테마 선택을 유지합니다.

`Ui.textIfChanged`는 현재 표시된 문구와 새 문구를 비교해 다를 때만 설정합니다. RunHud의 두 문구와 FloatingController의 상태·재생 문구에 적용하며, MainActivity의 기존 변경 비교도 공통 함수로 모았습니다. 재생 버튼의 접근성 설명과 RunHud의 표시 상태도 같은 값의 재설정을 피합니다. 이런 UI 변경에 별도 성능 개선 수치를 부여하지 않습니다.

최종 APK의 SHA-256은 `a6ce7b3aa3889117a790e0cab33dd6c659253fe010bfa2d625d7222a4dcc85a8`입니다. 실제 UI 검사에서 같은 값 40회 갱신의 문구 콜백은 최초 1회였고, 문구를 바꾸자 누적 2회가 되었습니다. 이는 동일 문구 재설정 방지의 동작 근거이며 전체 속도 향상률은 아닙니다.

호스트 빌드와 겹친 초기 예비 속도값은 최종 비교 수치로 사용하지 않습니다. 같은 장치에서 제품 빌드 없이 별도 속도 비교를 끝냈습니다. 중단된 연속 검사와 새 실행 시간을 합산하지 않았으며 원래 60분 성공 기준도 변경하지 않았습니다. 남은 호스트 원값·메모리 표본·원문 복구 실패·최종 미확인 항목은 검증 결과에서 구분합니다.

단위·정적 검사는 실제 기기 동작의 대체가 아닙니다. 60분 검사는 같은 실행의 연속성을 확인하는 유한 관측이며 재시작을 숨긴 채 같은 실행으로 합치지 않습니다. 사용자의 블루스택 대신 전용 검사 장치를 사용합니다. 성능 향상률·장기 무중단·모든 게임의 인식률은 결과 없이 주장하지 않습니다.

최종 결과와 남은 한계는 [검증 결과](../../27차/검증_결과.md)에, 납품 파일의 지문은 [파일 정보](../../27차/파일정보.json)에 연결합니다. 공개 가능한 코드의 주석·공백을 포함한 실제 차이는 [전체 비교](../revision-audit/27차.md)에서 확인합니다. 문서 저장 자체를 실제 검사나 원격 게시의 증거로 사용하지 않습니다.

## 최종 소스·파일·실행 근거 대조

26차는 16차를 구현 기준으로 선택했고 직전 제품과의 전체 비교도 별도로 남깁니다. 이전 차수의 성능·검사 수를 26차의 결과로 합치지 않습니다. 16차 선택 소스의 보존 해시, 실제 빌드 사본과 기준 소스의 동일성, 버전·ABI·인증서·ZIP CRC와 내장 OCR 자산을 확인했습니다.

| 근거 | 확인 대상 | 해석의 범위 |

최종 APK 지문과 실제 시험의 적용 범위는 [24차 검증 결과](../../24차/검증_결과.md)에 한 번만 정리했습니다.
