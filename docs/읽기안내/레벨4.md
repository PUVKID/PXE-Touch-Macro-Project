## LEVEL 4 · 실행과 비동기 응답의 수명

조회·캡처·OCR은 요청 시점과 완료 시점이 다릅니다. 실행 세대, 일시정지, 창·내용·설정·모델 상태가 바뀐 뒤 도착한 결과는 재확인이 필요합니다.17~19차의 단일 조회·캡처 페이싱·새 화면 재확인과24차의 UI/제스처 연속 대기를 구분해서 읽습니다. 같은 future를 기다리는 동작은 이미 보낸 입력 재전송과 다르며, **입력 없는 캡처 준비만** 취소·큐 정리 뒤 새 준비로 넘어갑니다.

작업 상태를 자주 조회하는 비용도 실행 시간에 들어갑니다. 중복 전체 상태 조회를 줄인 로컬 회귀32개 통과와 실제 Android 전체 지연 원인 확정은 다릅니다. a11의 snapshot 재시작 관측은 전후 상태·시각이 달라진 정확한 조건을 확정하지 못했습니다. 진단 관측이 동시성의 원자적 스냅샷인 것처럼 설명하지 않습니다.

reading_levels_gate.py는10093바이트 현존 파일이며 본작업 통과0입니다. 파일 존재를 독립의미검토나 같은수준 원격앵커 확인과 혼동하지 않습니다. publication/reading_levels 검사와 반영검증, 다른설치/SAF/모든게임/24시간/1년은 미완료 범위입니다.

기존 매크로가 주 기능이며 **AI는 기본 꺼짐**입니다. 23차 시범2회의 전용 관측과 24차 시각 검사의 실패를 구분합니다.

### LEVEL 4 · 확정된24차 검사와 납품

최종 소스는 빌드12 대비 시험 진단 제거와 비공개 운영 기록만 달라졌습니다. 제품 Java 변경은 없고 정상 빌드13의 패키지·서명·권한·CRC 검사와 이전 제품의 payload 동일성으로 실기 근거를 연결합니다.

### 이전 표 문구의 출처 구분

이전 표의 `정상빌드6661/280PASS`는 출처가 미확정인 압축 문구로 인용 보존합니다. 현재 빌드 번호나 검사 분모로 사용하지 않습니다. 현재 확정값은 **정상 빌드13·44클래스280개 단위 검사 통과**이며 실패·오류·건너뜀은0입니다.
