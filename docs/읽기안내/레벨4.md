## LEVEL 4 · 구현 경계와 변경 영향

| 경계 | 구현 | 영향·절충 |
|---|---|---|
| 빌드 시 테마 | theme-engine과 generate_astryx.py | Windows 실행 파일을 호출하며 Android 네이티브 라이브러리로 로드하지 않음 |
| 리소스 소비 | Ui의 bg/card/ink/muted/accent/line | 생성된 6역할×2모드 연결 |
| 상태 배경 | controlStates·ripple·focusRing | 기존 함수 중심으로 pressed/selected/focused/disabled/hovered 처리 |
| 화면 구성 | MainActivity | 간격·카드·목록·입력 라벨, 기존 콜백 유지 |
| 팝업 | styles.xml·nex_dialog_light/dark.xml | 표면색·16dp 반경·목록 높이 일관화 |

메인 화면은 `Ui.java`, `MainActivity.java`, 테마·팝업 리소스와 제어 벡터 아이콘에서 정돈합니다. 일반 메인 버튼은 최소 48dp와 내용에 맞는 높이를 사용하고, 폭이 400dp 미만이거나 fontScale이 1.15를 넘으면 반폭 작업 버튼을 세로로 배치합니다. 공통 버튼의 하드 2줄 제한을 해제했고 한글 폰트 패딩·fallback 줄간격을 적용했습니다. 기존 컨트롤의 접기·이동을 유지하면서 RunHud는 104×44dp의 작은 반복 표시로 새로 구성했습니다.

| 실패 지점 | 처리·확인 | 남는 한계 |
|---|---|---|
| Rust 출력 불일치 | Python에서 지정 팔레트와 정확히 대조 후 실패 | 실행 환경·경로는 재현 시 별도 확인 |
| 잘못된 CLI·색상 | Rust의 인자·색상 거부 단위 검사 포함 | 실제6개 통과, Android 기능 검증과 구분 |
| 빌드·검사 실패 | 하위 프로세스 check=True로 전파 | 성공 로그·종료 코드 결합 필요 |
| 화면 상태 누락 | 기기에서 포커스·눌림·선택 확인 | 정적 코드만으로 전체 표시 보장 불가 |

기존 `nex_soft`와 Android 상태를 사용해 추가 상태를 표현하며 생성기에 없는 색상 이름을 가정하지 않았습니다. 나눔고딕 Bold700과 저장된 테마 선택을 유지합니다. React 컴포넌트나 별도 행동 AI를 Android 앱에 설치하지 않았습니다. MLKit 한글 OCR·전체 화면 입력·캡처 동시 작업 제한·오래된 결과 폐기 정책은 유지합니다. MacroService는 재시작 API와 반복 수 공급을 위해 변경했으며 서비스 전체가 불변이라는 초기 범위의 설명은 현재 소스에 적용하지 않습니다.

Graphify의 초기 28차 로컬 code-only 질의 근거는 보존하며, 새 실행 제어·진행 위젯과 장식 삭제 후 최종 갱신은 707노드·2264연결·31커뮤니티입니다. 캐시29개 재사용·1개 갱신·1개 삭제를 반영했습니다. 그래프는 변경 위치를 조사하는 자료이며 연결 전부가 런타임 실행을 의미하지 않습니다. 실제 소스 대조와 별도 검사 결과를 함께 해석합니다. 그래프와 내부 조사 기록은 공개 산출물에 섞지 않습니다.

현재 MacroService는 27차와 다릅니다. 검증 후 새 세대로 재시작하는 API와 반복 수·실행 세대 공급을 추가했습니다. 반면 WatchConfig·Step·Macro·CapturePacer 네 파일은 16차·26차·현재 28차의 SHA-256이 모두 같습니다. 이 네 파일의 동일성을 서비스 전체나 성능 동일성으로 확대하지 않습니다. 이전 최종 26차·준비본 27차를 보존하고 28차 검증 완료 전 최종본 교체를 선언하지 않습니다.

### LEVEL 4 · 서비스·단축창·위젯의 새 경계

| 파일·경계 | 실제 변경 | 보존 조건 |
|---|---|---|
| MacroService.restart / restartWatch | 연결·녹화·설정·선택 매크로 검증 뒤 stop/start | 불량 입력에서 기존 실행 보존, 스냅샷 복사 |
| MainActivity | 네 탭 실행바·새 실행 호출·장식 제거·wrap 배치 | 기존 설정 항목·저장 구조·자동 일시정지 유지 |
| FloatingController.wordDialog | 실행 중 임시 일시정지·검증 후 적용·취소 원복 | 동일 runRevision과 원래 상태 확인 |
| RunHud | 작은 반복 수·드래그·화살표·상세·불투명도 | 화면 크기 변화 시 위치 제한 |
| prepareGesture | 기존 컨트롤과 HUD 실제 창 경계의 경로 충돌 | 겹치는 자동 입력 전에 overlay 숨김 |

사전 코드 검토에서 자동 터치와 새 HUD의 충돌, 화면 크기 변경 뒤 HUD 위치 제한 누락, 잘못된 글자 입력이 설정에 먼저 저장되는 문제 세 가지를 확인해 수정했습니다. 원인은 새 위젯 경계가 기존 충돌 검사에 포함되지 않은 점, 초기 배치 이후 크기 변화를 반영하지 않은 점, 검증보다 저장이 먼저였던 순서입니다. 전용 Android12의 대응 검사 방법은 통과했습니다. 모든 기기·미래 입력의 전체 재현 완료로 확대하지 않습니다.

16차·26차·현재 28차의 네 기준 파일 동일성은 직접 SHA-256으로 확인했습니다. 기본 설정 유지와 새 실행 제어 수리는 구분합니다. 학습형 행동 AI·ONNX 경로는 추가하지 않으며 MLKit OCR은 유지합니다. 3D PxeModelView 장식과 관련 사용 경로를 제거했지만 이를 AI 학습 제거로 설명하지 않습니다.

Control 최초6개 중2개 실패는 fixture의 word_match=REGEX가 다음 검사에 남은 점과 다이얼로그가 나타난 직후 창을 조회한 검사 타이밍에서 발생했습니다. 테스트 시작 때EXACT를 명시하고 입력창이 나타날 때까지 최대 4초 조건 대기로 수정했습니다. 진단 화면에서 실제 대상 존재를 확인했으며 추정으로 제품 코드를 바꾸지 않았습니다. 제품 APK는 같은 지문이고 검사 APK만 재빌드한 뒤 6개 모두 통과했습니다.

## LEVEL 4 - Advanced

### LEVEL 4 · 캡처 대기의 변경 경계

27차는 16차 기반 실행 구조와 직전 제품의 인식·취소 정책을 이어갑니다. 캡처 간격을 줄이거나 OCR 입력을 축소하는 대신, 캡처 전 두 대기를 함께 진행하도록 순서를 바꿉니다. 화면 품질·검색 조건·저장 모델 변경과 분리된 수정입니다.

| 부분 | 27차 변경 | 유지한 조건 |
| --- | --- | --- |
| 캡처 준비 순서 | 컨트롤 숨김 안정화와 pacer 대기를 겹침 | 각각의 마감 시점까지 대기 |
| Android API 30 이하 | 간격 값 변경 없음 | **1100ms** |
| Android API 31 이상 | 간격 값 변경 없음 | **500ms** |
| 숨김 안정화 | pacer와 함께 기다림 | **150ms** |
| OCR 입력 | 전체 화면 유지 | 영역 자르기·다운샘플링 없음 |
| 인식·검색 구성 | 기존 모델·조건 재사용 | 새로운 AI·의존성 없음 |

두 대기 조건을 함께 충족하는 시점이 캡처 가능 시점입니다. pacer 대기가 남아 있으면 그동안 숨김 안정화도 진행됩니다. pacer 대기가 거의 없더라도 150ms 안정화는 건너뛰지 않습니다. 실제 총 소요 시간에는 OCR 계산·화면 변화·제스처·기존 설정 대기가 함께 포함되므로 대기 순서만으로 전체 개선량을 확정하지 않습니다.

### LEVEL 4 · UI의 수정 위치와 역할

| 파일 | 변경 | 경계 |
| --- | --- | --- |
| `Ui.java` | 공통 팔레트 리소스 참조·변경 시 문구 설정 함수 | 테마 판단·글꼴·인식 이름 유지 |
| `RunHud.java` | 상태·시간 중복 설정 방지·보조 정보 간격·표시 상태 비교 | 캡처 중 숨김·터치 비간섭 유지 |
| `FloatingController.java` | 상태·재생 문구와 접근성 설명의 중복 설정 방지 | 버튼 동작·마커 갱신 정책 유지 |
| `MainActivity.java` | 상태창 함수 통일·카드 여백·연결·탐색 선택 표시 | 화면 구조·메뉴·기능 유지 |
| `values/nex_colors.xml` | 라이트·다크 공통 14색 | 기존 런처 배경 리소스 보존 |
| `values/styles.xml` | 테마·대화상자가 공통 색상 참조 | 기존 테마·글꼴 유지 |
| `drawable/nex_dialog_dark.xml` | 다크 팝업 배경 색상 참조 | 기존 팝업 형태 유지 |
| `drawable/nex_dialog_light.xml` | 라이트 팝업 배경 색상 참조 | 기존 팝업 형태 유지 |

상태 갱신은 250ms 주기를 유지하고 실제 문자열이 같은 경우에만 `setText`를 생략합니다. 지표를 덜 읽거나 정지·일시정지 처리를 늦추는 변경은 아닙니다. FloatingController의 마커 캐시나 실행 엔진 구조를 UI 수정과 함께 재설계하지 않았습니다.

### LEVEL 4 · 실패·취소 정책

| 상태 | 유지한 처리 |
| --- | --- |
| 대상 앱 불명확 | 입력하지 않고 대상 재확인 |

## 조회·인식·실행 수명 관리

제품은 16차의 Java View UI와 MacroService 실행기, JSON 모델·저장소, GesturePaths·FloatingController를 기반으로 합니다. UI와 리소스를 새 디자인으로 바꾸지 않고 버전 표시만 실제 설치 버전에서 읽습니다. 시범 학습·행동 모델·ONNX 의존성은 포함하지 않습니다.

| 부분 | 26차 변경 | 유지한 경계 |
| --- | --- | --- |
| TextRules.Prepared | 검색어 정규화·정규식 컴파일을 한 탐지에서 재사용 | 포함·일치·정규식·대소문자 옵션 |
| Unicode 공백 | code point로 공백·ZWS·BOM을 선택 제거 | 공백 무시를 끄면 공백 보존 |
| 창 조회 QueryLane | 진행 중 조회 하나를 기다리고 추가 요청 누적 방지 | 실제 오류를 글자 부재로 바꾸지 않음 |
| 창 응답 시한 | 무한 대기는 계속 대기, 유한 동작의 실제 창 대기만 제한 | 정상 OCR 전체에 절대 시한을 씌우지 않음 |
| 취소·일시정지 | generation·pauseRevision·activeTime 확인 | 이전 응답으로 입력하지 않고 일시정지 시간 제외 |
| R8·리소스 축소 | 미사용 의존성과 리소스 제거 | 자체 앱·공유 프레임워크·OCR 공개 API·반사 대상 보존 |

### 대기·취소의 구현 조건

| 구분 | 적용 내용 |
| --- | --- |

| 일시정지 세대 | pauseRevision이 달라지면 이전 응답을 폐기하고 재개 후 새 창을 확인합니다. |
| 취소 불가 조회 | 취소 불가능한 플랫폼 조회가 남아 있어도 큐에 계속 새 요청을 추가하지 않습니다. |

### OCR 보존과 실패 정책

| 구분 | 적용 내용 |
| --- | --- |
| 결과·필터 유지 | OCR은 기존 전체 화면과 결과 캐시·영역·순번 필터를 유지합니다. |
| 화면 품질 유지 | 영역을 잘라 품질을 낮추거나 오래된 화면을 임의로 재사용하지 않습니다. |
| 실제 오류 보존 | 실제 보안상 캡처 거부나 서비스 종료는 중단 원인으로 남습니다. |
| 장기 운용 해석 | 26차의 제한된 검사 표본으로 모든 환경의 무한 운용을 보장하지 않습니다. |

현재 제품은 **26차 · 2.6.0**입니다. 단위 106개와 최종 축소 APK 기기 검사 89개를 확인했습니다. 오류·취소·보존·미확인 범위는 [검증 결과](../../26차/검증_결과.md)에 구분합니다.

## 정책 입력과 실행 권한의 경계

| 역할·조건 | 동작과 확인할 내용 |
| --- | --- |
| 정책 확인 | 24차는 OCR 글자만 쓰던 선택형 정책에 화면 외형을 추가합니다. |
| 정책 입력과 선택 | 기존 584 →32 →K F64 MLP 읽기를 유지하면서 시각 정책은 OCR·이전 행동·상태 584차원과 RGB 배치 576차원을 결합한 **1160차원 입력**을 사용합니다. |
| 매크로와 선택형 AI | 기존 매크로가 주 경로이고 AI 는 기본 꺼짐입니다. |

새 정책의 존재가 일반 매크로 실행에 AI 사용을 요구하지 않습니다.

설계에서 구분할 출력은 행동 선택과 위치 결정입니다.

확정 시범으로 갱신한 정책이 이미지 행동을 선택해도 저장 좌표를 바로 실행하지 않습니다.

| 역할·조건 | 동작과 확인할 내용 |
| --- | --- |
| 현재 위치 결정 | 시범의 외형 조각을 현재 관측에서 다시 찾아 위치를 결정하며 중복 후보·낯선 화면은 무입력 대기로 처리합니다. |
| 입력과 처리 | OCR·RGB 배치·외형 조각의 역할을 합치면 ‘시범을 기억했다’는 상태가 ‘현재 입력을 승인했다’는 의미로 잘못 확장됩니다. |
| 동작 모드 분리 | 이미지·글자 대기·일반 동작 선택 사이의 모드 수명도 별도 경계입니다. |

<a id="level-4--모델-직렬화의-책임"></a>

## 모델 직렬화의 책임

| 역할·조건 | 동작과 확인할 내용 |
| --- | --- |
| 모델 형식과 호환 | v2 packed는 F64 가중치뿐 아니라 행동 사전, 시범, RNG와 학습 상태를 결합합니다. |
| 가중치 확인 | 예측 재현과 추가 학습 재개는 필요한 상태가 다르므로 가중치만의 왕복으로 전체 계약을 판단할 수 없습니다. |

구형 584호환과 신규 1160 정책을 각각 검사해야하며, 파일 형식 검증은 다른 설치의 SAF 선택·가져오기·실행 프로토콜을 대신하지 않습니다.

개인 시범·화면·모델은 공개 소스와 분리합니다.

<a id="level-4--지연-정책의-상태-전이와-절충"></a>

## 지연 정책의 상태 전이와 절충

| 역할·조건 | 동작과 확인할 내용 |
| --- | --- |
| 일반 UI | **5초**를 종료 기준이 아닌 **지연 관측 기준**으로 둡니다. |
| 제스처 | **65초**를 종료 기준이 아닌 **지연 관측 기준**으로 둡니다. |
| 원요청의 정체성 | 기준 변경의 핵심은 **원요청의 정체성을 유지**하는 것입니다. |
| 원요청 결과 대기 | 동일 future를 기다리면 뒤늦은 완료를 기존 요청의 결과로 받습니다. |

전달 여부가 불확실한 입력을 재전송하는 정책은 중복 동작 가능성을 만들므로 사용하지 않습니다.

| 역할·조건 | 동작과 확인할 내용 |
| --- | --- |
| 캡처 준비 재시도 | 캡처 준비는 입력 없는 작업으로 분리돼 오래된 작업 취소·큐 제거 후 다시 시도합니다. |
| 재시도 분리의 이유 | 이 차이는 단순히 제한시간을 늘리는 것보다 중요한 재시도 경계입니다. |
| 중단 조건 | 사용자 정지·권한 해제·서비스 종료·회전·전체 실행 기한은 계속 검사합니다. |

영구 무응답에서 진행 보장은 없으며, 지연 지속과 사용자 중단 가능성을 함께 유지해야 합니다.



## 24차에서 확인한 결과

단위 검사 280개와 전용 기능 1개·시 각 2개를 확인했습니다.

기능 검사의 동작 15회는 한 Watch 사이클이며 전체 매크로 15 사이클을 뜻하지 않습니다.

최종 APK 지문과 실제 시험의 적용 범위는 [24차 검증 결과](../../24차/검증_결과.md)에 한 번만 정리했습니다.
