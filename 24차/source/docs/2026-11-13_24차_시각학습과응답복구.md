# 24차 화면 이미지 학습과 응답 복구

확인일: 2026-11-13. 기존 디자인과 매크로를 유지하며, 선택형 AI에 그림·아이콘·화면 배치를 함께 가르치고 실행할 수 있도록 확장합니다. 경량화는 검토만 하며 이번 배포에서 기능이나 의존성을 제거하지 않습니다.

## 확인한 문제와 구현 경계

23차 관측은 글자 특징 512개, 직전 행동 64개, 상태 8개로 이루어져 있습니다. 글자 없는 그림은 행동 근거로 사용할 수 없었습니다. 시범의 화면 이미지와 누른 이미지 조각을 함께 보존하고, 현재 화면에서 다시 찾은 위치를 사용합니다. 화면 저장 자체를 장면 이해나 범용 LLM 학습이라고 부르지 않습니다.

캡처 준비의 UI 응답 대기가 캡처 복구 범위 밖에 있습니다. 제어한 지연으로 결함을 재현한 뒤 읽기 준비에 한해 복구하고, 늦게 도착한 입력과 대기 큐 누적을 막습니다. 실제 터치·뒤로가기 등 결과가 모호한 입력은 무조건 재전송하지 않습니다. 권한 해제·서비스 종료·사용자 정지는 계속 구분합니다.

## 개인정보와 한계

개인 화면·시범·개인 모델은 로컬 비공개이며 공개 저장소에 올리지 않습니다. 기존 매크로가 주 기능이고 AI는 기본 꺼짐을 유지합니다. 사용자의 블루스택·게임을 조작하지 않고 소유 검증 환경만 사용합니다. 1년 실제 운용이나 모든 화면의 정확도를 측정하지 않았으므로 무오류·장기 운용 성공을 보장하지 않습니다. 중단된 24시간 검증은 재개하지 않습니다.

## 일반 화면 작업과 제스처의 지연

기존 일반 UI 작업은 5초, 제스처 완료는 65초를 넘으면 시간 초과로 실행을 끝냈습니다. 이 두 값은 종료 제한 대신 지연 상태를 알리는 관측 기준으로 사용합니다. 원래 게시한 작업과 같은 future의 실제 결과를 기다리고, 응답이 늦다는 이유로 터치·뒤로가기·입력을 재전송하지 않습니다.

입력이 없는 캡처 준비는 별도의 제한된 시도로 구분하고, 오래된 준비 작업을 취소·큐에서 제거한 뒤 새 준비를 시도합니다. 정지·권한 해제·서비스 종료·화면 잠금·회전 변경과 사용자가 정한 전체 실행 시간 제한은 계속 확인합니다. 시스템이 영구적으로 응답하지 않을 때 진행을 보장하는 것은 아니며, 대기 이유를 표시하고 사용자가 중단할 수 있어야 합니다.

JVM의 제어된 시각에서 UI6001ms·제스처65001ms로 기존 종료를 먼저 재현했습니다. 실제 Android의 지연 주입 결과와 이 가상 시간 검사는 별도로 기록합니다. 기존 실패 원문은 후속 통과로 지우지 않습니다.

## 후속 대조

새 응답 대기 함수의 결과 수신 직후와 대기 poll 뒤에 전체 시스템 상태 조회가 중복 추가된 점을 확인했습니다. 두 위치만 토큰·연결·기한 확인으로 바꾸고, 기존 루프 진입과 실제 입력 직전의 화면·잠금·회전 확인을 유지했습니다. 제어된23개 검사는 구현자와 별도 검증자가 각각 통과했습니다. 실제 기기에서15회·15초 검사에 미치는 효과는 재검사 전이며 속도 개선 수치를 만들지 않습니다.

화면 정보 탐색의 깊이70·항목2000·내부2500ms 한도는 기존 일반 예외로 처리되어 명시 화면 정보 모드에서 종료될 수 있었습니다. 이 일시 읽기 예산만 전용 예외로 구분해 기존 복구 경로에 포함하고 취소를 분리했습니다. 원래 탐색 한도와 불완전 결과의 입력 금지는 유지합니다. 신규9개와 기존23개 검사는 통과했으며 실제 Android 재검사는 별도로 진행합니다.
