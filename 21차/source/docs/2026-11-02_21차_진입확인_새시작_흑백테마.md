# 21차 · 진입 화면 확인, 새 글자로 시작, 흑백 테마

## 사용자 요구와 기준

사용자는 이미지 시안 제작을 취소하고 기존 앱 화면 구조를 유지하라고 정정했습니다. 최신 요청은 기존 디자인의 색감을 블랙·화이트와 포인트색으로 정돈하는 것입니다. 새 이미지 10개·전면 재배치는 수행하지 않습니다. 기능 기준은 제품19차이며20차는 사용자가 중단한 장기 시험 자료입니다.20차 중단을 해제하거나24시간 시험을 재개하지 않습니다.

## 실행 요구와 성공 조건

- 목록 글자를 눌러 진입한 뒤, 사용자가 정한 확인 글자를 지정 영역에서 읽습니다. 기대 글자가 있으면 기존 매크로·반복을 실행합니다. 확인 글자가 정한 시간 동안 없으면 뒤로 가고1순위부터 목록 탐지를 다시 시작합니다.
- 원래 요청의 `사과가 보이면 뒤로가기 / 배가 보이면 매크로`는 확인 글자와 선택적인 되돌아갈 글자로 설정할 수 있게 합니다. 되돌아갈 글자를 명시한 경우 해당 글자의 존재를 우선 확인합니다. 둘 다 없으면 설정한 확인 시간 뒤에 복귀합니다.
- 새 진입 확인은 기본 꺼짐입니다. 기존 저장 프로필의 동작·글자·영역·1~6순위·15회 반복·대기·녹화·중복 방지·실행 기록을 유지합니다. 확인 영역은 목록 탐지 영역과 독립적이며 기본 전체 화면, 비교 기본 정확히 일치, 확인 시간 기본3초로 제공합니다. 시간은 초 단위로 표시·편집합니다.
- 잘못 진입한 항목에서는 매크로를 한 번도 시작하지 않고 완료 횟수도 늘리지 않습니다. 정상 완료 후의 긴 쉬는 시간을 잘못 진입한 경우에 적용하지 않습니다. 뒤로가기 후 목록의1순위부터 다시 확인하며 기존 영역별 중복 예약·해제 조건은 유지합니다. 확인 실패를 이유로 전역 중복 잠금을 무조건 지우지 않습니다.
- OCR·창 조회 실패와 정상 화면에서의 글자 부재를 구분합니다. 읽기 실패·대상 앱 변경·권한·보안 문제를 글자 없음으로 취급하여 뒤로가지 않습니다. 기존 복구·세대·일시정지·전체 제한·대상 보호를 유지합니다.
- 기존 일시정지·계속 실행 기능을 앱과 제어창에서 명확하게 사용할 수 있게 합니다. 일시정지 중에는 터치·뒤로가기·스크롤·분기 실행을 전달하지 않고, 계속 실행은 기존 위치에서 이어갑니다. 확인 시간은 일시정지 시간을 소비하지 않도록 기존 활성 시간 경계를 사용합니다.
- 실행 중에도 찾을 글자를 변경하고 시작을 누르면 새 설정을 검증한 다음 이전 실행 세대를 취소하고 새 설정의1순위부터 실행합니다. 사용자가 정지 버튼을 먼저 누를 필요가 없습니다. 기존 실행의 늦은 OCR·창 결과·완료 callback·finally가 새 실행을 중단하거나 통계·설정·중복 상태를 덮어쓰지 않아야 합니다. 새 설정이 잘못됐으면 기존 실행을 먼저 취소하지 않습니다.
- 앱의 시작은 새 설정으로 처음부터 실행, 일시정지·계속 실행은 현재 위치 유지라는 차이를 버튼 문구로 설명합니다. 녹화 중 실행 금지와 기존 설정 검증은 유지합니다.

## 시각 범위

기존 네이티브 Java Views, 하단4탭·화면 구조·작은 접이식 진행창·실제 OBJ 모델과 상태 연결·나눔고딕 Bold700·최소48dp 조작 영역을 유지합니다. 새 시안의 화면 이미지를 앱 UI 대신 붙이지 않습니다.

- 라이트: 바탕#FFFFFF, 글자#111114, 보조 바탕#F4F5F7, 선#DFE1E6, 포인트#245CDB.
- 다크: 바탕#101114, 글자#F5F5F7, 보조 바탕#1B1C20, 선#393B43, 포인트#8BAEFF.
- 상태는 색 외에 문구·아이콘으로 구분합니다. 파란색은 주 행동·선택 상태에 집중하며 실제 오류·정지의 의미는 유지합니다. 포인트색을 사용한 버튼의 글자 대비를 확인합니다.
- 홈·조건 설정·동작 편집·안내·설정·제어창·영역 선택·OBJ 재질 등 앱 소유 화면의 공통 토큰을 일관되게 적용합니다. 불필요한 굵은 테두리·큰 장식·중복 설명을 줄이되 기존 기능 진입점을 제거하지 않습니다.

## 구현과 검증 계획

1. 보존한19차에서21차/source와 실제 일반 폴더work/build21/source를 준비합니다. 새 연결·정션·심볼릭 링크를 만들지 않습니다. versionCode21/versionName2.1.0, 앱ID와 기존 서명을 유지합니다. 기존 키 원문을 수동으로 읽거나 복사하지 않습니다.
2. 현재 진입·일시정지·실행 중 시작 처리와 기존UI를 조사합니다. 새 설정 기본값·JSON 왕복·입력 검증·조건 결정·재시작의 늦은 결과 보호를 실패 경로부터 검사합니다. 기능과 무관한 구조 변경은 하지 않습니다.
3. 진입 확인·복귀·새 시작과 간단한 설정을 구현하고 기존 일시정지를 노출합니다. 주석은 변경한 범위에서 한국어로 씁니다.
4. 기존 단위·기기 검사와 새 집중 검사를 보존합니다. 제어된 검사와 실제 캡처·OCR 검사를 구분합니다. 새 테스트는 정상 진입/명시한 잘못된 글자/시간 내 부재/읽기 지연 구분/일시정지·정지/새 글자 시작과 늦은 결과를 다룹니다. 사용자 플레이어는 조작하지 않고 소유Android31 AVD·ADB5043만 사용합니다.
5. 기존 라이트·다크의 실제 화면과 새 팔레트를 대조하고 작은 화면·긴 글자·IME·접힌 진행창을 확인합니다. 움직이는 UI를 정지 이미지로 대체하지 않습니다.
6. PC용ARM64+x86_64, 노트10+용ARM64 APK를21차에 저장하고 앱ID·버전·기존서명·ABI·CRC·19차160항목 보존을 확인합니다. 장기 시험은 수행하지 않습니다. 필요한 기능·회귀 검사만 제한된 시간에 실행하고 시험기기를 정리합니다.
7. 소스 동결 후 별도verifier가 요구·새 집중 동작과 중앙3검사를 직접 대조합니다. 공개 가능한 소스·설명·실제 전체 비교를 현재GitHub 양식에 반영하고 원격ref·tree·링크와publication_gate를 실제 확인합니다.20차의 중단 상태와 공개 반영 대기는 성공으로 바꾸지 않습니다.

중앙3검사는 단위30초·엄격UTF8 15초·APK/보존30초, 합계75초입니다. 필수 기기 검사 상한은 실제 계획을 확인하고 기존 기준을 임의 완화하지 않습니다. 실제 사용자 블루스택·게임·실폰의 성능이나24시간 안정성을 이 검사로 보증하지 않습니다.
