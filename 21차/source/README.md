# PXE 21차 · 2.1.0

Android 접근성 서비스와 ML Kit 한국어 OCR로 글자 조건·터치·제스처 매크로를 실행합니다. 앱 ID와 저장 형식은 유지하며 기존 설치 앱과 같은 개인 서명으로 만든 APK만 덮어 업데이트할 수 있습니다.

## 진입 화면을 확인한 뒤 실행

탐지 홈의 **진입 화면 확인**에서 켤 수 있습니다. 기본은 꺼짐이며 기존 프로필은 원래 방식으로 실행됩니다. **매크로를 실행할 글자**가 보이면 기존 매크로를 실행하고, 설정한 시간 동안 없으면 매크로 없이 뒤로가서 목록의1순위부터 다시 찾습니다. **뒤로갈 글자 · 선택**을 입력하면 해당 글자를 우선 확인합니다. 예를 들어 사과는 뒤로가기, 배는 매크로 실행으로 설정할 수 있습니다.

확인 영역은 목록 영역과 독립적이며 기본 전체 화면·완전 일치·3초입니다. 시간은 초 단위로 편집합니다. 잘못 진입한 항목은 매크로와 완료 수를 늘리지 않고 완료 후의 긴 대기도 적용하지 않습니다. 기존 영역별 중복 예약은 유지하며 확인 실패만으로 전역 잠금을 지우지 않습니다. 화면을 못 읽은 오류·대상 앱 이탈·일시정지는 정상 글자 부재와 구분하고 새 화면으로 다시 확인합니다.

## 새 글자로 시작과 일시정지

실행 중 글자를 바꾸고 시작 버튼을 누르면 새 설정을 먼저 검증하고 이전 실행을 취소한 뒤 새 설정으로 시작합니다. 탐지는1순위부터 시작하며 정지를 먼저 누를 필요가 없습니다. 새 입력이 잘못됐으면 기존 실행을 유지합니다. 이전 실행의 늦은 OCR·조회·완료와 화면 복원이 새 실행을 덮지 않도록 실행 세대를 대조합니다. 실제 미완료 OCR·캡처를 초기화해 작업을 쌓지 않습니다.

앱과 접힌 제어창에 **일시정지 / 계속 실행**을 표시합니다. 계속 실행은 현재 위치를 이어가고, 시작 버튼은 새 실행을 만듭니다. 확인 시간은 일시정지 동안 소비하지 않습니다. 녹화 중 실행 금지와 대상 앱·권한·전체 제한·기존 반복·영역·저장 기능을 유지합니다.

## 기존 구조와 흑백·파란색 화면

기존 네이티브 화면·하단4탭·실제 OBJ 모델·작은 진행창·나눔고딕Bold700을 유지합니다. 바탕과 보조 영역은 흑백 계열로 정돈하고 주 동작과 선택에 파란색을 사용합니다. 라이트와 다크·320dp 작은 화면의 실제 기능 화면을 확인하며, 하단 동작과 긴 설정은 스크롤로 접근합니다. 새 이미지 시안 제작과 전면 재배치는 취소된 요청입니다.

새 집중 명세는 [entry-check-plan.json](tools/entry-check-plan.json)의 기본23개·작은 화면5개입니다. 긴 OCR·캡처 복구 후 정상 화면을 읽은 시점부터 확인 시간을 다시 보장하며, 실제 키보드를 연 상태에서도 진입 설정의 저장·취소를 조작하도록 새 설정창을 조정합니다. 여러 번 뒤로가는 도중 일시정지해도 이미 수행한 복귀 횟수를 유지하고, 연결 해제 직후 남아 있던 정지 버튼도 처리합니다. 기존120개 기기 회귀의 검사와 상한은 유지합니다.21차는19차 제품을 기준으로 한 새 요청이며, 사용자가 중단한20차 장기 시험을 재개하지 않습니다.24시간·장기 시험과 선택 성능 비교는 실행하지 않습니다.

## 유지한19차 대상 창 확인의 복구와 실제 상태

개별 창 조회만 취소된 경우에는 현재 실행 세대·서비스 연결·전체 기한을 먼저 확인하고 새 창 조회로 복구합니다. 이미 적용한 단일 조회 및 늦은 결과 폐기는 유지합니다. 중단·연결 해제·전체 최대 시간과 실제 권한 오류를 임의 재시도로 바꾸지 않습니다. 복구 중에는 하단에 **복구 대기 · 정지 가능**이 표시되며 현재 동작과 완료7/15회·8회째 같은 진행 수를 유지합니다.

오류 기록에는 실제 설치 버전과 제한된 예외 타입을 남깁니다. 검색 원문·화면·예외 메시지를 새 진단 필드에 추가하지 않습니다. 기존 기록은 삭제하지 않습니다. 같은 지연을 처리하던17·18차의 안전 복구는 유지합니다. 새 제어 검사에서 확인한 조회 취소/표시 결함과 사용자가 기억한 과거 지연 문구의 실제 원인은 구분합니다. 과거 설치 버전과 원본 오류 스택은 확보하지 않았습니다.

실제 수락한 활성·초점 창의 식별이 바뀌면 기존 터치 허가도 폐기합니다. 창 이벤트가 아직 도착하지 않아도 이미 관측한 앱 전환을 반영하며 메인 스레드에 새 동기 창 조회를 추가하지 않습니다. 조회 순번·실행 세대·일시정지 세대를 대조해 취소된 결과나 더 새로운 조회보다 늦은 결과가 관측 상태를 덮지 않습니다. Android의 창 전환과 제스처 전달을 완전히 원자적으로 묶는 기능이나 아직 관측하지 못한 모든 전환의 차단을 보장하지 않습니다.

기준 소스와 별개 실제 빌드 폴더를 사용하며 빌드 전 선택한 모든 파일의 원문·해시를 대조합니다. 새 바로가기·정션·심볼릭 링크를 만들지 않습니다. 새 집중 계약은 tools/target-window-check-plan.json의6개이며 기존114개 기기 및104개 단위 계약을 보존합니다. 실제 최종 결과는 납품 폴더의 검증 문서를 따릅니다.

19차의 관측 순서 단위5개를 포함한 기존109개와21차 설정 호환·검증6개로 현재 단위 계약은115개입니다. 선택적 성능 비교 도구는 과거18→19차 명세로 보존하며21차 기능 검증에서 실행하지 않습니다.

## 작은 진행창과 명확한 반복 횟수

하단 진행창은 완료7/15회와 현재8회째를 구분하고 현재 동작을 짧게 표시합니다. 실제 전체 반복이 끝난 후에만 완료 횟수를 올리며, 개별 동작 반복 및 목록 탐지 바퀴와 혼합하지 않습니다. 다음 목록 항목에 진입하면0부터 다시 셉니다.

진행창을 한 번 누르면200dp·48dp의 작은 한 줄 표시로 접고 다시 누르면 펼칩니다. 펼침 폭은280dp이며 이번·직전 한 바퀴와 전체 경과 시간은 보조 두 줄에 남습니다. 접기 선택은 실행 중 갱신과 캡처·일시정지·새 실행에도 유지됩니다. 긴 문구는 화면에서 줄임 표시하고 기존 전체 실행 기록은 보존합니다. 자동 터치와 녹화 재생이 진행창에 가로채이지 않도록 겹치는 제스처와 녹화 중에는 숨깁니다. 기존 위쪽 정지 버튼은 그대로 사용합니다.

인식·실행 순서·저장 설정·수동 제스처를 바꾸지 않은 표시 개선입니다. 새 기기 명세는tools/hud-check-plan.json이며 기존104개 기기 회귀와 새10개를 구분합니다. 하단 진행창에만 겹치는 긴 제스처에서는 위쪽 정지를 계속 표시하며, 여러 경로 중 위쪽 제어창에도 겹치는 경우에는 기존 충돌 보호를 유지합니다. 실제 게임 성능이나24시간 무오류를 보장하지 않습니다.

## 유지한 17차 화면 인식 복구와 짧은 자동 스크롤

대상 창 조회와 명시한 화면 정보 방식의 일시 응답 지연은 터치 없이 복구를 기다립니다. 이전 조회 뒤에 새 작업을 쌓지 않고, 응답이 돌아오면 새 창과 새 화면으로 다시 확인합니다. 자동 방식의 기존 OCR 전환은 유지하며 화면 정보를 선택한 동작을 임의로 OCR로 바꾸지 않습니다. 복구 이전의 글자 부재 관측으로 중복 차단을 풀거나 오래된 좌표를 누르지 않습니다.

실제 완료된 OCR 작업의 일시 사용 불가·시간 만료·취소는 새 화면을 캡처해 다시 인식합니다. 재시도 대기는 0.25초에서 최대2초까지 늘어나며 정지와 일시정지는 계속 사용할 수 있습니다. 권한 없음·보안 캡처 거부·잘못된 입력·미지원·확인되지 않은 내부 오류는 임의로 일시 오류로 바꾸지 않습니다. 접근성 피드백만 중단된 경우와 실제 서비스 연결 해제도 구분합니다. 이미 전달한 제스처의 취소를 성공 처리하거나 자동으로 다시 누르지 않습니다.

글자가 없을 때 목록을 아래로 내리는 자동 스크롤은 화면 높이75%에서52.5%까지 위로 쓸어올립니다. 이전75%→30%보다 손가락 이동 거리가 절반입니다. 목록 새로고침의 ‘아래로 스크롤’과 개별 글자 동작의 ‘위로 스크롤 후 다시 찾기’에 적용됩니다. 아래로 당겨 새로고침과 직접 등록·녹화한 스와이프는 그대로입니다. 기존 프로필에도 자동 적용되며 콘텐츠의 실제 이동량은 대상 앱의 스크롤과 관성 처리에 따라 달라집니다.

정상적으로 읽은 화면에 글자가 없는 경우의 유한 탐지 시간과 실패 정책은 유지합니다. 화면 자체를 읽지 못하는 일시 오류는 글자 없음과 구분해 복구를 기다리므로 뒤로가기·스크롤 재시도 조건이 되지 않습니다. 복구 중에도 사용자가 정한 매크로/탐지의 전체 최대 실행 시간과 정지는 적용됩니다. 기존 제한 값을 자동으로0으로 바꾸지 않습니다.

## 변경 범위

- 목록 탐지와 개별 글자 동작의 인식 방식을 기본 설정에서 고르고 적용 범위를 확인합니다. 글자 탭의 선택은 그 탭의 단독 실행 및 글자 탭에서 추가하는 동작에만 적용됩니다.
- 실제 오류 단계와 요청/실제 인식 방식을 구분합니다. 화면 정보는 OCR을 호출하지 않으며, 이미지 글자를 제공하지 않는 앱에서 접근성 텍스트를 만들어 내지는 않습니다.
- 캡처 간격은 API30에서 1.1초, API31 이상에서 0.5초를 기준으로 합니다. 간격 거절 시 최대12초까지 후퇴하고 실제 성공 뒤 점진적으로 기준에 복귀합니다. 이는 기기별 성능 보장이나 숨은 OS API 호출이 아닙니다.
- 목록 확인의 추가2초 대기를 줄이고, 세부 설정의 인식 즉시 들어가기가 켜진 경우에만 터치 전 재확인을 생략합니다. 기본은 재확인을 유지합니다.
- 기본 설정과 동작 사이 대기·세부 설정을 나누어 접습니다. 기존 값·1~6순위·동일 글자 순번·중복 방지·계속 기다리기·중단 기능은 유지합니다.
- OCR은 전체 이미지와 기존 중심점 영역 필터를 유지합니다. 경계 글자 손실 위험이 있어 이번 차수에는 영역 자르기를 도입하지 않았습니다.

## 16차의 적응 실행과 실제 입체 모델

매크로 설정의 **다음 글자에 맞춰 진행**은 기본 꺼짐입니다. 켜면 같은 인식 방식과 영역의 연속 글자 동작에서 다음 글자의 사전 부재를 확인한 경우, 완료 후 대기를 다음 조건 대기로 바꿔 새 글자가 보이면 진행합니다. 이미 보이는 조건·수동 대기·반복 간격·무작위 대기는 유지합니다. 바로 다음 글자 터치가 같은 위치를 가리키면 사라짐과 재등장을 확인합니다. 개별 동작의 명시적 반복이나 전체 반복 경계를 모두 차단하는 기능은 아닙니다. 목록 탐지의 기존 사라짐 확인 설정은 별도로 유지합니다. 기존 프로필의 숫자를 일괄 축소하거나 터치 전 재확인을 끄지 않습니다.

실행 측정은 단계·OCR·캡처·설정 대기의 실제 시간을 구분합니다. 단계 시간에는 하위 작업이 포함되므로 네 값을 더한 숫자를 전체 시간으로 사용하지 않습니다. 전체 반복의 외부 측정과 내부 집계를 구분합니다.

실행 준비보다 먼저 일시정지하거나 정지해도 이전 대기열 작업이 측정값을 다시 초기화하지 않도록 실행 세대를 확인합니다. 개별 글자 터치는 제어창 준비 뒤에 대상을 확인하고, 실제 전달 직전에 관측된 창 변경과 일시정지 세대를 다시 대조합니다. 이 추가 전달 검사는 개별 `TEXT_TAP` 경로에 적용합니다. 목록 진입 터치는 기존의 대상 확인과 중복 예약 순서를 유지합니다.

홈의 PXE 모델은 실제 OBJ 224정점·168면을 읽어 원근 투영·깊이 정렬·조명으로 그립니다. 상태가 바뀔 때 갱신하며 상시 애니메이션·예약 렌더 루프는 없습니다. 나눔고딕 Bold와 기존 라이트/다크·제어 흐름을 유지합니다.

15회 120초는 통제 시험에서 측정할 목표입니다. 실제 게임·사용자 블루스택의 성공률99% 또는 무오류를 코드만으로 보장하지 않습니다. 납품 검사 결과에 실제 실행 범위를 기록합니다.

## 개발 환경

Java17, Gradle8.13, Android Gradle Plugin8.9.1, compile/target SDK35, min SDK30, ML Kit 한국어16.0.1입니다. 나눔고딕 Bold 파일과 기존 OFL 고지를 포함합니다. 프로젝트 전체의 새 라이선스는 부여하지 않습니다.

일반 개발 환경에서는 Android SDK를 local.properties 또는 ANDROID_HOME으로 지정한 후 Gradle wrapper를 사용할 수 있습니다.

한국어를 포함한 UTF-8 BOM없는 `빌드.ps1`은 PowerShell7에서 `pwsh -NoProfile -File .\빌드.ps1`로 실행합니다. Windows PowerShell5의 `powershell -File`로 읽으면 인코딩 때문에 파서 오류가 날 수 있습니다. 납품 빌드는 Gradle daemon의 중간 DEX 잠금이 남지 않도록 `--no-daemon`을 사용합니다.

```powershell
.\gradlew.bat :app:assembleRelease :app:testDebugUnitTest :app:lintDebug
.\gradlew.bat :app:assembleRelease :app:assembleReleaseAndroidTest -PNEX_PC
```

개인 키와 key.properties는 공개하지 않습니다. NEX_SIGNING_DIR가 유효한 개인 서명 폴더를 가리키지 않으면 개발 구성은 debug 서명을 선택하므로 기존 설치본 업데이트용으로 사용하지 않습니다. 납품 빌드.ps1은 D:/2026/PXE Project/work/build21/source 실제 일반 폴더와 기존 개인 키 존재를 확인하며 tools/sync_build.py로 선택 소스의 원문·해시를 대조합니다. PC는 ARM64/x86_64, 휴대전화는 ARM64를 포함합니다.

## 검사 범위

필수 검사 명세는 tools/required-check-plan.json, 추가 인식/UI 검사는 tools/recognition-check-plan.json입니다. 유지한17차 복구와 자동 스크롤 집중 검사는 tools/recovery-check-plan.json의15개이며, 기존89개 회귀와 별도로 확인합니다. 조건 대기·제어·입체 화면 검사는 tools/adaptive-check-plan.json, 진행창은 tools/hud-check-plan.json, 창 복구는 tools/target-window-check-plan.json,21차 기능은 tools/entry-check-plan.json에 구분합니다. 기기 검사 도구는 소유 PXE19 AVD, 별도 ADB5043, emulator5598, 설치 버전21을 확인한 후 실행합니다. 사용자 블루스택을 자동 선택하지 않습니다. 서명/19차160항목 보존 검사는 별도로 보관한 APK와 불변 로컬 보존 기준이 필요합니다.

실제 사용자 블루스택의 처리 속도, 5개 동시 실행, 24시간 무중단은 이 시험 구성의 검증 범위가 아닙니다. OS가 캡처를 제한하는 화면은 우회하지 않고 해당 단계에서 원인을 표시합니다.
