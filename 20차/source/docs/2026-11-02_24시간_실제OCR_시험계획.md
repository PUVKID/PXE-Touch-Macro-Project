# 20차 · 19차 제품의 실제 OCR 24시간 연속 시험

사용자 요청은 완료한 19차를 실제 24시간 검증하는 것입니다. 20차는 시험 도구와 결과를 보존하는 차수이며 새 제품 버전이 아닙니다. 19차 소스·납품 APK는 변경하지 않습니다.

## 고정 대상과 경계

- 제품: kr.yunseok.touchmacro, 1.9.0 / 19. PC APK SHA256 `46017d7f2bb2736871776d69eb93ce5d28dc8838294999e2e129bee4bf358276`.
- 전용 PXE19 Android31, emulator-5598 / ADB5043, CPU4 / RAM2048 / 1080×2280 / 420dpi / SwiftShader만 사용합니다. 사용자 플레이어·게임·실제 휴대폰·기본 ADB5037을 조작하지 않습니다.
- 시험 소스·19차 제품·별도 시험 빌드·운영 기록을 서로 분리하고 실제 일반 폴더를 사용합니다. 연결을 생성하거나 복원하지 않습니다.
- 새 instrumentation만 기존 승인 Gradle 내부 서명 경로를 사용합니다. 서명 원문 수동 읽기·출력·복사·새 키 생성은 하지 않습니다. 빌드 부산물 제품 APK를 시험 대상이나 납품본으로 대체하지 않습니다.

## 실제 부하

하나의 instrumentation이 실제 제품 MainActivity에 Canvas 목록·상세 fixture를 표시합니다. 소유 fixture 화면만 바꾸며 인식·창 조회·캡처 성공을 주입하지 않습니다. 실행은 실제 Store/WatchStore 및 MacroService.startWatch로 정확히 한 번 시작합니다.

목록 OCR → 찾은 글자 터치 → 다음 글자와 완료 글자를 실제 OCR로 인식하고 터치하는 두 동작을 15회 → 제품의 실제 뒤로가기 → 같은 목록의 중복 차단 확인 → 실제 부재를 인식해 잠금 해제 → 재등장의 순환을 유지합니다. Canvas 글자는 접근성 텍스트로 제공하지 않고 모든 인식 방식을 OCR로 고정합니다. 다음 글자가 아직 없는 구간도 표시해 계속 기다리기 경로를 사용합니다.

전체 반복은 15회, 무한 글자 대기와 즉시 진행을 사용합니다. 목록 새로고침 1초, 사라짐 확인 1초, 진입·복귀·새로고침 화면 대기 각 0.3초, 완료 후 대기 5초, 명시 최대 시간은 0입니다. 같은 항목은 실제 중복 대기 상태와 OCR 증가를 관측할 때까지 유지합니다. 이후 부재 표시는 실제 WatchStore 잠금 해제까지 유지하며 30초 이상 해제되지 않으면 실패합니다.

## 사전 시험과 본 시험

- 사전 시험: 최소 300초와 최소 3회의 정확한 15회 사이클을 모두 충족한 뒤 뒤로가기 완료 경계에서 종료합니다. 준비·완료를 포함한 명령 상한은 480초입니다. 이 기준은 제품의 일반 성능·정확도 보장이 아닙니다.
- 본 시험: 제품 실행의 SystemClock.elapsedRealtime 기준 86,400초 이상을 한 프로세스·한 서비스·한 macro generation으로 유지한 뒤 완료 경계에서 종료합니다. 명령 전체 상한은 87,000초입니다. 중간 정지·앱/서비스/기기/host 재시작의 시간을 이어 붙이지 않습니다.
- 실제 정지 입력은 종료 경계에서만 수행합니다. 제어된 오류·지연 주입 시험은 이 실제 OCR 연속 시험에 섞지 않습니다.

## 관측과 판정

30초마다 장치 atomic 상태와 host heartbeat를 기록합니다. boot_id, 제품·서비스 PID, macro generation, monotonic 경과, 실제 OCR 횟수·시간·캡처 시간, 완료 사이클·15회 단언, 중복 입력·단계 오류, 상태·오류 기록의 변화, 메모리·CPU 추세를 수집합니다. 원문 로그는 크기 제한·회전하며 운영 기록은 공개 소스 밖에 둡니다.

실행 중단, 다른 세대·PID·boot, 잘못된 순서·중복·15회 불일치, 진행 300초 정체는 실패합니다. 진행 180초 정체는 경고로 먼저 기록합니다. host/장치 heartbeat 공백 90초 초과, 절전·수면·ADB 불통·측정 근거 단절은 연속 PASS에서 제외하여 실패 또는 판정 불가로 구분합니다. 24시간 전에는 PASS를 기록하지 않습니다. 초기 실제 OCR 증가와 여러 15회 사이클을 확인하기 전에는 시작 완료라고 보고하지 않습니다.

장치 상태의 실제 수신 바이트와 조회 결과를 독립 PID/boot 조회보다 먼저 보존합니다. 실행 중에는 살아 있는 동일 PID를 요구합니다. Android의 정상 instrumentation 종료는 대상 프로세스를 종료하므로, 최종 PASS는 이전부터 동일한 PID/boot/시작 시각/매크로 세대와 실제 정지 관측을 대조하고 계측 종료코드 0 및 성공 표식을 모두 요구합니다. RUNNING 수신 직후 PID가 사라졌다면 이미 정상 종료한 계측에 한해서 최종 장치 상태를 한 번 재수집하며, 완전한 최종 PASS가 없으면 실패합니다. 오래된 RUNNING이나 초기부터 존재한 PASS로 성공하지 않습니다. 이 종료 경계 구분은 실행 중 PID 변경을 허용하지 않습니다.

host는 자기 프로세스에서만 SetThreadExecutionState의 SYSTEM_REQUIRED를 요청하고 finally에서 해제합니다. 전역 전원 설정·화면 켜기 설정을 변경하지 않습니다. fixture는 FLAG_KEEP_SCREEN_ON을 사용합니다. 정지·시간 초과 cleanup은 소유 PID 자식과 소유 serial의 대상 앱으로 제한합니다.

오류 일지는 매 관측과 최종 종료 때 읽으며 조회 결과·원문·SHA256을 제한 회전 JSONL에 보존합니다. 최초 원문과 최신 원문은 별도 파일로 보존합니다. 상태의 `error_journal`은 최초/현재 해시, 관측 수, 변화 수, 최초/현재/마지막 변화 시각, 최초 기준이 실행 후라는 표식, 관측 간 추가 줄 수를 기록합니다. 초기 일지가 비어 있지 않거나 이후 바뀌면 `journal_warning`을 표시합니다. 복구 경고와 연속 실행 실패는 별개이며 기존 기록을 지우지 않습니다. 조회 실패는 실패로 처리합니다. 시작부터 최초 관측까지의 오류 시점과 관측 간 회전으로 사라진 줄은 이 수집만으로 확정하지 않습니다.

로컬 WMI 숨김 기동 뒤 동일 사용자 SID와 실제 Windows 작업 그룹 외부 여부를 검사합니다. `runpy` 실행에는 대상 스크립트 폴더와 UTF-8 출력 파일 객체를 명시합니다. 별도 프로세스 생성 성공과 장기 연속 실행 성공은 구분합니다.

## 정적·단위 검사 계약

모든 cwd는 ROOT의 `.`이며 실제 Python 절대경로와 `-B -X utf8`을 사용합니다.

1. `tools/test_soak_runner.py`: 30초. 시간·연속성·완료 판정·기록 크기와 관련 실패 경로를 검증합니다.
2. `tools/check_contract.py`: 30초. 제품 SHA, 19차 보존 manifest, 시험 설정·실제 빌드 사본의 경계를 검증합니다.
3. `tools/verify_text.py`: 15초. 이번 시험 소스·문서의 엄격 UTF-8과 대체 문자 부재를 검증합니다.

합계 상한은 75초입니다. 검사 실행과 장기 시험의 실제 완료를 구분합니다. 장기 시험을 시작한 것과 완료·독립 검증을 구분하며 사용자 실제 게임·24시간 모든 환경의 무오류를 주장하지 않습니다.
