# 실제 실행 환경 점검

2026-10-28 한국 시각에 실행 중인 프로그램을 종료하거나 설정을 바꾸지 않고 조회했습니다. CPU 연속 측정은 76.9초·12개 표본이며, GPU/메모리/Docker의 추가 조회는 각각 원본 파일의 시각과 구분합니다. 모든 가능한 동시 실행 개수를 실제 완주 시험한 결과는 아닙니다.

## 확인한 의미

네 개의 HD-Player 프로세스는 호스트 CPU 평균 약5.75~5.98%를 사용했습니다. 논리32개 기준 약1.84~1.91개 상당이며 설정된2코어에 가까웠습니다. 전체 CPU가 계속100%라기보다 인스턴스별2코어 제한이 속도를 묶는 것으로 의심됩니다. 인과관계 확정이나4/6코어의 실제 완주 시험은 아닙니다. 나머지2개는CPU가낮았지만, 이것만으로 매크로 정지와 정상 대기를 구분할 수 없습니다.

도커 컨테이너의24코어·48GiB는 허용 상한이지 현재 모두 사용하는 양이 아닙니다. CPU6개×블루스택5개는30개의 가상CPU 설정이고, 이것도 물리코어30개를 독점 예약한다는 뜻은 아닙니다. 다만 도커의 부하가 함께 올라가면32논리CPU에서 대기와 처리 지연이 생길 수 있습니다.

현재 안정성에서 더 주의할 값은 시스템 커밋입니다. 물리 RAM 여유와 별개로, 추가 메모리를 보장할 여지가 적습니다. Windows 페이지 파일은 이미 자동 관리 상태이며 C드라이브 공간도 남아 있습니다. 그래도 확장·페이징이 빠른 OCR을 보장하지 않으므로 각 인스턴스 메모리부터 크게 늘리는 것은 권하지 않습니다. 이 값만으로 특정 프로그램의 누수를 확정하지 않습니다.

GPU 추가 순간 조회에서 vmwp 가상머신 프로세스가 큰 전용 GPU 메모리와 엔진 부하를 보였습니다. Docker는실행중인WSL2 docker-desktop에서GPU를요청하고있지만,호스트GPU의모든할당을특정컨테이너에직접일치시켰다고주장하지않습니다. CPU온도는측정하지않아GPU온도로대체하지않습니다.

## 현재 조건에 대한 판단

- 도커·메이플·블루스택을 함께 실행하는 것 자체는 가능합니다. CPU/GPU100%와 정해진 시간 안의 매크로 완료는 다른 기준입니다.
- 현재상태에서 블루스택5개를 각각6코어로 바꾸고 RAM도 동시에 크게 늘리는 구성은 권하지 않습니다.
- 조정 시험의 시작값은 각CPU4코어·RAM2GB·현재20FPS 유지가 더 적절합니다. 변경 후 빨라진다고 확인한 값은 아니며, 실제 설정 변경은 이번 점검에서 하지 않았습니다.
- 실제 최대 개수를 확정하려면 다른 프로그램 부하를 같게 두고 개수별15회완주시간·실패율을 비교해야 합니다. 이번읽기전용점검만으로3개또는5개가검증된최대라고표현하지않습니다.
